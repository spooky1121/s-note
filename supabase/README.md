# 상사정보 저장 기능 적용

v2.63 신규 공유 알림과 공유 표시에는 [신규 공유 SQL](migrations/20261105105113_shared_vehicle_registered_notifications.sql)을 추가 적용한다. 운영 적용·권한 확인을 완료했다.

공유 차량 변경 알림은 [알림 안내](../docs/vehicle-notifications.md)의 두 추가 마이그레이션을 사용한다. 운영 DB 적용과 권한 검증을 완료했다.

딜러 간 차량 공유는 [공유 안내](../docs/vehicle-sharing.md)와 [공유 SQL](migrations/20261104153021_vehicle_scoped_dealer_sharing.sql)을 사용한다. 이 작업에서는 운영 DB에 적용 후 권한 검증까지 완료했다.

휴대폰의 단계별 입력·주민번호·서명·자동 반영에는 [0004 SQL](migrations/202611010004_customer_intake_wizard.sql)을 적용합니다. [사용·적용 안내](../docs/customer-intake-wizard.md)를 확인하세요.

판매 진행의 수동 주민번호 저장·전체 표시는 [사용 안내](../docs/manual-customer-identity.md)를 확인하세요. v2.14 수동 저장 기능에는 추가 SQL이 필요하지 않습니다.

이 저장소의 Cloudflare Pages 배포는 Supabase의 DB 구조를 자동 변경하지 않습니다.

직접 입력 차종을 상사 공용 목록으로 쌓으려면 [차종 DB 적용 안내](../docs/vehicle-taxonomy-setup.md)에 따라 `migrations/202611010005_vehicle_taxonomy.sql` 전체를 한 번 실행합니다. 새 키 설정은 필요하지 않습니다.

1. 연결된 Supabase 프로젝트의 [**SQL Editor**](https://supabase.com/dashboard/project/rmlycycleuscfqywbihj/sql/new)를 엽니다.
2. `migrations/202610240001_company_profile.sql` 전체를 붙여 넣고 실행합니다.
3. S-NOTE의 관리자 계정으로 **직원·설정 → 상사 정보**를 열고 **연결 다시 확인**을 누릅니다. 이미 입력한 내용은 유지됩니다. 이전 버전이라 이 버튼이 없다면 페이지를 새로고침합니다.
4. 상사명, 사업자등록번호, 대표자, 사업장 주소·상세주소, 관리자 성명·휴대전화를 입력하고 **상사정보 저장**을 누릅니다. 주소 검색은 기존 판매진행 화면과 동일한 카카오 주소검색을 사용합니다.

SQL은 여러 번 실행할 수 있습니다. 상사정보와 현재 관리자 연락처는 하나의 트랜잭션으로 저장되며, 활성 상태인 소속 관리자만 실행할 수 있습니다. 사용자 역할·이메일·다른 직원의 정보는 변경하지 않습니다. 이메일은 인증 계정의 값을 읽기 전용으로 표시합니다. 도장·로고 파일은 기존 이미지 등록 버튼으로 별도 저장합니다.

DB 적용 전에는 카드에 서버 설정 안내가 표시되고 저장 버튼이 비활성화됩니다. 저장이 실패하면 입력 내용은 유지되고 성공 메시지는 표시되지 않습니다.

`42703` 오류는 저장에 필요한 컬럼이 아직 없는 경우이고, `PGRST202` 오류는 저장 함수가 아직 없는 경우입니다. 위 SQL 전체가 실행되어야 합니다. **연결 다시 확인**은 DB를 다시 조회하며, 입력 내용을 자동 저장하지 않습니다. 연결 확인 후 **상사정보 저장**을 눌러야 저장됩니다.

이 변경을 위해 DB 비밀번호나 서비스 키를 프런트엔드 파일에 넣지 마세요.

고객 휴대폰 입력·문자 인증 기능의 별도 DB 적용과 자료 정리 예약은
[고객 입력 운영 절차](../docs/customer-intake-setup.md)에 순서대로 정리되어 있습니다.

## 상사 도장·로고 이미지

`migrations/202610240002_company_branding.sql`은 기존 `zc_media` 테이블에서 `companyStamp`·`companyLogo` 종류를 허용합니다. 이미지 파일은 기존 비공개 `zc-vehicle-private` 버킷에, 파일 경로·종류·크기 등 등록 정보는 `zc_media`에 저장합니다.

활성 관리자는 소속 상사의 이미지를 등록·교체·삭제할 수 있으며, 직원은 기존 상사 조회 권한으로 이미지를 확인합니다. PNG·JPG·WEBP, 3MB 이하 파일만 등록합니다. 기존 차량 사진·서류 권한과 버킷의 비공개 설정은 유지됩니다.

## 사업자 전화번호와 계약서 자동 입력

기존 상사정보 SQL을 적용한 프로젝트에서는 `migrations/202610260001_company_phone.sql` 전체를 추가로 실행합니다. 이 SQL은 `business_phone` 항목과 기존 저장 함수를 함께 갱신합니다. Cloudflare Pages 배포만으로는 DB에 적용되지 않습니다.

적용 후 관리자 계정의 **직원·설정 → 상사 정보 → 연결 다시 확인**을 누르면 상세주소 옆의 **사업자 전화번호**를 입력할 수 있습니다. 지역번호·070·0505·대표번호·휴대전화 등 숫자 8~12자리를 지원하며 하이픈은 저장 시 제거합니다. 설정 입력칸과 계약서에는 번호에 맞춰 `02-123-4567`, `02-1234-5678`, `031-123-4567`, `031-1234-5678` 형식으로 하이픈을 자동 표시합니다. 기존 대표번호·0505 번호도 유지합니다. DB에는 숫자만 저장하므로 이 표시 변경에는 추가 SQL 적용이 필요하지 않습니다. 입력은 선택 사항이고 빈칸으로 저장하면 등록된 사업자 전화번호가 지워집니다. 관리자 개인 휴대전화와 별도로 저장합니다.

새 DB 항목을 적용하기 전에도 기존 상사정보는 계속 저장할 수 있습니다. 사업자 전화번호 칸만 비활성화되고 안내가 표시됩니다. 기존 클라이언트가 전화번호 없이 저장해도 이미 등록된 번호는 보존합니다.

신규 판매 계약서에는 저장된 상사명·사업자등록번호·사업장 주소와 상세주소·사업자 전화번호가 자동 입력됩니다. 직원도 로그인할 때 소속 상사정보를 불러옵니다. 저장된 계약서를 다시 열 때는 상사측 빈칸을 보완하고 이미 작성한 계약 내용은 유지합니다. 매수 계약에서는 매수인 쪽에 상사정보가 입력됩니다.

차량인수증의 **고객 연락처**는 판매 진행에서 입력한 고객 전화번호를 사용합니다. 고객관리에서 저장된 인수증을 다시 열 때도 같은 값이 입력됩니다. 이 연락처 표시는 기존 고객 데이터의 `phone`을 사용하므로 별도 DB 변경이 필요하지 않습니다.

## v2.41 원 단위 금액

앱의 차량가·비용·수리비·재고대출·금융 한도 입력/계산/표시는 원 단위 정수입니다. 기존 DB와 구버전 클라이언트의 저장 형식은 `assets/money.js`의 읽기/쓰기 경계에서만 변환하므로, 기존 차량 전체를 일괄 배수 갱신하지 않습니다. 선재고·월정산·계약서·소득 정산의 기존 원 단위 값은 추가 환산하지 않습니다.

고객 인증 링크에서도 1원 단위 차량가를 보존하려면 [금액 정밀도 SQL](migrations/20261103140147_customer_intake_won_precision.sql)을 웹 앱 배포 전에 적용합니다. 기존 고객 입력 함수가 설치된 DB에만 적용하며, 가격 검증의 소수 자릿수만 2→4로 변경합니다. 금액 데이터·권한·잠금·소유자/상사 검사는 변경하지 않습니다. 연결된 운영 프로젝트에는 2026-11-03 적용·재조회 검증을 마쳤습니다.

## v2.44 차량 서류 MMS 공유

[서류 MMS 접수 SQL](migrations/20261103155058_document_mms_delivery.sql)을 먼저 적용합니다. 연결된 운영 DB에는 적용·권한 검증을 마쳤습니다. `snote_document_mms`와 접수 함수는 서버 service_role만 사용할 수 있고 브라우저 역할의 조회/접수는 차단합니다. 원본 사진/수신 전체 번호는 접수 표에 보관하지 않습니다.

Cloudflare Pages Functions의 기존 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`를 재사용합니다. 고정 `SOLAPI_SENDER`는 이 기능에 사용하지 않습니다. 발신번호는 차량 담당자의 실제 `zc_members.phone`을 서버에서 다시 읽으며, 솔라피 발신번호 목록에 같은 번호가 ACTIVE 상태로 승인되어 있어야 합니다. 미승인 번호/번호 없음/API 조회 권한 오류는 전송 전에 안내하고 다른 발신번호로 대체하지 않습니다. 솔라피 키에 발신번호 조회·파일 업로드·MMS 전송 권한이 필요합니다.

딜러/관리자가 차량 상세의 공유 아이콘에서 받는 휴대전화와 서류를 선택해 전송합니다. 등록증은1장, 성능기록부는최대2장이고 한 장당MMS1건입니다. 브라우저가190KB 이하 JPEG 사본을 준비하며 원본을 교체하거나 공개 Storage URL을 만들지 않습니다. 미리보기에서 글자를 확인할 수 있습니다. 발송 접수와 실제 수신 완료는 구분합니다. 응답 유실/알 수 없는 접수는 자동 재전송하지 않고 최근 내역에서 확인합니다. 같은 최근 사진/수신자 요청은5분 동안 재사용해 중복 접수를 막으며, 실패한 접수만 사용자가 다시 선택할 수 있습니다.

공식 SDK `solapi@6.0.1`의 `storage/v1/files` (MMS200KB 제한), 기존 `messages/v4/send`, 공식 solapi/solactl의 `senderid/v1/numbers` ACTIVE 검사 형식을 확인했습니다. 실제 고객 사진이나 문자를 이용해 발송 테스트하지 않았습니다.
