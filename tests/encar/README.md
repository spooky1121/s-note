# Advertisement lookup test gates

The active Encar-button flow uses the read-only GLOAR `/api/encar-id` contract. Since UI v2.149 the verified ID opens `https://fem.encar.com/cars/detail/{id}` in a new tab rather than an ID popup; server lookup remains v2.148. Run `npm test --prefix tests/encar` for the API, header automation/ID proof, client cancellation/new-tab guards, browser transport, historical parsers and unrelated regressions. Run `npm run test:browser --prefix tests/encar` for actual list/card/detail new-tab navigation, popup-blocked fallback and no price/vehicle writes. Run `node tests/encar-id-loading.browser.cjs` for pending/success/error/cancel/account-change animation and reduced-motion checks at desktop/mobile sizes. External advertisement pages are intercepted with synthetic HTML in the browser tests.

The old `server`, `discovery`, `server-price`, `frontend`, `integration`, `saved-bridge`, `list-price-entry`, and automatic-price endpoint specs describe the removed workflow. They remain as historical reference; they are deliberately absent from the current gate. The original baseline is commit `07494c5cec445d741267ca0ca3b8a21d4d5eb533`. Their former Korean-page, automatic-price and database-write behavior must not be restored to make those old expectations pass.

The production API now uses `encar-id-gloar.mjs`: open the actual GLOAR home, fill exactly `#headerSearchInput`, verify focus/value, send native Enter, follow observed results and verify the primary full plate and explicit original Encar ID. The browser transport runs in a GLOAR-only profile. Old ordered/Tavily parsers remain backup coverage and are not imported by the default API. Unit fixtures do not establish the actual GLOAR search contract or production credentials. Live provider access is still blocked by this execution environment's CONNECT 403.

Native runtime checks require a Wrangler Pages Functions build and a toolchain supplying `miniflare` via `NODE_PATH`. Run `node tests/encar-id-browser.workerd.cjs` for the Workers WebSocket client and `node tests/encar-id.workerd.cjs <pages-build-output>` for the actual compiled default API with synthetic Auth/Browser Run/CDP services. Both prohibit real outbound requests and check native Workers fetch options. The production harness evaluates the compiled serialized page function against synthetic GLOAR DOM, exercises the real header/Enter flow, UUID rejection and failure boundaries, and prohibits Korean Encar/price/database writes. Browser emulation and synthetic results do not establish live search coverage.
