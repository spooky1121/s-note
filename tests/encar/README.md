# Advertisement lookup test gates

The active Encar-button flow is now the read-only `/api/encar-id` contract. Run `npm test --prefix tests/encar` for the API, ordered resolver, retired endpoints, independent parsers and unrelated application regressions. Run `npm run test:browser --prefix tests/encar` for the actual list/card/detail ID-only UI. Run `node tests/encar-id-loading.browser.cjs` for pending/success/error/cancel/account-change animation and reduced-motion checks at desktop/mobile sizes.

The old `server`, `discovery`, `server-price`, `frontend`, `integration`, `saved-bridge`, `list-price-entry`, and automatic-price endpoint specs describe the removed workflow. They remain as historical reference; they are deliberately absent from the current gate. The original baseline is commit `07494c5cec445d741267ca0ca3b8a21d4d5eb533`. Their former Korean-page, automatic-price and database-write behavior must not be restored to make those old expectations pass.

The production API now uses the ordered web-search flow in `encar-id-lookup.mjs`, `encar-id-search.mjs`, and `encar-id-search-parser.mjs`. Search/Extract HTTP and primary evidence use synthetic fixtures; the `66너7230` case reconstructs minimal visible source fields rather than capturing a live Tavily response. Missing/invalid/quota-limited search credentials fail distinctly. Actual operational search success remains unverified in this execution environment. The v2.146 Browser Run modules/tests remain backup coverage and are not imported by the current default API.

Native runtime checks require a Wrangler Pages Functions build and a toolchain supplying `miniflare` via `NODE_PATH`. Run `node tests/encar-id-browser.workerd.cjs` for the Workers WebSocket client and `node tests/encar-id.workerd.cjs <pages-build-output>` for the actual compiled default API, synthetic Auth/Tavily services, ordered early exit, the source-shaped 66너7230 case, bounded extraction, upstream failures, pure configuration GET and zero browser/provider/price/write calls. Both prohibit real outbound requests. The first is previous-browser backup verification; the second covers the current default API and native Workers fetch options. Browser emulation and synthetic results do not establish live search coverage.
