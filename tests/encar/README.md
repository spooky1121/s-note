# Advertisement lookup test gates

The v2.159 flow preserves GLOAR `/api/encar-id` discovery and adds ACK-confirmed per-vehicle links. A subsequent explicit Encar click directly opens the saved share URL without a GLOAR request. The list/card icon requires confirmed metadata. Vehicle detail uses authenticated read-only `/api/encar-ad-price` for a known ID/full plate, caches verified KRW amounts and asks before changing the planned sale price through the existing owner CAS transport. No SQL schema change is required. See `docs/encar-id-v2148.md` for the current contract and earlier ID-only history.

Run `npm test --prefix tests/encar` for the price/API, GLOAR automation, browser transport, historical parsers and independent application regressions. Run `npm run test:browser --prefix tests/encar` for actual list/card/detail flows against synthetic services: held or missing CAS acknowledgement, browser reload, direct tab activation, price comparison/cancellation/confirmation, raw legacy and KRW preservation, unrelated drafts, stale contexts and fixed diagnostics. No real vehicle/customer records are changed. `node tests/encar-id-loading.browser.cjs` separately checks search animations and reduced-motion behavior with its ID-only fixture.

The old `server`, `discovery`, `server-price`, `frontend`, `integration`, `saved-bridge`, `list-price-entry`, and automatic-price endpoint specs describe the removed workflow. They remain as historical reference; they are deliberately absent from the current gate. The original baseline is commit `07494c5cec445d741267ca0ca3b8a21d4d5eb533`. Do not restore their removed resolver or retired endpoints to satisfy obsolete assertions; the authorized v2.159 storage/price contract is covered by the new tests.

The production API now uses `encar-id-gloar.mjs`: open the actual GLOAR home, fill exactly `#headerSearchInput`, verify focus/value, send native Enter, follow observed results and verify the primary full plate and explicit original Encar ID. The browser transport runs in a GLOAR-only profile. Old ordered/Tavily parsers remain backup coverage and are not imported by the default API. Unit fixtures do not establish the actual GLOAR search contract or production credentials. Live provider access is still blocked by this execution environment's CONNECT 403.

Native runtime checks require a Wrangler Pages Functions build and a toolchain supplying `miniflare` via `NODE_PATH`. Run `node tests/encar-id-browser.workerd.cjs` for the Workers WebSocket client and `node tests/encar-id.workerd.cjs <pages-build-output>` for the actual compiled default API with synthetic Auth/Browser Run/CDP services. Both prohibit real outbound requests and check native Workers fetch options. Run `node tests/encar-ad-price.workerd.cjs <pages-build-output>/index.js` for the compiled price route with native Workers Auth/fetch/HTMLRewriter and synthetic Encar HTML; it verifies exact plate/ID, won conversion, inactive/dummy rejection and authentication/429/configuration failures without real outbound traffic. The production harness evaluates the compiled serialized page function against synthetic GLOAR DOM, exercises the real header/Enter flow, UUID rejection and failure boundaries, and prohibits Korean Encar/price/database writes within that ID-only API harness. The separate price handler and storage browser fixtures cover the newly authorized price path. Browser emulation and synthetic results do not establish live search coverage.
