# 엔카 실행 복구 — v2.116

v2.115에서 사용자가 보내준 운영 진단은 `SESSION_UNAVAILABLE`, HTTP 503, `RPC_NETWORK_ERROR`였다. 공식 광고 검색보다 앞선 서버 로그인 확인 단계에서 실패해 검색 요청이 시작되지 않았다.

로그인 확인 요청이 `redirect: 'error'`를 사용했지만 Cloudflare Workers는 이 모드를 지원하지 않는다. 요청을 구성하는 순간 오류가 나며 외부 요청은 전송되지 않는다. 이전에 동작하던 서버 조회와 같은 `manual` 모드를 사용하고, 성공 응답이 아닌 리디렉션은 기존 HTTP 검사로 거부한다. 다른 주소로 로그인 토큰을 전달하지 않는다.

이전 호환 날짜에서는 `Request.cache` 옵션도 같은 단계에서 거부되는 것을 재현했다. 로그인 확인은 캐시하지 않는 POST와 `Cache-Control: no-store` 헤더를 사용하고 해당 옵션을 제거해 호환 날짜 변경 없이 요청할 수 있게 한다. API 응답의 비공개·캐시 금지 헤더도 유지한다.

서버의 로그인 확인은 계속 실행한다. 기존 접속 해제·세션 소유권·응답 검증·5초 제한·오래된 응답 차단을 유지하며, 로그인 확인을 건너뛰어 검색을 허용하지 않는다.

차량 상세의 Encar 버튼은 기존 이미지가 로딩되지 않으면 빈 버튼처럼 보일 수 있었다. 기본 글자 표시를 추가해 이미지 지연·실패에도 버튼을 볼 수 있게 한다. 조회 모듈의 초기화와 별개로 판매 상태를 반영하며 기존 판매 완료 차량의 숨김 조건을 유지한다.

이 작업은 광고 검색·가격 확인의 기존 연결을 사용한다. 차량·가격·고객 자료나 DB 스키마는 변경하지 않는다.

Cloudflare가 지원하는 리디렉션 모드는 [공식 Request 문서](https://developers.cloudflare.com/workers/runtime-apis/request/#constructor)에서 확인할 수 있다.

자동 테스트 795개, PC·모바일 상세 브라우저 7그룹, 가격 저장 7그룹과 workerd 실행기 10개 사례가 통과했다. 실행기에서는 수정 전 두 호환 날짜 모두 외부 요청 0회로 같은 503이 발생했고, 수정 후 정상·기존 세션은 처리에 진입하며 교체된 세션·리디렉션은 차단됐다. 실행기·브라우저 시험은 합성 인증·응답을 사용하며 실제 운영 광고 확인과 구분한다. [검증 기록](encar-runtime-recovery-verification.json)에 범위를 남긴다.
