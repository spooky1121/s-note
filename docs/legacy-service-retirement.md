# 이전 웹서비스 정리

범위는 예전 웹서비스의 이름·주소·진입 경로다. 실제 제로카 상사명, 법인 로고·도장, 기존 계약서와 차량·고객·금융 자료는 유지한다.

## 공식 서비스

- 공식 접속: https://s-note.kr/
- S-NOTE Pages: https://s-note.pages.dev/
- 기존 Supabase 프로젝트는 `s-note-db`이며 그대로 사용한다.

6개 HTML 진입점은 가장 먼저 `assets/service-location.js`를 실행한다. 예전 `zerocar-office.pages.dev` 및 해당 프로젝트의 미리보기 호스트, `zerocar-office.<계정>.workers.dev`에서 실행될 때만 공식 주소로 이동한다. 경로·쿼리·고객 링크의 fragment를 유지한다. 공식 주소, S-NOTE 미리보기, localhost 및 실제 상사 도메인은 변경하지 않는다.

이는 클라이언트의 HTML 이동 처리다. Cloudflare 프로젝트 삭제, DNS 해제 또는 서버 HTTP 리디렉션을 수행한 것이 아니다. 이전 Worker가 새 코드를 배포받지 못하는 상태라면 그 Worker 주소에는 이 변경도 적용되지 않는다.

## 자료 호환

- 기본 차량 이미지의 코드 이름과 월정산의 주 통신 이름을 S-NOTE로 정리했다.
- 기존에 열린 월정산 부모 화면과 캐시된 자식 화면을 위해 이전 메시지 이름은 호환 별칭으로 유지한다. origin·source·유한 숫자 검사는 유지한다.
- v2.201부터 새 로컬 저장 키와 사진·계정·고객 IndexedDB는 `s-note-office-*`를 사용한다. 이전 이름은 두 호환 모듈에 명시적인 읽기·이전 입력으로만 남긴다. 문자열을 인코딩해 숨기지 않는다.
- 브라우저의 이전 origin 자료를 삭제하거나 다른 origin으로 자동 복사하지 않는다. 서버 자료·권한·백업 연결은 변경하지 않는다.
- 개발 이력과 분류 원본의 출처·무결성 식별자도 보존한다. 해당 기록에 있는 과거 배포 주소는 현재 접속 안내가 아니다.

### v2.201 저장 이름 이전

- `assets/snote-storage-compat.js`: 로컬 차량·커버는 새 값이 없을 때만 같은 소유자의 이전 값을 읽는다. 조회만으로 복사·병합·서버 저장하지 않는다. 새 값이 빈 배열이어도 우선하며, 명시적 삭제 마커로 이전 자료가 다시 나타나는 것을 막는다. 로그아웃은 양쪽 세션 힌트를 제거한다.
- 공유 금융 캐시는 상사 식별자가 없는 이름만으로 가져오지 않는다. 기존의 상사·사용자·권한·내용 해시·서버 버전 검증을 거친 저장 복구만 허용한다. 금융 3종은 인증된 메모리 스냅샷 또는 현재 상사의 서버 행만 사용한다.
- `assets/snote-idb-compat.js`: 현재 저장소의 기존 행을 덮어쓰지 않고 과거 Blob·계정·고객 행을 한 트랜잭션으로 복사하고 완료를 기록한다. 원본은 삭제하지 않는다. 이전 앱의 열린 연결 때문에 안전한 전환을 할 수 없으면 창을 닫거나 새로고침하라는 안내를 표시하며, 공간 부족·중단은 원본을 보존하고 재시도한다. 완료 후에는 삭제한 행을 다시 가져오지 않는다.
- 온라인 로그인 준비는 새 IndexedDB 캐시만 열며, 이전 로컬 계정·사진 전환은 로컬 기능 사용 시 수행한다. 온라인 인증과 상사 범위는 유지한다. 실제 로컬 계정의 세션 복원은 서버 인증 복원 뒤에 실행하며, 온라인 계정의 캐시 별칭을 로컬 로그인으로 사용하지 않는다.
- 새 로컬 식별번호 암호문은 버전 2와 현재 서비스 salt를 사용한다. 버전 1은 비밀번호 확인 뒤 이전 키를 필요한 순간에만 파생해 읽는다. 잠금·로그아웃·계정 전환 뒤에 끝난 비동기 작업은 키나 평문을 반환하지 않는다. 서버 암호화와 실제 고객 기록은 일괄 수정하지 않는다.
- `tests/service-brand-boundaries.test.mjs`는 현재 코드·설정의 새 이전 서비스명 사용을 차단한다. 호환 입력은 파일별 정확한 문구와 최대 횟수로 제한하고, 분류 원본 15개는 바이트 해시로 보호한다. Git 이력·과거 작업 문서까지 문자열이 0개라고 주장하는 검사는 아니다.

### v2.201 검증 범위

- 새 저장 호환·유휴 복구·상사 금융 격리·이름 경계 단위 시험 128건, 주소·가입·분류·견적 관련 회귀 단위 시험 69건 통과.
- IndexedDB 브라우저 시험 14그룹, 로컬 저장 호환 브라우저 시험 11그룹, 실제 앱·암호문·세션·계정 전환 대기 경쟁 시험 9그룹 통과. 합성 자료만 사용했고 운영 DB·고객·문자를 변경하지 않았다.
- 금융 캐시 교체 2개 화면 크기, 저장 실패 롤백 4사례, 유휴 세션 9그룹을 기존 실제 앱 시험으로 확인했다.
- 월정산은 새 주 메시지와 이전 호환 메시지, 현재 부모·자식의 저장·충돌·CSV·A4 인쇄를 별도 회귀 시험으로 검증했다.
- 오래된 전체 화면 시험의 현재 UI 기대값 불일치는 변경 전 `main` 사본으로 대조하며, 이름 변경을 통과시키려고 관련 없는 UI 조건을 약화하지 않는다. 실제 운영 계정 로그인·서류 출력과 이전 호스트 HTTP 응답을 이번 합성 시험으로 검증했다고 보고하지 않는다.

## Cloudflare에서 남은 작업

공식 CLI 확인 결과 현재 실행환경에는 Cloudflare 인증 연결이 없다. 따라서 예전 프로젝트의 설정·라우트·배포와 연결을 확인하거나 프로젝트 자체를 삭제하지 않았다.

Cloudflare **Workers & Pages**에서 이름이 정확히 `zerocar-office`인 Pages와 Worker를 확인한다. 현재 S-NOTE 프로젝트 `s-note` 및 `s-note.kr` 연결을 유지하고, 예전 프로젝트의 연결 도메인·라우트·Git 자동 빌드 연결을 확인한 뒤 사용하지 않는 프로젝트를 종료한다. 실제 제로카 상사의 별도 회사 사이트·자료는 이 작업에 포함하지 않는다.

Pages의 `_redirects`는 도메인 단위 규칙과 Pages Functions 요청을 지원하지 않으므로, 확인되지 않은 호스트 규칙을 저장소에 추가하지 않았다. 서버에서 이전 호스트만 이동시키려면 Cloudflare 계정의 Redirect Rules/Bulk Redirects 또는 이전 프로젝트 전용 구성이 필요하다.

근거: [Pages redirects](https://developers.cloudflare.com/pages/configuration/redirects/)

## v2.200 검증 기록

- 주소 처리: 단위 6개 그룹, 실제 브라우저 20개 사례 통과. 고객 링크 해시·경로·쿼리 보존, origin 고정, 현재/회사 도메인 무동작, 같은 origin 부모 이동·외부 부모 보존, 이동이 차단된 프레임의 수동 탈출과 기존 DOM 보존을 확인했다.
- 월정산: UI 11개 그룹, 실제 부모·iframe·PGlite 7개 그룹 통과. 신규 통신, 구버전 호환, 위조 메시지 거절, 저장 ACK·충돌·재시도·권한·CSV·인쇄를 확인했다. 새 진입 스크립트를 포함한 UI 회귀도 통과했다.
- 금융 복구·유휴 복구·가입·견적 연락처 관련 기존 단위 회귀 통과. 기존 저장 식별자 15종·31회와 로컬 암호키 파생 함수는 변경 전과 동일하다.
- 기존 차량 서류 브라우저 시험은 1440px에서 통과한 뒤 390px의 숨겨진 보기 전환 버튼에서 중단됐다. 변경 전 main으로 대조해 같은 시험 실패가 재현됐다. 기본 이미지 파일과 저장 데이터는 변경하지 않았다.
- 실제 옛 호스트의 HTTP 응답과 Cloudflare 프로젝트 삭제는 계정 연결·접속이 없어 검증하지 않았다. Git·원본 분류 자료·과거 배포 기록을 삭제한 것으로 보고하지 않는다.
