# 운영자 전용 자체 OCR 실험실 · v2.258

기준 main은 `1e742a78292cc76b87fccc077db5d0f1397c2b29`이다. `codex/operator-self-ocr-v2258` 테스트 브랜치에서 구현한다. 사용자의 최종 범위에 따라 딜러 등록 UI와 현재 Google Vision 경로는 유지하고 **운영자 메뉴에만 자체 OCR 테스트**를 추가한다. 운영 DB·Cloudflare 설정·비밀값은 바꾸지 않으며 main 병합·운영 전환은 이번 작업에 포함하지 않는다.

## 경로와 구성

[기존 흐름 조사](self-ocr-existing-flow-v2258.md)에 업로드·원본 준비·실제 Google 호출·파서·수동 수정 보호·최종 차량 폼 전달 위치를 기록했다. 새 테스트에서는 같은 운영자 인증 경계를 확장하고 차량 저장 기능은 호출하지 않는다.

| 구성 | 주요 파일 |
|---|---|

| 운영자 인증 중계 API | `functions/api/operator-ocr.js`, 기존 `operator.js`의 읽기 전용 인증 helper |

검출 **PP-OCRv6_small_det**, 한국어·영문·숫자 인식 **korean_PP-OCRv5_mobile_rec**을 **ONNX Runtime 1.23.2 CPU**로 실제 실행했다. 네이티브 PaddleOCR 3.3.2/PaddlePaddle 3.2.2 설치·모델 문서를 먼저 검토했으나 공식 가중치 호스트가 환경 정책으로 차단됐다. 공개 GitHub 모델 릴리스의 ONNX 파일을 설치 단계에서 준비하고 크기·배포자 SHA256을 고정했다. 원본 제공자의 독립 체크섬 대조는 미완료이며 출처·Apache-2.0 및 라이브러리 라이선스를 별도 기록한다. 이 구현을 새로 학습한 자체 모델이라고 표시하지 않는다.

## 추출·UI 보호

- 항목명과 위치·다음 칸 경계를 함께 사용한다. 숫자 2/3자리 및 구형 지역 차량번호, 17자리 VIN, 두 줄 차명, 명시된 모델연도를 처리한다. 트림을 추정하지 않는다.
- VIN의 해당 칸만 원본 해상도로 재판독한다. 문자 혼동·두 결과 불일치는 수동 확인이다. 흐린 필드 때문에 정상 필드의 전체 OCR을 반복하지 않는다.
- 모델연도 누락은 공란·확인 필요로 남기며 최초등록연도·한국어 연월 날짜를 대신 입력하지 않는다.
- 원본 해상도·EXIF 방향을 사용하고 네 방향을 확인한다. 기울어진 표는 토큰 좌표를 보정해 공간 판정을 수행한 뒤 표시 영역을 원래 좌표계로 되돌린다. 인접 칸 이름이 안 읽히거나 열 경계가 불확실하면 `layout_uncertain`으로 자동입력을 막는다.
- 사진 카드와 수정 가능한 네 항목 카드만 사용한다. 항목의 원본 영역을 같은 카드에서 확대하며 별도 확인 팝업·차량 자동 저장을 추가하지 않는다.
- 직접 수정한 필드는 늦은 응답과 재분석으로 덮어쓰지 않는다. A→B 사진 교체, 메뉴 이탈, 로그아웃 뒤 응답을 버린다. 재분석에서 불확실해진 이전 자동입력값은 지우되 직접 수정한 값은 남긴다.
- 같은 세션의 토큰 갱신은 화면과 편집값을 보존한다. 갱신 중 시작한 요청은 오래된 인증 결과를 적용하지 않고 재시도하도록 한다.

## 인증·파일·로그

브라우저는 기존 운영자 JWT로 같은 출처 `/api/operator-ocr`에 원본 이미지 한 장을 보낸다. 서버가 Auth 사용자와 실제 운영자 세션 allowlist를 확인하고, 비공개 CPU API로 전달하며, 결과 반환 전에 다시 세션을 확인한다. 상사 관리자·딜러 권한을 운영자로 인정하지 않는다.

Python API는 별도 서버 간 Bearer 키를 검증한다. 이 키는 브라우저에 전달하지 않는다. 입력은 최대 6MB·40MP JPG/PNG/WebP이고 메모리에서 처리하며 업로드 임시 파일·등록증 사본 DB·Storage 저장을 만들지 않는다. 전체 OCR 텍스트·주민번호·주소·원본 파일명·토큰·제공자 예외는 일반 로그에 쓰지 않는다. 응답도 네 항목과 확인 사유·위치·처리시간으로 제한한다. 원본 사진은 브라우저 메모리 URL로만 보이고 종료 시 회수한다.

Google 자동 폴백은 없다. `SNOTE_OPERATOR_OCR_PROVIDER=self`는 테스트 API만 선택하며 미설정·다른 값이면 연결 안내를 표시한다. Python 모델 로딩과 추론은 외부 연결을 사용하지 않는다. 실제 운영자 로그인/검증의 Supabase 연결은 오프라인 모델 검증과 구분한다.

## 실행과 평가

전체 명령은 [서비스 README](../services/registration-ocr/README.md)에 있다. 로컬 모델·서버를 준비한 뒤 `node --env-file=services/registration-ocr/local.env scripts/operator-ocr-dev.mjs`로 화면을 열고 `http://127.0.0.1:3000/operator.html#ocr-lab`에 기존 운영자로 로그인한다. 기존 Google 키와 Supabase service-role 키는 필요 없다.

평가 JSONL은 이미지 파일과 네 항목의 정답을 담는다. 차량번호·VIN은 문자 하나라도 다르면 오답이며 공백·대소문자 퍼지 대조를 하지 않는다. `tools/evaluate.py`는 항목별 완전 일치율·오답 자동입력·수동 확인·장당 시간을 출력하고 값/사진/파일명은 평가 보고서에 넣지 않는다. 실제 표본은 개인정보를 가린 뒤 별도 디렉터리에 두고 Git에 올리지 않는다.

독립 검토에서 인접 원동기 값의 차명 혼입, 한국어 최초등록 날짜의 연식 오인, 방향 동점, 재분석의 이전 값 잔류를 재현해 수정했다. [검토 결과](self-ocr-review-v2258.md)에 근거를 남겼다. 기존 운영 파일은 운영자 HTML·console·인증 helper·API 정책 네 개만 확장했고 딜러/Google OCR/스캐너/로고/폰트는 바이트 동일하다. Pages 함수 빌드도 통과했다.

증적은 작업 환경 `/workspace/work/self-ocr-v2258/`의 `evaluation-real-model-stress-final.json`, `evaluation-real-http-final.json`, `api-offline-real-model-final.json`, `pages-real-model-integration.json`, `qa/`에 보관한다.

## 운영 전환 전 확인

- 개인정보를 가린 실제 등록증과 정답 목록으로 양식·노후 번호판·폰 촬영·흐림별 정확도 및 오답 자동입력을 다시 평가한다. 합성 정확도를 실제 정확도로 제시하지 않는다.
- 원본 모델 배포 출처·라이선스·독립 체크섬을 재확인하고 선택한 버전을 고정한다.
- 비공개 CPU 호스팅·HTTPS·서버 간 키와 방화벽, 메모리/CPU·동시 처리 한도·재시도/시간 제한을 준비한다.
- 실제 운영자 세션·로그아웃/권한 회수 및 프록시 로그 정책을 검증한다. 현재 로그인 검증의 외부 인증 연결과 OCR 추론의 오프라인 조건을 구분한다.
- 사용자 검토 후에만 운영 환경의 자체 OCR 주소/설정을 연결한다. 현재 Google Vision 실사용 흐름은 계속 유지한다.
