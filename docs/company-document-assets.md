# 상사 도장과 로고 표시 — v2.128

계약서가 설정에 등록한 상사 도장을 읽지 않고 고정된 예전 이미지를 사용하던 연결을 교체했습니다. 회사 로고를 갱신하면서 다른 화면이 사용하는 Blob URL을 먼저 회수해 이미지가 깨지던 캐시 관리도 통합했습니다.

계약서는 현재 상사의 `companyStamp` 이미지를 매도 계약의 매도인, 매수 계약의 매수인 성명 옆 `(인)`에 표시합니다. 고객의 휴대폰 제출 서명은 기존 별도 처리와 위치를 유지합니다. 등록된 도장이 없으면 `(인)`을 비워 두며, 예전 도장이나 다른 상사의 이미지를 대체하여 표시하지 않습니다. 등록 파일 조회·다운로드·디코딩이 실패한 상태에서는 인쇄 버튼이 안내를 표시하고 인쇄를 진행하지 않습니다.

설정의 도장·로고 미리보기, 프로필 상사 로고, 견적서·계약서의 하단 로고가 하나의 로더를 사용합니다. 비공개 `zc-vehicle-private` 버킷의 기존 인증된 다운로드를 유지합니다. 최신 메타데이터의 회사·종류·업로드 경로·파일 형식과 크기를 확인하고 실제 이미지 디코딩이 끝나야 표시합니다. 동일 경로의 디코딩된 이미지는 재사용하며, 교체·삭제·로그아웃·계정 변경 시 먼저 화면의 참조를 지운 뒤 URL을 회수합니다.

인쇄는 상사 이미지와 고객 원서명 준비를 기다린 다음 두 장의 A4 계약서 복사본을 다시 구성합니다. 기다리는 동안 차량·계정·문서가 바뀌면 이전 작업을 적용하지 않습니다. 프로필 로고 갱신은 작성 중인 이름·연락처 등의 입력을 초기화하지 않습니다. 이미지 로드 실패 시 깨진 이미지 표시를 숨기고, 문서 로고는 기존 S-NOTE 기본 로고를 사용합니다.

추가 SQL·환경변수·재등록 절차는 없습니다. 이번 변경으로 실제 상사 이미지 파일이나 고객정보를 수정하지 않습니다. 운영 메타데이터의 기존 로고·도장 파일 존재 여부는 읽기 전용으로 확인했으며, 자동 화면·인쇄 검증은 합성 이미지와 가상 계정으로 실행합니다.

검증 명령과 결과는 [company-document-assets-verification.json](company-document-assets-verification.json)에 기록합니다. 새 배포에는 `index.html`, `assets/company-assets.js`, `assets/profile-editor.js`를 함께 포함합니다.
