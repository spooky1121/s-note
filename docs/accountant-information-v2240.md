# 경리 정보 관리 — v2.240

정보를 사이드바의 단일 메뉴로 표시하고 계좌·전화번호·직원을 페이지 안의 탭으로 나눈다. 경리 기본 페이지의 상단 메뉴 제목·설명은 표시하지 않는다. 기존 `acctAccounts`, `acctPhones`, `acctStaff` 진입은 `acctInfo`의 해당 탭으로 연결하며 뒤로가기·저장 전 이동 확인을 유지한다.

## 등록 항목

- 계좌: 은행명, 계좌번호, 메모. 계좌번호는 문자로 보관해 앞자리 0과 하이픈을 유지한다.
- 전화번호: 이름, 전화번호, 그룹, 메모. 새 그룹 등록·이름 변경·그룹 지정·미지정과 그룹별 조회를 제공한다.
- 직원: 기존에 확인한 소속 상사 활성 직원 정보를 읽기 전용으로 표시한다.

연락처·그룹·계좌는 등록·수정·삭제할 수 있다. 전화번호가 연결된 그룹은 먼저 다른 그룹 또는 미지정으로 옮긴 뒤 삭제한다. 그룹 이름 변경은 편집 중인 연락처의 이름·메모·선택 그룹을 바꾸지 않는다.

같은 상사의 관리자·경리가 서버에서 공유하는 독립 정보 장부다. 경리 화면에서만 새 메뉴를 노출하며, 기존 개인 입금계좌·선재고·재고금융 데이터와 저장 경로를 분리한다. 연락처 등록은 직원 로그인 계정이나 인증 휴대전화 변경을 수행하지 않는다.

## 저장과 접근

새 비공개 스키마 `snote_information_private`에 그룹·연락처·계좌를 보관한다. 테이블의 직접 접근을 허용하지 않으며, 공개 invoker RPC 세 개가 비공개 검증 경로를 통해 현재 세션·소속 상사·활성 관리자/경리 역할을 확인한다. 기존 세션 검증 함수는 그대로 사용한다.

목록은 한 SQL 스냅샷에서 세 종류의 자료와 개수를 함께 반환한다. 그룹 500개·연락처 5,000개·계좌 2,000개 한도를 명시하고 불완전한 응답을 정상 목록으로 적용하지 않는다. 저장·삭제는 UUID와 revision을 확인하며, 충돌 시 입력을 유지한다. 응답을 잃은 재요청은 같은 ID·내용·revision으로만 처리하고 삭제는 tombstone 응답으로 확인한다.

브라우저는 검증한 토큰을 요청에 고정한다. 정보 페이지·계정·상사·세션이 바뀌면 이전 응답을 새 화면에 적용하지 않는다. 서버의 권한 거부를 확인하면 편집 화면과 메모를 즉시 비우며, 연락처·계좌를 브라우저 저장소에 새로 보관하지 않는다. 정보 모듈은 첫 메뉴 사용 시 로드한다.

## 검증

격리 PostgreSQL 테스트와 저장소 단위 테스트에서 상사·역할·세션 분리, CAS, 재시도, 그룹 참조, 한도, 완전한 목록과 기존 객체 보존을 확인한다. 브라우저에서는 가상 자료로 등록·수정·삭제·재접속, 화면 크기, 탭·뒤로가기, 저장 충돌·지연 응답·권한 철회와 기존 금융 화면을 점검한다. 검증 기록은 작업 환경의 `/workspace/work/accountant-information-v2240`에 보관한다.
