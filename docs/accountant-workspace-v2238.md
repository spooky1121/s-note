# 경리 대시보드와 상사 차량 서류함 — v2.238

경리의 기본 진입과 메뉴에 대시보드를 추가했다. 금융 요약 계산을 열지 않고, 검증된 상사 차량의 전체·보유·계약 진행·이번 달 매입 건수와 개인 달력, 오늘·다가올 일정, 서류함·매입관리 바로가기를 제공한다. 회사 차량을 확인하는 동안 건수를 먼저 0으로 표시하지 않는다. 기존 딜러·관리자 금액 대시보드와 금액 잠금은 유지한다.

개인 일정의 클라이언트 context·store·서버 actor에 경리를 추가한다. 계정·상사·역할·세션, 본인 소유, 수정 버전(CAS), 중복 ACK와 삭제 조건은 유지한다. 경리 달력의 차량 매입·판매 표시는 같은 상사 canonical 차량의 날짜만 읽고, 금액을 투영하지 않는다. 딜러·관리자의 차량 날짜 범위는 기존 본인 차량 그대로다.

## 서류함

상단 내부 제목을 제거하고 차량 기준으로 차량번호·차명·매입일·매입금액·양수인·자동차등록증의 여섯 열을 제공한다. 같은 상사 canonical 매입 차량을 기준으로 판매완료·미작성 차량도 표시하고 휴지통·다른 상사에서 받은 공유 차량은 포함하지 않는다. 이전 직원의 차량도 회사 조회에서 허용되는 자료는 유지한다. 문서는 담당자 UUID와 차량 ID를 함께 비교한다. 양수인은 최신 연결 문서의 저장된 값을 사용하며 문서가 없으면 빈 표시를 사용한다. 고객관리 DB 권한을 새로 열지 않는다.

기존 미연결 문서와 이전 연결 문서는 접힌 ‘이전 문서 보기’에서 그대로 열고 수정·저장·인쇄할 수 있다. 문서 자체나 차량 자료를 삭제하지 않는다. 검색과 두 목록의 페이지 이동은 독립적으로 동작한다.

등록증은 상사 범위의 메타데이터만 먼저 조회하고 클릭한 파일만 비공개 Storage에서 불러온다. 업로더와 차량 담당자가 다를 수 있으므로 둘을 동일한 값으로 가정하지 않는다. 같은 raw 차량 ID가 여러 담당자에게 있으면 잘못 연결하지 않고 ‘연결 확인’으로 표시한다. 조회가 불완전하면 미등록으로 단정하지 않는다. 등록증 조회는 최대 3,000개 메타데이터까지 확인하며, 불완전한 응답에 포함되지 않은 차량은 확인 중 상태를 유지한다. 파일 경로·이미지 형식·크기, 원래 문서 열기 상태, 계정·상사·자료 세대가 바뀌는 동안의 응답을 검증한다.

## 메뉴 범위

차량 검수 도우미는 딜러에게만 표시한다. 관리자·경리에서는 메뉴뿐 아니라 직접 이동·해시 복원·통합검색·늦은 모듈 연결도 허용하지 않는다. 딜러의 기존 검수 체크와 PDF 사진 학습 자료는 유지한다.

## 서버 변경과 검증

후속 migration은 `snote_schedule_private.actor(uuid)`의 기존 허용 역할에 `accountant`를 추가하는 한 곳만 변경한다. 일정 데이터·테이블·RLS·공개 RPC 권한·함수 소유자·세션 검증을 변경하지 않는다. 격리 SQL의 신규 15개 및 원래 migration 회귀 16개를 통과했다. 운영 적용 전 함수 본문과 ACL·search_path·소유자 메타데이터를 대조한다.

신규 브라우저 검증은 경리 대시보드·일정 12개, 서류함 6개, 검수 메뉴 권한 4개, 실제 모바일 뷰포트 위치 1개의 총 23개를 통과했다. 1440/360/390/430px에서 계정·상사·역할 전환, 일정 CRUD·CAS·늦은 응답, 비금융 요약, 실제 등록증 1개 선택 로딩과 이탈 후 취소를 확인했다. PC·모바일 화면을 직접 검토했고 글꼴·공식 로고 해시를 유지했다.

단위 검증은 등록증 스토어 26개, 서류함 모델 8개, 차량 달력 ID 13개와 경리 대시보드·기존 대시보드·일정 스토어 모델을 통과했다. HTML 내부 스크립트 8개 및 관련 JS 구문·diff 검사를 통과했다. 차량 달력은 raw ID의 기존 200자 한도를 유지하면서 소유자 UUID를 내부 고유 키에 합성해, 긴 ID나 담당자별 동일 ID를 누락·혼동하지 않는다.

문서 복귀 시 검색창이 자동으로 열려 다음 행 클릭을 가로막지 않도록 복귀 포커스를 조정했다. 수정 후 등록증·서류함과 미연결 문서 열기, 연속 매입·매도 문서 A4 출력까지 확인해 신규 최종 25개를 통과했다. 관련 기존 회귀는 일정 CRUD·권한·CAS·lifecycle 4그룹, 딜러 검수 사진 학습 및 비딜러 거부 21개, 검색 역할·기능 12개, 이전 매입·매도 서류 archive 2종을 통과했다. 수동 검색 팝오버는 기존 흐림·바깥 클릭 닫기 동작을 유지한다.

기존 문서 heavy suite의 변경 없는 전체 사례는 반복하지 않고 변경된 서류함의 페이징·fresh read·CAS·A4·늦은 상사 응답을 두 문서 종류에서 선택 검증했다. 일부 구 fixture의 startup 대기는 실행 메모리에서 자연스러운 표시를 기다리는 hook을 사용했으며 제품·공통 fixture를 강제로 표시하도록 바꾸지 않았다.

운영 반영은 서버 함수 메타데이터 및 보안 권고 전후 대조와 정확한 main 커밋의 Cloudflare Pages 결과로 확인한다. 모든 시험 계정·차량·고객·파일은 가상 자료이며 운영 고객과 업무 데이터는 사용하거나 변경하지 않았다. 모바일은 Chromium 뷰포트 모사로 검증했으며 실제 기기는 사용하지 않았다.
