# v2.211 판매완료 차량 등록·정산

판매완료 화면 상단의 등록 버튼은 ‘판매등록’이다. 기존 매입 등록과 같은 차량 정보 입력 형식을 유지하고, 판매등록에서만 금액·비용과 정산 화면을 바꾼다. 매입 화면의 등록·재고 설정·금융 입력은 유지한다.

금액·비용 화면에서 판매가와 판매일을 직접 입력한다. 판매가는 양수여야 하며, 실제 날짜와 매입일 이전 여부를 최종 저장 경로에서도 검증한다. 기존 고정 매입 부대비용 입력은 판매등록에서 숨기고 추가비용만 받는다. ‘매입 부대비용 (-)’는 빨간색, ‘수익 (+)’는 파란색으로 표시한다. 수익의 기본 항목은 수수료·보험·할부금융이며 이름과 금액을 가진 추가수익을 더할 수 있다.

정산 화면은 차대금(판매가)을 위에 표시하고 아래를 비용·수익 두 열로 나눈다. 비용은 매입가와 추가비용, 수익 열은 부가수익 항목을 표시한다. 최종 합산 정산은 **판매가 − 매입가 − 추가비용 + 부가수익**이다. 차대금을 부가수익에 다시 포함하지 않는다. 금액 수정·항목 추가·삭제 시 합계를 즉시 갱신한다.

판매등록은 기존 소유자·상사 범위의 저장과 충돌 검사를 사용하며 판매완료로 저장한다. 새 판매등록의 재고대출금은 0원, 선재고 사용은 해제 상태다. 확인 응답 전에는 성공으로 표시하지 않으며 중복 클릭과 응답 유실 후 재시도에는 같은 등록 시도를 사용한다. 저장 성공 시 해당 판매월 목록에 등록한 차량을 표시한다.

부가수익은 선택 필드 `saleRegistrationIncome`에 정수 원 단위로 보관한다. 기존 차량 장부의 만원 단위 직렬화는 유지하고 이 필드는 자체 `moneyUnit: KRW`를 유지한다. 차량 ID·판매일·실제 판매가와 결합한 유효한 판매완료 내역만 수익 계산에 한 번 더한다. 비용·총투입원가·재고투자금에는 더하지 않는다. 별도 소득정산 세무 문서와 그 계산은 변경하지 않는다.

동일 판매의 금액·날짜를 수정하면 유효한 수익 내역의 결합 정보를 갱신한다. 판매취소 후에는 부가수익을 제거하고 복제·다른 차량·미판매 상태의 부가수익은 합산하지 않는다. 운영자 수정 경로에서는 기존 SQL의 필드 보존 규칙을 만족하도록 취소 필드를 null로 남겨 동일하게 0원 처리한다. 운영 DB 마이그레이션이나 권한 변경은 없다.

가상 데이터로 판매등록 9그룹(1440/360/390/430px, 실패·응답유실 재시도, 날짜·금액 검증, 매입 모드 복원, 판매취소, 딜러·경리·관리자 범위)을 검증했다. 기존 매입 등록 16그룹과 판매 검증 2폭도 통과했다. 모델·원화 변환·운영자 API·운영자 SQL 회귀 및 격리된 PostgreSQL의 실제 장부 RPC/CAS/상사 권한 검증을 통과했다. 예시 금액 10,000,001원 매입·12,000,004원 판매·125,001원 추가비용·76,005원 부가수익의 정산은 1,951,007원이다.

운영 고객 데이터·DB 설정·문자·NAS·백업에는 접근하지 않았다. 브라우저 검증은 Chromium과 가상 응답으로 수행했으며 실제 휴대기기와 운영 계정에서의 등록은 수행하지 않았다.
