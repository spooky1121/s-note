# v2.251 저해상도 차량 목록과 로그인 첫 표시

차량 목록의 고정 최소 너비와 셀의 줄바꿈 금지 때문에 작은 노트북에서 가로 스크롤이 발생했다. 목록에만 화면 너비에 맞는 글씨 크기·간격을 적용하고, 선택한 열이 들어가지 않으면 같은 차량의 주요 정보 아래에 라벨이 있는 부가 정보를 배치한다. 차량번호·날짜·금액은 중간에서 끊지 않는다. 넓은 화면의 기본 표와 모바일 카드, 원본 셀·이벤트·개인별 열 설정을 유지한다. 항목을 숨기거나 바깥 부분을 잘라서 넘침을 감추지 않는다.

로그인은 현재 디자인을 초기 HTML의 화면 전용 스타일에 포함했다. 뒤늦게 요청하던 `login-landing.css`, `login-refinement.css`를 제거하고 로그인 글씨 크기도 초기 스타일로 이동했다. 초대 가입·저작권 안내를 초기 HTML에 확정해 후속 문구 치환을 제거했다. 장식 모듈이 지연·실패해도 인증을 사용할 수 있고 JavaScript 비활성 상태에는 안내를 표시한다. 차량 목록 초기화도 최초 데이터 렌더 전에 설치해 지연된 부가 스타일에 의존하지 않는다.

## 확인 방법

실제 로컬 HTML·CSS·핸들러를 Chromium에서 실행하고 계정·차량·고객·문서·API 응답은 모두 가상 데이터로 대체했다. 로그인 전후 운영 DB나 실제 고객 자료를 읽거나 수정하지 않았다.

- `tests/vehicle-list-responsive-v2251.browser.cjs`: 기본·전체 열의 변경 전후 너비, 선택열·정렬·상태·사진·키보드·페이지·역할별 목록·모바일 전환.
- `tests/login-first-paint-v2251.browser.cjs`: PC/모바일의 지연 CSS·JS 전후 좌표·글씨 크기·문구 동일성, 장식 파일 실패, JavaScript 비활성 상태.
- `tests/login-availability-v2229.browser.cjs`: 부가 CSS 지연 중 로그인·목록·로그아웃·재로그인, 필수 CSS 지연, 글꼴·이미지 실패, 비밀번호·멤버십 거부.
- `tests/layout-overlap-v2251.browser.cjs`: 딜러·관리자·경리·운영자 및 공개 페이지의 주요 영역, 헤더 버튼, 로고와 경계 넘침. 의도적인 팝업·툴팁·인쇄 복사본은 겹침 오류에서 제외한다.

로그인 첫 표시 5개, 가용성 8개, 기존 로그인 10개, 소개 화면 6개 검증을 통과했다. 지연 CSS 상태의 목록 `scrollWidth/clientWidth`는 1024px 화면에서 `912/912`, 1440px에서 `1212/1212`였다. 일반 부가 스타일이 도착해도 로그인 폼·제목·사진·안내·하단 영역의 좌표와 크기는 같았다.

차량 전용 검증의 28개 측정·기능 기록도 통과했다. 같은 가상 차량과 화면에서 신규 목록 스타일을 제외했을 때와 적용했을 때의 목록 가로 넘침은 다음과 같다. 단위는 CSS px이며 적용 후에는 개별 셀의 내용과 선택한 항목도 목록 안에 들어오는지 확인했다.

| 화면 너비 | 기본 13항목 적용 전 | 전체 20항목 적용 전 | 적용 후 기본/전체 |
|---|---:|---:|---:|

| 1280 | 477 | 1189 | 0 / 0 |
| 1366 | 400 | 1112 | 0 / 0 |

| 1920 | 0 | 706 | 0 / 0 |

360/390px 모바일 카드, 딜러·경리·관리자 목록, 정렬·사진 확대·상태 선택·키보드 진입·페이지 이동·빈 목록·숨긴 열·원본 데이터 및 개인 설정 유지도 확인했다.

주요 메뉴 감사는 1024×600, 1280×720, 1366×768, 1440×900, 1920×1080, 360/390px에서 실제 182개 화면 조합을 검사해 넘침·겹침·컨트롤 잘림·로고 넘침이 없었다. 딜러·관리자 고객 목록, 경리 전화번호 탭, 월정산 부모 화면과 iframe, 공개 고객 확인·이름 입력·계정 복구 화면도 포함한다. 중복 탭 검사는 집계에서 제외했다.

계약서·인수증은 1024×600·1366×768·390×844의 6개 화면/실제 PDF 검증을 통과했다. 버튼 배치, 편집·리사이즈, 모바일 입력 필드, 본문·서명, 계약서 2페이지·인수증 1페이지를 유지했다. 테스트 공통 fixture에는 초기 화면의 표시 대기가 끝난 뒤 실제 가시성을 검사하도록 한 줄의 제한 시간 있는 대기를 추가했다. 기존 가시성 검사는 그대로 유지했다.

견적서도 같은 3개 화면 크기에서 편집·리사이즈·모바일 키보드 조건·실제 PDF와 1페이지 출력을 검증했다. 이전 인쇄 안전성 수정에서 쓰는 임시 선택적 로고 속성 하나만 테스트의 clone 비교에서 정규화했으며, 문서 본문·금액·상태·인쇄 검사는 유지했다. 총 문서 화면/PDF 9개 검증을 통과했고 제품 인쇄 코드는 변경하지 않았다.

## 범위와 한계

운영 DB·권한·업무 계산·상사 자료·서버 설정·스캐너 연결 도우미는 변경하지 않는다. 공식 로고와 Pretendard 글꼴 파일도 기존 SHA-256과 동일하다. 문서 화면과 A4 인쇄 스타일은 수정하지 않는다. 경리 금융사 카드와 월정산 장부의 의도적인 내부 스크롤은 유지한다.

검증은 데스크톱 Chromium의 화면 크기 및 자산 지연·실패 재현이다. 실제 저사양 노트북의 CPU·그래픽·브라우저 조합을 모두 시험한 것은 아니다.

관련 없음이 확인된 기존 테스트 실패: `service-brand-boundaries.test.mjs`의 보호된 과거 테스트 파일 해시가 최신 main에서도 정책 해시와 다르다. `tests/contract-print-recovery-v2165.browser.cjs`는 이번 작업과 최신 main의 바이트가 동일하며, 이 변경에서는 보호 정책을 완화하거나 그 파일을 수정하지 않았다.

`purchase-columns-v2177.browser.cjs` 전체 실행의 과거 모바일 가정은 현행 정책과 다르다. 이 테스트는 모바일에서 재고대출금이 표시되기를 기대하지만 현행 모바일 카드는 재고금융 항목을 숨긴다. 신규 반응형 자산 두 개를 제외해도 같은 실패가 발생한다. 새 모바일 검증은 현재 카드 정책과 개인별 선택 설정이 유지되는지 확인한다.

과거 선택열·보기 테스트의 전체 실행을 통과로 계상하지 않았다. 이전 스키마 버전·은행 설정 화면 포커스 등 현재와 다른 UI 기대도 포함돼 있다. 현재 유효한 데스크톱 금융 표시·정렬·견적서 클릭/Enter 진입은 통과했고, 이번 변경의 현재 동작은 신규 목록 검증으로 확인했다.
