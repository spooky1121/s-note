# 경리 스캐너 이미지 수신함 · v2.247

기준 main은 v2.246 `30d87f4bbfd7cb4d088a9c4b041481aa8a8c8cd6`이다. 경리 왼쪽 메뉴에서 서류함 다음에 스캐너를 표시한다. 기존 메뉴·계정·인쇄·차량 자료는 변경하지 않는다.

## 제공 기능

스캐너 앱에서 저장한 JPG·PNG·WebP 이미지를 파일 선택 또는 끌어놓기로 등록한다. 한 번에 최대 10장, 파일당 5MiB 이하이며 순서대로 업로드한다. 저장 상태와 명시적 재시도를 제공하고, 불확정 응답은 같은 File과 요청 ID로 다시 확인한다. 이미 저장된 파일은 유지하며 선택한 파일을 닫을 때 저장되지 않은 선택만 취소한다.

등록한 이미지는 상사의 비공개 수신함에 보관한다. 등록일·파일명·용량과 보기·다운로드·삭제를 제공한다. 목록은 최신 30장씩 읽고 더 보기로 이어진다. 커서의 6자리 소수 초를 원문 그대로 전달하여 같은 밀리초에 등록된 자료를 빠뜨리지 않는다. 이미지 바이트는 보기나 다운로드를 누를 때만 받는다. 상사 로고·도장·가입 증빙·차량서류·운영서류에 자동으로 첨부하거나 덮어쓰지 않는다. OCR도 실행하지 않는다.

이 화면은 스캐너 장치를 직접 제어하지 않는다. Windows의 장치 스캔은 설치된 장치·드라이버를 사용하는 [별도 스캔 앱/API](https://learn.microsoft.com/en-us/windows/apps/develop/devices-sensors/scan-from-your-app) 영역이고, 이번 기능은 [브라우저 파일 선택](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/file)을 사용한다. USB·네트워크 장치 연결 서비스나 유료 SDK 설치는 추가하지 않았다. PDF·TIFF·BMP는 이번 이미지 업로드의 지원 형식이 아니다.

## 저장·권한

새 `snote-scanner-inbox` 비공개 버킷과 `snote_scanner_private.requests/scans`만 사용한다. 기존 운영서류의 context·actor 검증과 순수 이미지 검증기를 그대로 재사용한다. API는 현재 상사의 활성 경리·관리자 및 살아 있는 세션을 매 작업 확인하며, 경리 UI만 메뉴와 경로를 노출한다. 다른 상사·딜러·운영자·비활성 계정은 차단한다.

서버가 이미지 형식·구조·크기·최대 4천만 화소·SHA256을 확인한다. 고유 파일 ID와 불변 경로를 사용하며 저장 실패·응답 유실·삭제 충돌을 보호한다. 직접 테이블/Storage 권한을 주지 않으며 명시적 false RLS와 서비스 전용 검증 함수를 사용한다. 공개·서명 URL을 발급하지 않는다. 파일명·경로·토큰을 서비스 관측에 기록하지 않는다.

삭제는 먼저 검증된 tombstone ACK를 받은 뒤 목록에서 제거한다. 물리 삭제는 Storage API를 사용한다. 중단된 업로드의 lease, 정리 실패, 정리 후 늦게 생성된 객체도 후속 승인된 요청에서 안전하게 수거한다. 실제 상사·계정·세션·경로가 바뀌거나 서버가 권한을 거부하면 화면 자료와 임시 URL을 폐기한다. 일반 확인창이나 이미지 보기의 일시적 inert 상태는 계정 변경으로 오인하지 않는다.

관련 저장 모델은 [Supabase 비공개 버킷](https://supabase.com/docs/guides/storage/buckets/fundamentals)과 [Storage 객체 삭제](https://supabase.com/docs/guides/storage/management/delete-objects)를 따른다. SDK·Auth·기존 버킷·Cloudflare 비밀값·NAS/백업 설정은 수정하지 않는다.

## 검증과 적용

가상 계정·이미지만 사용하여 UI/클라이언트 단위 25개, 새 SQL·API와 기존 운영서류·보안·관측 회귀 61개, 실제 Pages/workerd 실행을 확인했다. PC 1440px 및 모바일 430/390/360px에서 통합 20개를 검증했다. 로그인 지연 로딩, 업로드 재시도와 지속성, 미리보기·다운로드·삭제, 상사 분리, 권한 회수, 늦은 응답과 기존 정보·운영정산 동작을 포함한다. 서비스 로고·Pretendard 바이너리는 유지한다.

운영 적용에는 CLI로 만든 `20261126165102_accountant_scanner_inbox.sql` 한 건이 필요하다. 적용 후 기존 권한 함수의 해시·ACL, 새 버킷·테이블·함수·정책을 메타데이터로 대조해야 한다. 실제 운영 고객 파일 CRUD, 실제 스캐너 하드웨어, 실제 다중 연결 잠금 경합은 시험하지 않았다. GitHub와 운영 배포는 검증한 동일 소스 기준으로 확인한다.
