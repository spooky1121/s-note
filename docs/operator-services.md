# 운영자 계정·서비스 관리

v2.202는 기존 운영자 허용 목록과 실제 Auth 세션 검사를 그대로 사용한다. 일반 상사대표·딜러·경리에게 운영자 권한을 추가하지 않는다.

## 계정과 상담

- 계정관리에는 이름 앞 프로필 사진, 계정ID, 비밀번호 설정 여부와 변경 버튼, 연락처, 상사, 최근 로그인·확인된 로그아웃을 표시한다. 원래 비밀번호나 암호 해시는 반환하지 않는다.
- 프로필 사진은 등록된 비공개 Storage 파일만 운영자 API에서 읽는다. 최대 5MiB의 기존 사진을 지원하고, 보이는 사진을 동시에 두 개까지만 읽는다. 임의 외부 이미지 주소를 실행하지 않으며, 사진이 없으면 이름 첫 글자를 표시한다.
- 로그아웃은 SDK 성공 뒤 캡처한 본인 JWT로 확인한다. DB는 해당 JWT의 관측된 본인 세션이 Auth에서 실제로 사라진 경우에만 최초 확인 시각을 기록한다. 과거 기록·창 닫기·유휴 만료를 로그아웃으로 추정하지 않는다.
- 챗봇 숫자는 대화 수가 아닌 읽지 않은 사용자 메시지 수다. 빨간 숫자로 깜빡이며, 동작 줄이기 설정에서는 움직임을 멈춘다.

## 서비스 메뉴

- **문자메세지 서비스:** 보관 중인 S-NOTE 고객 입력 요청의 담당자·차종·수신번호·발송 접수·고객 제출 여부를 표시한다. 솔라피 최근 발송 최대 20건은 별도 표로 보여주며, 사용자·차량과 임의로 연결하지 않는다. 본문·OTP·이미지·추가 필드는 반환하지 않는다.
- **잔액과 단가:** 서버의 기존 SOLAPI 연결로 잔액·포인트·SMS/LMS/MMS/알림톡 계정 단가를 조회한다. 필요한 읽기 권한은 `cash:read`, `pricing:read`, `message:read`다. 일부 조회 실패 시 가능한 정보와 S-NOTE 기록은 유지하고, 알 수 없는 금액을 0원으로 표시하지 않는다. 실제 발송이나 유료 연결 시험은 하지 않는다.
- **엔카 광고찾기:** 수집 적용 이후 최근 30일의 실제 검색 계정·시각·성공·처리 시간·광고 ID·공식 엔카 링크를 표시한다. 차량번호·차대번호·외부 원문 URL은 로그에 넣지 않는다. 검색의 중복 처리·재시도·권한은 유지한다.
- **Google vision:** 수집된 OCR 요청 수·실패·사용자·단계·처리 시간·확인된 이미지 크기를 표시한다. 원본 이미지·판독문·고객 입력값은 수집하지 않는다. API 연결 설정이 있어도 Google Cloud 전체 사용량·요금·할당량을 검증한 것으로 표시하지 않는다.
- **서버:** 모든 Storage 버킷의 이미지 MIME 메타데이터를 기준으로 이미지 수·크기를 집계한다. 크기가 없는 이미지가 있으면 전체 크기는 미확인으로 둔다. API 요청·오류·관측된 응답 본문 바이트와 크기를 확인한 요청 바이트를 별도로 보여준다.

서버 지표는 앱의 지정 API 관측값이며 정적 이미지 다운로드·CDN·Cloudflare 전체 트래픽이나 청구량이 아니다. 관측은 응답을 복제·버퍼링하지 않고 통과시키며, 기록 실패가 원래 작업을 막지 않는다. 공개 요청으로 과도한 DB 기록이 발생하지 않도록 관측만 실행 인스턴스당 분당 최대 240건으로 제한한다. 검색·OCR 등 원래 사용자 작업을 이 제한으로 막지 않는다. 30일 조회와 별도로 관측 원본은 최대 90일 보관을 목표로 새 기록마다 오래된 행을 최대 100개 정리한다. 기존 업무·고객·감사 기록과 백업은 정리 대상이 아니다.

## 설치와 검증

DB 변경은 [마이그레이션](../supabase/migrations/20261123120535_operator_service_observations.sql)을 먼저 적용하고 새 운영자 코드를 배포한다. 기존 비밀값을 브라우저에 넣거나 변경할 필요는 없다. 연결 도구의 별도 실행 확인이 끝나지 않았다면 DB 반영 완료로 보고하지 않는다.

새 SQL 14그룹·기존 운영자/접속 23그룹, 제공사 13건, 관측 관련 84건, HTTP 스트리밍 7건, 운영자 API 추가 9건, 로그아웃 확인 10건, 새 UI 9그룹·기존 UI 7그룹, 메뉴 정렬 5그룹을 가상 데이터로 검증했다. 실제 Pages 빌드와 workerd의 OCR·문자 조회·비공개 사진·관측 3그룹도 확인했다. 설치된 workerd는 2026-10-26까지만 지원해 실행 시험에서는 그 날짜를 명시했으며, 2026-11-01 기본값으로 실행하는 기존 시험은 런타임 시작 단계에서 거절됐다. 배포용 빌드는 원래 2026-11-01로 유지한다.

기존 운영자 시험 중 보관 탭이 변경 저장 종료보다 먼저 클릭된 한 번의 타이밍 실패는 로그에 보존했으며, 직렬 재실행은 7그룹 모두 통과했다. 전체 계정 원문 비밀번호, 실고객 문자 발송, 유료 OCR·브라우저 호출, 실제 운영 로그인이나 프린터를 검증했다고 보고하지 않는다. 외부 제공사 계정의 읽기 권한과 최종 운영 수신은 별도 실제 응답으로 확인한다.
