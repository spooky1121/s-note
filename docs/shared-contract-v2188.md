# v2.188 · 고객 입력 오류와 공유 차량 계약

기준 main: `165c42d25933b25d6300d620a7d5f44cb420d097`.

## 변경

- 판매 창의 자동 요청 내역 조회가 실패할 때 본인 차량이 아니라는 팝업을 반복하지 않는다. 입력값을 유지하고 창 안에 재확인 기능을 제공한다. 재확인과 발송은 서버 저장 확인 후 권한 조회에 성공해야 진행한다.
- 접속 주소 불일치는 소유권 오류와 별도 코드로 구분한다. 기존 출처 제한은 유지한다. 인증 토큰을 받는 동안 계정·상사·세션이 바뀌면 결과를 사용하지 않는다.
- 수락된 수정/모든 권한 공유만 계약을 진행할 수 있다. 조회/삭제 권한을 계약 쓰기 권한으로 확장하지 않는다.
- 수신 딜러 전용 계약 ID로 고객정보·암호문·서명·문서를 저장한다. 원래 재고와 고객을 복제하거나 수정하지 않는다. 원래 상사를 매도 상사로, 수신 딜러를 담당자로 표시한다. 다른 상사의 법인 도장·로고를 혼용하지 않는다.
- 고객목록에서 공유 계약서·인수증을 다시 열고 인쇄할 수 있다. 공유 회수·권한 변경·상사/계정 변경 후에는 서버가 접근을 거부하고 열려 있는 화면의 개인정보를 지운다.
- 공유 경로의 저장은 기존 CAS/복원 세대 검증을 거친다. 직접 쓰기와 과거 식별번호 RPC를 통한 우회를 차단한다. 공개 입력 링크는 표시용 차량정보만 받는다.

## DB 적용

Supabase CLI로 만든 `20261122135201_shared_vehicle_contract_contexts.sql` 한 건만 적용한다. 기존 운영 데이터나 설정 변경, 관련 없는 과거 마이그레이션의 일괄 적용은 하지 않는다.

설치된 함수 본문의 CRLF 줄바꿈을 LF로 정규화한 뒤 대상 블록을 정확히 한 번 찾았을 때만 확장한다. 선택적인 과거 `snote_intake_rrn_access` 함수가 없으면 만들지 않는다. 필수 함수의 예상 구성이 다르면 전체 트랜잭션을 중단한다. 기존 구현 복사본의 외부 실행권한은 제거한다.

운영 적용 이름/버전: `shared_vehicle_contract_contexts` / `20261122142638`.
적용 SQL SHA256: `6e9baf90f80caf0c6c389188237fea21f2307e34036257e97677b861027da900`.
적용 후 RLS, 네 개 제한 정책, 새 공개 RPC 세 개의 authenticated 전용 실행권한과 invoker 속성, 필수 함수의 공유 잠금 분기, 없는 계약의 거부를 읽기 전용으로 확인했다.

보안 advisor의 기존 WARN 항목은 증가하지 않았다. 새 private 계약 연결 테이블은 테이블 권한을 모두 회수하고 검증된 RPC로만 접근하도록 설계해, 정책 없는 RLS의 INFO 알림이 추가된다([설명](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)).
