# 고객 휴대폰 단계 입력·서명·자동 반영

v2.15에서는 차량을 확인한 뒤 한 화면에 한 항목씩 입력합니다.

1. 성함
2. 주민등록번호
3. 등본상 주소와 상세주소 — 카카오 새 창 검색 지원
4. 전화번호와 문자 인증
5. 환급계좌 — 필요 없으면 건너뛰기
6. 개인정보 활용 동의와 손서명

마지막 완료 버튼을 누를 때 고객정보·주민번호·서명을 함께 서버에 제출합니다. 성함·주민번호·주소는 단계 이동 중 서버에 저장하거나 휴대폰 브라우저 저장소에 보관하지 않습니다. 전화번호 단계의 인증 요청에는 문자 링크를 받은 번호를 입력하며, 다른 수신 번호로 변경할 수 없습니다.

## 적용

1. Supabase SQL Editor에서 [0004 단계 입력·서명 SQL](../supabase/migrations/202611010004_customer_intake_wizard.sql)을 **처음부터 끝까지 한 번 실행**합니다. 기존 0001 고객 접수 SQL이 먼저 적용되어 있어야 합니다. 이전 주민번호 SQL 0003을 적용하지 않은 환경에서도 사용할 수 있도록 구성합니다.
2. v2.15 전체 파일을 Cloudflare Pages에 배포합니다. `customer.html`, 고객용·담당자용 `assets`, `functions`와 새 공유 암호화 모듈도 함께 포함합니다. `index.html`만 바꾸면 휴대폰 화면과 저장 API는 갱신되지 않습니다.
3. 담당자 화면과 휴대폰 링크를 새로 열어 테스트합니다. 별도 카카오 키나 새 암호화 키를 추가할 필요는 없습니다. 기존 문자 인증용 서버 설정을 사용합니다.

새 휴대폰 화면의 주민번호 단계는 상사의 이전 `rrn_enabled` 설정 때문에 숨기지 않습니다. 새 SQL이 없으면 완료로 처리하지 않고 DB 적용 안내를 표시합니다. 주소 검색의 팝업이 차단되면 허용 후 다시 누르거나 직접 입력합니다.

## 저장과 웹페이지 반영

- 인증된 전화번호와 고객 입력을 함께 저장하고, 주민번호는 기존 수동 입력과 호환되는 암호문으로 보관합니다. 서명은 이미지 URL이나 SVG 대신 제한된 손글씨 좌표로 저장합니다. 서명 시각은 서버에서 기록합니다.
- 신규 고객이면 기존 고객 저장 공간에도 한 번에 등록합니다. 이미 저장된 고객 기록은 휴대폰 제출만으로 무조건 덮어쓰지 않습니다. 제출 원본은 별도 접수함에 남습니다.
- 담당자가 판매 진행을 열어 두었다면 새 제출을 확인해 입력칸을 자동으로 채웁니다. 담당자가 편집 중이면 현재 내용을 유지하고 새 입력 도착을 알립니다. 이 경우 **입력정보 불러오기**로 확인한 뒤 반영할 수 있습니다.
- 화면을 다시 열었을 때도 서버에 보관한 주민번호와 제출 서명을 확인할 수 있습니다. 서명은 고객이 제출한 원래 내용의 서명으로 표시하며, 이후 수정한 문서를 새로 서명한 것으로 처리하지 않습니다.
- 전송 중 연결이 끊기면 같은 제출 내용으로 결과를 다시 확인합니다. 서버 저장 성공 전에는 접수 완료로 표시하지 않습니다. 이미 제출한 링크로 값을 바꾸지는 않습니다.

접수함의 30일 조회·정리 정책은 유지합니다. 고객관리로 반영된 기록은 접수함 정리와 별개입니다. 암호화 키를 바꾸면 기존 번호 복호화에 영향을 주므로 기존 서버 키를 유지합니다.

## 확인할 항목

휴대폰에서 단계별 이전·다음, 주민번호 입력, 주소 새 창, 문자 인증, 계좌 건너뛰기, 서명 지우기·다시 쓰기, 최종 제출을 확인합니다. 담당자 화면에서는 자동 입력·편집 중 보호·주민번호 전체 표시·제출 서명 미리보기를 확인합니다. 개발 테스트는 가상 번호와 가짜 문자 응답, 격리 DB를 사용합니다.
