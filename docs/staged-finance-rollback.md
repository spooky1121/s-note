# 금융 입력 실패 원복의 회사 범위 보강

`zc182SubmitFinance`의 실패 원복용 백업이 공용 localStorage 본문을 읽는 것을 확인했다. 다른 회사 탭이 캐시를 교체한 뒤 차량 저장이 실패하면, 그 다른 본문을 현재 회사의 금융 snapshot으로 재채택할 수 있었다.

원복 백업은 인증된 현재 회사 ledger bridge가 반환한 원래 wire 배열을 그대로 직렬화한다. 정규화된 계산 배열을 백업에 사용하지 않으므로 기존 단위 표기와 부가 metadata도 보존한다. 확인창 대기 후 저장 시작 및 예외 원복 때 원래 회사·권한 context, client, readiness와 현재 ledger 쓰기 범위를 다시 확인한다. 권한 context가 바뀌면 이전 작업은 원복이나 안내를 새 계정에 전달하지 않는다.

실제 폼 제출·차량 저장 실패를 주입하는 두 탭 가상 브라우저 시험에서 다음을 확인했다.

- 1440/390px에서 A의 인증된 원장과 B 탭의 공용 캐시를 따로 유지한다.
- 차량 저장이 실패하면 원래 A의 혼합 단위 원장과 metadata가 정확히 복원된다.
- B가 공용 키를 다시 교체해도 후속 금융 CAS에는 A의 원래 본문만 들어간다.
- 실패 도중 회사가 바뀌면 이전 원장 원복을 새 scope에 캡처하지 않는다.

기존 금융 복구 30건과 복구 통합 17건, inline JavaScript 구문 검증도 통과했다. 모든 시험은 가상 데이터이며 운영 DB·설정·장부는 변경하지 않았다. 선재고 원장의 같은 종류의 공유 캐시 사용은 별도의 다음 검토 커밋에서 보완한다.
