# 고객 삭제 후 입력 링크 재발송

고객관리에서 고객을 휴지통으로 옮기면 기존 입력 링크를 취소하고 고객정보를 보관한다. 기존 차량 권한 검사에는 이 고객 삭제 상태도 포함되어 있어, 정상 재고에서도 새 고객에게 입력 링크를 보내지 못했다. 횟수 제한이나 발신번호 차이로 발생한 오류가 아니다.

## 변경

- 입력 요청 전용 차량 검사는 기존 상사·담당자·재고 상태·공유 권한을 유지하면서 새 고객 접수를 허용한다. 일반 고객 저장과 휴지통 보호는 변경하지 않는다.
- 각 요청에 고객의 저장 세대와 삭제 경계를 기록한다. 이전 고객의 요청·전화번호·제출정보는 현재 요청 목록에 다시 나타나지 않는다.
- 새 링크 발급만으로 고객을 만들거나 복원하지 않는다. 고객이 인증·서명·제출을 완료한 경우에만 새 제출 내용으로 고객을 생성한다. 이전 고객의 개인정보·서명·휴지통 기록은 합치지 않는다.
- 판매창은 불러온 요청이 서버 고객의 원본 요청과 정확히 일치할 때만 새 저장 세대를 수용한다. 계정·상사·차량·입력값·화면이 바뀐 경우 늦게 도착한 응답을 버린다.
- 기존 발신번호, 인증·동의, 명시적 발송, 재시도 및 발송 제한은 유지한다. 자동으로 문자를 다시 보내지 않는다.

## 검증 범위

신규 회귀 테스트는 가상 계정·차량·고객만 사용한다. 삭제 전 링크와 개인정보 숨김, 새 요청과 제출, 기존 고객 복원, 오래된 입력창 저장 방어, 공유차량 및 상사·담당자 권한을 검증한다. 브라우저 테스트는 실제 앱 코드와 API를 사용하며 외부 문자 발송은 모의 처리한다.

운영 확인에서는 DB 함수 정의·권한·스키마 및 비식별 집계만 확인한다. 운영 고객에게 테스트 문자를 보내거나 고객정보를 복원·수정하지 않는다. 실제 통신사 수신과 고객 휴대전화 입력 완료는 이 자동 시험에서 확인하지 않는다.

마이그레이션: `supabase/migrations/20261123081303_customer_intake_after_customer_trash.sql`

## 검증 결과

- `tests/customer-intake-after-trash.sql.cjs`: 실제 PostgreSQL 엔진(PGlite) 14개 그룹 통과. 운영 DB와 변경 전 대상 함수 7개의 정의 해시가 일치한다. 기존 휴지통·일반 저장·트리거·권한을 유지하고 마이그레이션 재실행도 검증했다.
- `tests/intake-customer-version.browser.cjs`: 실제 클라이언트·서버 버전 확인 훅·저장 래퍼로 21개 브라우저 사례 통과.
- 기존 고객 입력·식별번호·계약 서명 단위 테스트, 실제 Pages 런타임 API 6개 사례, 휴지통 DB 74개 사례, 인수증 SQL 9개 그룹, 공유 계약 SQL 18개 그룹 및 본인 차량 권한 복구·여러 계정 브라우저 회귀 검증 통과.
- 별도 실제 클라이언트/API 모의 시험에서 명시적 재발송·취소·세션 갱신 등 7개 사례 통과. 실제 문자 발송은 0건이다.
- 기존 `customer-identity.browser.cjs` 전체 시나리오는 이번 변경 전 main과 변경 후 모두 `workspace-order` 시험 설정 오류 안내창이 출력 버튼을 가려 중단됐다. 새 저장 버전 경로는 위 전용 테스트로 검증했다.
- 다중 PostgreSQL 연결을 이용한 실제 동시 실행과 통신사 수신은 미검증이다. 삭제·복원·제출 순서 및 잠금 순서는 가상 데이터와 독립 코드 검토로 확인했다.
