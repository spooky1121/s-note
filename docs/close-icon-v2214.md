# v2.214 닫기 아이콘 실패 복구

기존 닫기 아이콘은 각 버튼의 이미지가 `assets/close-circle.svg`를 별도로 읽는 방식이었다. 해당 요청이 실패하면 이미지의 `complete`가 true여도 `naturalWidth`가 0일 수 있는데, 같은 src라는 이유로 refresh가 그 실패한 이미지를 계속 유지하는 경로가 있었다.

같은 32px SVG 원본을 data URI로 코드에 내장한다. 빨간 원·흰색 X, 화면상 그림 24px·버튼 30px, 기존 위치·hover·포커스 표시를 유지하면서 외부 아이콘 파일 요청을 제거한다. 일반 SVG로 DOM을 바꾸지 않아 프로필의 SVG 16px 규칙이나 공통 SVG 숨김 규칙에도 영향을 받지 않는다.

이미지 표시가 실패하면 같은 크기의 span과 CSS 원·교차선으로 즉시 대체한다. CSS 대체 표시는 글꼴의 X 문자를 그리는 방식이 아니다. 같은 src의 실패한 이미지도 refresh 시 복구하고, 하위 이미지의 src·class 변경이나 버튼 내용 재생성도 관찰해 보정한다. 복제하거나 옮긴 이미지에도 오류 처리기를 연결하며 WeakMap으로 중복 연결과 오래된 버튼 참조를 피한다.

버튼 자체를 교체하지 않으므로 onclick·이벤트 리스너·폼 연결·disabled·hidden·닫기 전 변경 내용 확인은 유지한다. 그림은 보조 표시로만 취급하고 기존 접근성 이름을 보존한다. 단순 X만 있던 무명 버튼에는 ‘닫기’ 이름을 제공한다. 확인 버튼만 있는 메시지의 숨겨진 닫기는 계속 숨긴다. 계산기의 곱하기·인쇄·취소 버튼은 대상에 포함하지 않는다.

메인·월정산·소득정산·운영자·계정 찾기·주소 검색의 공통 JS/CSS 주소를 같은 새 버전으로 갱신한다. 기존 SVG 파일은 이전 HTML/JS 캐시와의 호환을 위해 유지한다. CSP나 운영 서비스 설정을 변경하지 않으며 현행 여섯 페이지의 img-src data: 허용을 확인했다. 데이터 이미지까지 허용하지 않는 조건에서도 CSS 대체 표시를 검증한다.

검증은 가상 페이지·계정·차량·서류와 차단된 외부 이미지 응답을 사용한다. 실제 운영 고객 데이터·DB·인증·문자·Cloudflare 설정에는 변경이 없다. 브라우저는 Chromium을 사용하며 실물 모바일 기기는 별도로 검증하지 않는다.

최종 가상 브라우저 검증에서 원본의 503 실패 후 naturalWidth=0 유지, 내장 이미지의 정상 표시, 이미지 전체 차단 조건의 CSS 대체 표시, 실제 앱 1440/390px의 손상 복구·복제 이미지 오류·반복 열기/닫기·동적 버튼 핸들러·확인 전용 닫기 숨김·인쇄 및 곱하기 버튼 유지의 5개 그룹을 통과했다. 기존 팝업 이동·리스너·폼·취소/확인 동작 단위 테스트 5개도 통과했다.

기존 닫기 전체 회귀는 1440px와 390px에서 각각 14종을 통과했다. 정상 내장 그림의 기존 빨강/흰색 픽셀, 크기·좌표·hover·뷰포트 내부 배치, 실제 닫기·변경 내용 확인·인쇄 제외 assertions를 유지했다. 기존 테스트의 src 기대는 내장 URI로 바꾸었고 모바일에서는 현재 UI에 맞게 사진/기본정보 탭을 먼저 선택하도록 준비 단계만 보완했다. 해당 모바일 탭 코드는 기준 main과 동일하여 제품 수정은 하지 않았다.
