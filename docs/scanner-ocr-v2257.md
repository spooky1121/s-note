# 스캔 문서 방향·종류 분석 · v2.257

기준 main: `583afaa638b173fe7fb7f17e0f3be2abaae57ceb`. 기존 스캐너 저장·권한·장치 연결 방식과 원본은 유지한다. 운영 DB, Google/Cloudflare 비밀값 및 Windows 연결 프로그램은 변경하지 않는다.

## 동작

- 저장 ACK를 확인한 새 문서를 Google Cloud Vision `DOCUMENT_TEXT_DETECTION`으로 자동 분석한다. 이번 로그인 모음은 보이는 문서부터 분석하며 과거 이력 전체를 자동 전송하지 않는다. 과거 문서는 선택 후 `문서 분석`으로 요청할 수 있다.
- Google 단어 꼭짓점의 읽기 방향을 종합해 0/90/180/270도 보정값을 구한다. 가로 문서를 무조건 세로로 만들지 않으며, 보정된 실제 비율을 유지한다.
- 보정된 상단 40%에서 `자동차등록증`을 찾으면 **자동차 등록증**, 그렇지 않고 `자동차성능` 또는 `상태점검기록부`가 있으면 **자동차 성능지 1장**이다. 둘 다 없으면 문서 전체에서 `상태 고지자` 또는 `상태 점검자`를 찾아 **자동차 성능지 2장**, 모두 없으면 **미분류**로 표시한다. 공백·문장부호를 정리한 뒤 판정한다.
- 종류는 오른쪽 썸네일 아래에 표시한다. 큰 미리보기와 파생 썸네일만 회전하며 저장 원본·다운로드 바이트·업로드 요청 ID는 바꾸지 않는다. 기존 수동 회전·확대·맞춤도 유지한다.
- 방향 근거가 부족하면 강제로 회전하지 않고 `방향 확인 필요`를 표시한다. 브라우저의 자동 EXIF 보정과 중복될 수 있는 회전·반전 메타데이터도 수동 확인으로 처리한다. 저화질·가림·특이한 양식의 OCR 정확도는 실제 문서에서 확인해야 한다.
- `분석 중`, `분석 실패`, 성공한 `미분류`를 구분한다. 실패는 자동 반복하지 않으며 `다시 분석`으로 재시도한다. 성공 후에는 `분석 완료`로 표시한다.

## 요청·보관 범위

- `/api/scanner-analysis`는 같은 출처의 인증된 POST `{companyId,id,revision}`만 받는다. 서버가 현재 경리/관리자 권한·상사·세션과 저장된 문서를 확인한다. 브라우저가 보낸 이미지, 임의 URL, Storage 경로는 받지 않는다.
- 비공개 저장소의 실제 바이트·크기·MIME·SHA를 검증하고 분석 및 캐시 응답 직전에도 접근 권한과 문서의 활성 상태를 다시 확인한다. Google 키는 기존 서버 환경변수 `GOOGLE_VISION_API_KEY`를 사용한다.
- 응답은 문서 종류·한국어 명칭·회전각·가로세로 분류·확인 필요 여부의 다섯 필드뿐이다. OCR 원문·개인정보·비밀키·파일 경로·제공자 오류 본문은 브라우저나 로그에 남기지 않는다.
- 같은 파일의 진행 중 요청은 공유하고 서버 동시 분석은 2건으로 제한한다. 64건/15분의 서버 인스턴스별 임시 캐시와 할당량 오류 후 30초 대기를 적용한다. 영구 캐시나 전체 배포 인스턴스 간 과금 중복 방지를 보장하지 않는다.
- 브라우저 분석 큐는 직렬이며 최대 200건의 메타데이터만 메모리에 보관한다. 같은 로그인에서 메뉴를 오갈 때 성공 결과를 재사용한다. sessionStorage에는 기존처럼 문서 ID만 저장하며 분석 결과나 이미지·원문은 저장하지 않는다.
- 로그아웃/상사 전환·삭제·메뉴 이탈 이후 늦게 온 결과는 화면을 복원하지 못한다. 실제 로그아웃 경로의 선행 UI 정리에도 로그인 ID 모음이 즉시 지워지도록 명시적인 인증 초기화 이유를 전달한다. 스캐너 모듈을 아직 불러오지 않은 로그아웃도 전용 ID 저장 영역을 지운다.
- 기존 운영자 Vision 관측에는 요청 단계·소요 시간·바이트 수 등 정해진 메타데이터만 기록한다. 캐시를 이용한 API 응답도 관측될 수 있으므로 관측 건수는 Google 청구 건수와 같지 않다.

## 검증

실제 고객·운영 DB·실제 Google API 호출 없이 생성 이미지, 합성 계정과 Google 응답을 사용했다.

- 분류기 13개: 네 방향, 실제 가로 문서, 제목 우선순위·본문 오탐 방지, 공백·문장부호, 불확실 방향, 잘못된 좌표·입력 상한.
- 분석 클라이언트 13개: 공유 Promise, 직렬 처리, 명시 재시도, 잘못된 응답, 세션·삭제·늦은 응답, 메모리 상한.
- 격리 PostgreSQL 기반 신규 API 13개와 기존 스캐너 API 12개: 실제 권한 RPC, 상사 분리, 캐시/공유 응답 재검증, 위조/변조·삭제, 제공자 오류·응답 상한, EXIF, 동시 처리 제한.
- 기존 스캐너 클라이언트·저장 큐·장치·자동 연결·로그인 모음·inline 미리보기 단위 76개와 핵심 업무/OCR/보안 회귀 438개 통과.
- 신규 브라우저 15개: 1366/1024/430/390/360px, 실제 썸네일 픽셀을 이용한 네 방향 검증, 원본 SHA 보존, 명칭, 실패/재시도, 과거 문서 명시 분석, 로그아웃·권한 거부·삭제 중 분석 응답 차단.
- 기존 브라우저 스캐너 작업 화면 16개·보관함 20개·장치 연결 19개도 동일한 최종 제품 소스에서 모두 통과했다. 총 브라우저 검증 70개이며 생성 이미지·가상 계정만 사용했다.
- 최신 Pages 함수 빌드와 실제 workerd에서 신규 OCR 경로 및 기존 스캐너 경로를 실행했다. 네이티브 바이트/base64, 실제 라우팅·미들웨어, 캐시의 권한 재확인과 제공자 오류 재시도를 가상 외부 응답으로 검증했다.

실제 Google 운영 키의 사용 가능 여부와 실제 스캔 문서 판독 정확도, 사용자 PC의 실물 스캐너는 이번 자동화 시험에서 확인하지 않았다. 기존 저장·다운로드·인쇄 양식 및 상사 로고·도장은 유지한다.

공식 근거: [Google Vision OCR](https://docs.cloud.google.com/vision/docs/ocr), [단어 꼭짓점의 자연 읽기 순서](https://docs.cloud.google.com/vision/docs/reference/rpc/google.cloud.vision.v1#word). 테스트 증적은 작업 환경 `/workspace/work/scanner-ocr-v2257/`에 보관한다.
