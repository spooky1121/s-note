# 경리 업무 화면 보완 · v2.246

기준 main은 v2.245 `6d17e6dfeaade7509f0039d9bf8150cad5042cc6`이다. 기존 재고금융사 통합은 유지한다.

## 화면과 편집

- 차량서류의 문서 선택은 기존 상태 메뉴와 같은 공통 드롭다운을 사용한다. 메뉴는 테이블 밖에 표시하여 행·열 크기를 바꾸지 않는다.
- 대시보드는 현재 총매입 옆에 총 매입대수를 표시한다. 현재 등록된 상사 전체 차량의 대수이며 삭제 이력을 포함한 누적 통계가 아니다. 금융사별 한도·사용액을 각각 표시하되 기존 금융 원장과 미상환·중복 제외 규칙으로 계산한 전체 합계와 대조한다. 미확인 한도는 0원으로 표시하지 않는다.
- 정보의 계좌·전화번호 등록은 목록에 빈 행을 추가하고 한 번만 fade-in한다. 빈 신규 행은 서버에 쓰지 않으며 이동 시 취소한다. 유효한 편집은 순서대로 자동 저장한다. 부분 입력·충돌·불확정 응답은 초안을 보존하고 확인·재시도 절차를 제공한다. 한글 조합과 활성 입력 위치를 유지한다.
- 직원 업무용 이름·연락처·메모는 회사와 직원 UUID를 기준으로 별도 저장한다. 로그인·인증 번호, 역할, 계정 상태는 이 편집으로 바뀌지 않는다. 두 직원이 최초 업무 연락처를 동시에 생성한 경우에도 초안을 보존한다.
- 운영정산의 외부 담당 딜러 필터를 숨긴다. 내부 입금표·금액 계산·A4 출력은 유지한다. 행 추가는 `+`, 행 삭제는 작은 빨간 `−`로 표시하며 접근성 이름을 유지한다.
- ‘딜러소득’ 표시명을 ‘직원 사업소득’으로 변경한다. 신고 자료가 없으면 신고 여부나 신고액을 추정하지 않는다.
- 조회는 자동차 원부조회와 사업자 등록조회 두 영역의 기본 화면이다. 외부 조회 서비스 연결은 추가하지 않았다. 모바일에서는 세로로 배치한다.

## 운영서류 사진

사업자등록증, 자동차관리사업 등록증, 주주명부, 법인 통장사본, 대표자 신분증을 종류별 한 장씩 등록·교체·삭제한다. 기존 가입 증빙·상사 로고·도장·차량 서류는 재사용하거나 이전하지 않는다. 상시 다시 불러오기 버튼을 없애고 실패한 요청에만 재시도를 제공한다.

별도 비공개 `snote-office-documents` 버킷과 `snote_office_private` 저장소를 사용한다. 현재 상사의 활성 경리·관리자와 유효한 세션을 매 요청 확인한다. JPG·PNG·WebP, 5MiB 이하, 최대 4천만 화소이며 서버가 실제 파일 구조·해시를 검증한다. 브라우저의 직접 버킷 접근과 공개 URL은 허용하지 않는다.

변경은 불변 객체와 슬롯 revision으로 처리한다. 같은 요청 재시도는 기존 결과를 확인하고, 다른 직원이 수정한 뒤에는 과거 응답으로 되돌리지 않는다. 물리 파일 삭제는 Storage API를 사용하며 실패 시 안전하게 다시 정리한다. 인증·상사·화면 전환 뒤 늦게 도착한 결과는 반영하지 않는다. 사진 바이트는 미리보기를 선택할 때 읽고 임시 URL을 해제한다.

## 인증 전화번호

기존 서버 OTP 소비·검증 기록과 현재 유효한 복구 바인딩을 재사용하여 공식 회원 연락처를 동기화한다. 가입 입력 문자열·사용자 metadata·업무용 연락처는 인증 증거로 취급하지 않는다. 기존 Auth·복구·인증 함수 본문과 권한은 유지한다. 이전 번호·무효 바인딩·잠금·중복·복구 진행 중인 번호는 우회하지 않는다. 현재 유효한 기존 증거만 좁게 재확인하며 잠금이나 충돌로 처리할 수 없는 항목은 건너뛴다.

## 검증 범위

가상 계정·파일·데이터만 사용한다. 새 SQL은 격리 PostgreSQL에서 회사·역할·세션·CAS·원본 보존을 확인한다. API는 실제 라우터와 격리 DB·가짜 Storage로 이미지 검증, 응답 유실, 교체·삭제 경쟁, 권한 회수와 정리 실패를 확인한다. 프런트엔드는 PC·모바일에서 입력·빈 행 취소·사진·드롭다운·대시보드·운영정산을 검증한다.

운영 고객 자료로 CRUD하거나 실제 SMS를 보내는 시험은 하지 않는다. 단일 연결 SQL 시험으로 실제 다중 세션 잠금 경합을 재현하지는 못했다. 운영 적용 시 원래 함수 해시·권한과 신규 스키마·버킷·실행 권한을 다시 확인한다. Supabase의 기존 설정, NAS·백업 연결, 업무 인쇄 양식·상사 로고·도장·서비스 서체는 변경하지 않는다.

격리 SQL 44개, 운영서류 API·기존 보안/가입/관측 회귀 57개와 실제 Pages/workerd 실행이 통과했다. 정보 편집·문서·대시보드·금융·운영정산 관련 단위 검증도 통과했다. PC 1440px·모바일 390px 통합 화면 검증 18개를 수행했다.

운영 적용 후 기존 인증·정보·세션 함수 9개의 본문 해시·실행 권한이 그대로임을 확인했다. 새 운영서류 스키마·비공개 버킷·제약과 직원 연락처·전화번호 트리거의 권한 검증도 통과했다. 새 경고·오류는 없으며, 운영서류 비공개 테이블 3개에는 의도한 기본 거부 때문에 [RLS 정책 없음 정보 알림](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)이 표시된다. 직접 테이블 권한과 클라이언트 정책을 주지 않고 검증된 함수만 허용하는 구조다.
