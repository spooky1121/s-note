# 딜러 간 차량 공유

차량 상세의 저장 디스켓 바로 옆 공유 아이콘에서 가입된 딜러의 이메일을 입력한다. 이메일이 확인된 활성 딜러·관리자 계정에 차량 단위로 공유하며 다른 상사 딜러도 지정할 수 있다. 같은 이메일 재등록은 공유를 중복 생성하지 않는다. 원 소유자와 소유 상사 관리자는 공유 대상 목록에서 해제할 수 있다.

받은 딜러는 매입관리 차량 목록 상단의 ‘공유받은 차량’ 아이콘을 열어 차량을 선택한다. 차명·차량번호·제조사·연식·차대번호·주행거리·색상·매입일·매입가·판매예정가를 함께 수정하고 저장할 수 있다. 사진·자동차등록증·성능기록부는 조회할 수 있다. 공유 사진 업로드·삭제, 차량 판매/삭제/재공유, 고객·주민번호·서명·소득정산 자료 권한은 부여하지 않는다.

공유 창을 열 때 서버 최신 정보를 조회한다. 다른 딜러가 먼저 저장한 경우 원 소유 장부 revision CAS로 충돌을 반환해 현재 입력을 보존한다. ‘최신 정보 다시 불러오기’는 확인 후 현재 입력을 서버값으로 바꾼다. 원 소유자의 기존 화면도 동일 장부 revision이 증가해 오래된 전체 장부를 덮어쓸 수 없다. 공유 자료는 브라우저 localStorage/IndexedDB의 자기 장부에 복사하지 않는다. 로그아웃/상사/사용자 변경 시 공유 창과 임시 이미지 URL을 비운다.

## DB

- 마이그레이션: `supabase/migrations/20261104153021_vehicle_scoped_dealer_sharing.sql`.
- `snote_private.vehicle_shares`: RLS 활성화, 브라우저 직접 테이블 권한 없음, 차량·소유자·수신자 복합 키 및 수신자 조회 인덱스.
- `public.snote_vehicle_share`: authenticated 전용 SECURITY INVOKER 진입점. 실제 제한된 교차 소유자 접근은 비노출 스키마의 SECURITY DEFINER 함수에서 auth.uid/활성 회원/소유권/정확한 차량 공유를 검증한다. 함수 search_path는 비우고 모든 테이블 이름을 명시한다. anon/PUBLIC 실행권한을 회수한다.
- 차량 조회는 명시한 키만 반환한다. 수정도 고정 허용 필드만 받아 해당 차량 JSON만 교체하고 원 소유자와 다른 차량·민감한 기존 필드는 그대로 둔다. 금액은 화면 정수 원 단위이며 기존 KRW/레거시 만원 저장 형식에 맞춰 왕복한다.
- 기존 datasets/customers/media RLS를 넓히지 않는다. private Storage 버킷에는 활성 공유와 정확한 차량의 사진/서류 메타데이터에 일치하는 경로만 SELECT를 추가한다. 공유 해제·비활성 계정·차량 삭제 이후 새 조회는 차단한다. 이미 다운로드한 자료를 원격에서 회수하지는 않는다.
- 생성/해제/수정은 기존 zc_audit에 기록한다. 사용자·상사·인증키 생성/교체 없음. 이메일 알림이나 문자 발송 없음.

로컬 PostgreSQL 호환 PGlite 27개: 다른 상사 공유, 이메일 중복, 다른 차량 차단, 고객/정산 제외, 제한 필드 수정·CAS 충돌, 형제 차량 보존, Storage 경로, 해제/비활성/익명 차단. Chromium1440/390/320px: 버튼 위치, 이메일 공유/해제, 공유받은 목록, 원 단위 콤마/저장 변환, 충돌/저장 응답 대기 중 추가 입력 보존, 계정 변경 정리, 가로 넘침 없음.

운영 Supabase에 적용 후 RLS/권한/invoker/Storage 정책·공유0건·미인증 요청 거부를 재조회했다. 운영 고객에게 임의 공유를 생성하지 않았다. 적용 전후 advisor는 이번 API의 새 security warning 없이 기존 경고와 구분했다(직접 접근을 막은 private 표의 정책 없음 INFO는 의도한 기본 거부). 실제 운영 계정 간 공유·iPhone/Safari 직접 검증은 합성 검증과 구분한다.

Supabase MCP 문서로 Data API grant/RLS/함수 접근 지침을 조회했다. changelog.md는 실행 환경 네트워크에서403으로 접근되지 않았다.
