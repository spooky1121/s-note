# 엔카 조회 진단·중복 실행 점검

최신 main v2.183에서 시작한 단계별 개선의 2단계 변경이다. 운영 환경이나 제공처 제한·검색 방식은 바꾸지 않는다.

- API가 실제로 확인한 매물 없음은 HTTP 200 + `status: not_found` + `code: NOT_FOUND`로만 처리한다. 503이나 모순된 응답은 오류로 표시하며 저장 링크를 지우지 않는다. 예외로 던져진 `NOT_FOUND`도 매물 없음으로 확정하지 않는다.
- 각 API 요청은 서버가 만든 요청 ID, 고정된 실행 단계, 소요 시간만 오류 로그에 남긴다. 응답의 `X-Snote-Request-Id`, `X-Snote-Lookup-Stage`, `X-Snote-Duration-Ms` 헤더로 같은 값을 확인할 수 있다. 차량번호·계정 식별자·토큰·원본 주소·예외 내용은 로그에 넣지 않는다. 브라우저는 ID·단계·숫자를 검증한 뒤 오류 화면에 표시한다.
- 같은 실행 인스턴스에서 동시에 진행되는 조회만 공유한다. 각 요청이 직접 Auth와 활성 상사 회원을 확인한 다음, 상사·사용자·역할·요청·환경 자격값을 포함한 메모리 해시로 묶는다. 차량이나 가격 결과는 완료 즉시 제거하며 재시도와 직접 광고 주소 열기는 유지한다.
- 한 요청 취소는 다른 대기 요청을 취소하지 않는다. 모두 취소하면 해당 조회를 중단한다. 공유 작업은 독립된 기한을 가지며 원래 요청의 `waitUntil`로 수명을 유지한다. 브라우저·소켓이나 응답 스트림을 다른 요청으로 전달하지 않고 완성된 결과만 전달한다. 공유 대기 항목 수에 도달하면 별도로 실행하므로 새 요청 한도를 만들지 않는다.

## 검증 범위

Auth·차량·광고 응답은 모두 가상 데이터다. API와 pending 모델에서 동시 요청, 매번 권한 확인, 회사·계정·환경 분리, 부분/전체 취소, 시간 초과 후 재시도, 민감정보 없는 진단을 검사했다. 실제 컴파일된 Pages/Workers와 로컬 GLOAR DOM/CDP, 합성 엔카 HTML 응답에서도 동시에 두 번 인증하고 외부 조회는 한 번만 실행되는 것을 확인했다. 실제 외부 통신은 0건이다.

PC·모바일 브라우저에서 오류 표시, 저장된 광고의 직접 열기와 재조회 방지, 지연 응답 보호도 회귀 검증했다. 기존 테스트의 인라인 오류문구 가정은 현재 공통 알림 팝업으로, 모바일 목록형 가정은 현재 기본 카드형으로 맞췄다.

## 확인하지 않은 항목

운영 계정·실제 광고 제공처로 조회하지 않았으므로 실서비스 503의 발생 주체·차단 여부·빈도는 판단하지 않았다. 공유는 실행 인스턴스의 메모리 범위이며 서로 다른 Cloudflare 인스턴스의 요청까지 합치지 않는다. 운영 Cloudflare/Supabase 설정, 장부·차량 데이터, 제공처 접근 정책은 변경하지 않았다.

검증 명령은 `node --test --test-isolation=none`의 Encar API/pending/client/provider 9개 파일, `tests/encar-id.browser.cjs`, `tests/encar-id.workerd.cjs <Pages 빌드>`, `tests/encar-ad-price.workerd.cjs`다. 테스트 결과와 합성 브라우저 증적은 `/workspace/work/audit-encar-v2184/`에 보관한다.
