# 딜러별 입금계좌 · v2.158

설정 첫 화면의 독립된 `내 입금계좌` 카드에서 차대금 계좌·이전비 계좌를 입력하고 디스켓 아이콘으로 저장합니다. 프로필을 펼칠 필요 없이 바로 입력할 수 있으며 프로필 드로어에서도 같은 편집기를 사용합니다. 계좌마다 은행명, 계좌번호, 예금주를 입력합니다. 두 계좌는 독립적인 선택 항목이며, 한 계좌의 세 입력칸을 모두 비워 저장하면 그 계좌를 삭제합니다. 일부만 입력한 계좌는 저장하지 않습니다.

견적서 버튼은 서버에 저장한 계좌를 먼저 조회합니다. 저장된 계좌가 하나도 없으면 `입금 계좌 먼저 입력 하셔야합니다` 안내를 표시하고, 확인 후 설정의 계좌 입력 카드로 이동해 첫 미등록 계좌의 입력칸에 초점을 맞춥니다. 입력 중인 값만으로 견적서를 열지 않으며, 차대금 또는 이전비 계좌 중 하나 이상을 완전히 저장하면 견적서를 열 수 있습니다. 조회 실패는 미등록으로 판단하지 않습니다. 조회 중 차량·계정·같은 차량의 열기 세션이 바뀌면 이전 결과를 적용하지 않고, 기존 차량의 미저장 내용에 대한 이동 확인도 유지합니다.

설정 카드의 저장하지 않은 입력은 같은 설정 화면의 재렌더링에 유지됩니다. 다른 메뉴로 이동할 때 확인하고, 다른 계정으로 바뀌면 비웁니다. 프로필 펼치기/접기와 독립된 카드 상태를 분리해 프로필을 접어도 계좌 입력이 사라지지 않습니다. 이 변경은 v2.157의 비공개 DB와 자기 계좌만 접근하는 RPC를 그대로 사용하며 추가 마이그레이션이 없습니다.

견적서의 기존 고정 계좌를 제거했습니다. 견적서와 판매 계약서는 현재 로그인한 딜러가 실제 저장한 계좌만 표시하고, 미등록 항목은 숨깁니다. 두 항목 모두 없으면 입금계좌 영역 전체가 나타나지 않습니다. 매수 계약서에는 딜러의 입금계좌를 넣지 않습니다. 고객의 이전비 환급계좌와 선재고 계좌는 별도 자료로 유지하며 대체 계좌로 사용하지 않습니다.

`snote_private.member_payment_accounts`에 `(company_id,user_id)` 단위로 보관합니다. 현재 활성 딜러·관리자는 자기 계좌만 읽고 저장할 수 있으며, 관리자도 다른 딜러의 계좌를 조회하는 API는 없습니다. 경리·익명·비활성·정지 계정은 접근하지 못합니다. RLS와 직접 테이블 권한 차단을 유지하고, 현재 회원행 잠금과 리비전 비교로 이전 화면의 저장을 거절합니다. 감사 기록에는 사용자·작업만 기록하며 계좌 내용은 포함하지 않습니다.

공개 함수 `snote_payment_accounts_read(p_company)`와 `snote_payment_accounts_save(p_company,p_expected_revision,p_accounts)`는 인증된 호출자의 ID를 사용합니다. `accounts`는 `vehicle`과 `transfer` 두 키만 포함하며 각 값은 `null` 또는 `{bank,number,holder}`입니다. 은행명 35자·예금주 60자·계좌번호 6~32자(숫자 최소 6개, 하이픈 허용)를 검사합니다. 번호를 숫자형이나 일반 고객정보 정리 함수에 통과시키지 않아 앞자리 0·13자리 계좌를 유지합니다. 브라우저 영구 저장소에는 보관하지 않습니다.

문서는 조회 전에 계좌를 비우고 현재 사용자·상사·클라이언트·세션·역할과 일치하는 응답만 적용합니다. 인쇄 직전에 다시 조회하며 조회 실패나 계정 변경 시 인쇄를 중단합니다. 저장하지 않은 입력은 문서에 반영하지 않고, 실패한 저장은 입력을 유지합니다. 계약서 두 A4 복사본에 동일한 저장 자료를 표시합니다.

DB 적용 파일은 `supabase/migrations/20261120070158_dealer_payment_accounts.sql`입니다. 기존 계좌를 추정하거나 고정 계좌를 새 계정에 자동 입력하지 않습니다. 로컬 검증은 `tests/payment-accounts-db.cjs`와 `tests/payment-accounts.browser.cjs`에서 합성 계정·합성 계좌·차단된 외부 요청으로 실행합니다. 실제 고객·계좌·문자나 로그인 정보는 검사 자료에 사용하지 않습니다. 실행 산출물은 `/workspace/work/dealer-payment-accounts-v2157`에 보관합니다.

검증은 로컬 PostgreSQL 권한·입력·충돌 검사 23건, PC/390px 실제 프로필·문서 동작, 320px 최대 길이 계좌의 견적서 1장과 계약서 2장 PDF를 포함합니다. 계좌가 없는 기존 문서도 1440/390/320px의 일반·긴 내용 A4 검사 12건을 통과했습니다. 기존 프로필의 연락처 인증·사진·비밀번호·계정 변경 처리도 유지됩니다. 운영 DB에서는 RLS, 직접 접근 차단, 익명 함수 접근 차단과 13자리·앞자리 0 보존을 확인했습니다. 보안 점검의 새 항목은 직접 테이블 접근을 막은 비공개 테이블의 정책 없음 정보이며, 새 경고는 없습니다.
