# v2.253 중복 호출·렌더링 점검

## 확인하고 수정한 문제

| 위치 | 재현된 동작 | 수정 |
|---|---|---|
| `assets/icon-sizing.js` | 추가·삭제 아이콘의 동일한 class를 매번 다시 기록하고, 자체 MutationObserver가 이를 받아 다음 프레임에 다시 처리했다. | class가 실제로 달라질 때만 기록한다. 아이콘·버튼·핸들러는 유지한다. |
| `assets/dealer-scheduler.js` | 차량 일정 자료를 아직 사용할 수 없을 때 저장한 `null`과 비교한 `undefined`가 항상 달라져 500ms마다 같은 달력과 일정 목록을 다시 만들었다. | 비교 전에 부재 값을 `null`로 통일한다. 실제 자료·상태·날짜·상사·브리지 변경에 따른 갱신은 유지한다. |
| `index.html`의 프로필 사진 로더 | 같은 상사·사용자·세션과 같은 사진을 동시에 요청하면 완료 캐시가 채워지기 전에 비공개 파일 다운로드가 두 번 시작됐다. DOM 이미지는 기존에도 하나였다. | 같은 context·client·사진 경로·revision의 진행 중 다운로드만 공유한다. 실패 시 제거해 재시도할 수 있다. 완료 직후 새 사진 정보가 도착하는 경계도 최신 revision으로 다시 확인한다. |

프로필의 요청별 본인 인증과 메타데이터 조회는 유지한다. 세션·상사 전환 시 진행 중 공유 상태를 초기화하며, 이전 응답의 화면 적용 차단과 Blob URL 회수를 유지한다. 비공개 Storage 요청의 사용자 Authorization과 기존 RLS 경로도 바꾸지 않는다. [Storage 공식 문서](https://supabase.com/docs/guides/storage/serving/downloads#private-buckets)를 대조했다.

## 중복으로 분류하지 않은 코드

운영 HTML 7개에서 정적 script/style 태그 317개를 검사했다. 각 문서 안에서 같은 자산 경로가 두 번 등록되거나 정적 DOM ID가 중복된 곳은 없었다. 자산 JS/CSS 241개에서도 내용이 완전히 같은 파일 복제는 없었다. 이는 의미가 비슷한 모든 함수가 같다는 뜻은 아니다.

- 금융사 목록의 복원은 메모리의 설정 정규화와 최신 딜러 금리 적용 단계다. 서버 중복 조회로 분류하지 않았다.
- 상사 기본 정보와 문서용 프로필은 이미 필수 조회·최초 사용 조회로 분리되어 있다.
- 보호된 동적 모듈 로더는 공유 Promise·브라우저 모듈 캐시·초기화 가드가 있다. 실제 이중 초기화가 확인되지 않은 경로를 제거하지 않았다.
- iframe마다 필요한 공통 코드, 인쇄용 복사본, 모달·툴팁·알림 배지와 공유 표시 등 의도한 레이어는 유지한다.

## 검증

가상 계정·차량·이미지와 지연·실패 응답으로 로컬 소스를 실행했다. 실제 고객 정보·운영 DB·Cloudflare 설정은 변경하지 않았다.

- 원본 자산을 가상 응답으로 제공한 통제 비교에서, 매입 목록의 700ms 무조작 측정 중 동일 class 쓰기 84회가 수정 후 0회가 됐다. 차량 상세의 추가·삭제·사진 추가 버튼에서도 매 프레임 반복 기록이 사라졌다.
- 차량 일정 자료 미준비 상태의 1200ms 측정에서 원본 달력의 childList 변경 16회·원본 노드 4개 교체를 재현했다. 수정 후 변경 0회·원본 노드 4개 유지이며, 실제 차량 매입일을 추가하면 정상 갱신한 뒤 다시 안정된다. `tests/ui-render-idempotence-v2253.browser.cjs`의 2개 브라우저 회귀로 보존했다.
- 지연 로딩, 로그인 후 dashboard→목록 이동, 연속 메뉴 이동, 팝업 재진입, 프로필 및 역할별 주요 화면의 61개 상태·2,123개 프레임을 검사했다. 의도치 않은 아이콘·이미지 누적, 표시 중인 중복 ID, 이전 로그인·업무 화면과의 동시 표시는 발견하지 못했다.
- `node tests/profile-avatar-download-dedup.test.cjs`: 동시 요청 1회 공유, 실패 재시도, 상사·client 교체, 새 revision, 이미지 바이트 검증, URL 회수, 완료 직후 메타데이터 변경의 9개 검증 통과.
- `node tests/dealer-vehicle-calendar.test.cjs`: 차량 일정 투영·중복 식별·매입/판매 구분 13개 통과.

### 과거 테스트의 미통과 항목

`tests/icon-sizing.browser.cjs` 전체 실행은 현재 텍스트와 함께 표시하는 엔카 아이콘에 과거의 `must be sized` 가정을 적용해 실패한다. 이 버튼은 추가·삭제 아이콘 처리 대상이 아니며, 수정 전 자산만 가상 응답으로 제공해도 같은 실패가 발생한다. 수정 전후 버튼의 class·좌표·SVG는 동일하다. 전체 검사를 통과로 계상하지 않았고 현재 월정산·소득정산 컨트롤은 별도로 확인했다.

`tests/customer-address-popup.cjs`의 정상 주소 선택·신뢰 메시지·상세주소·취소·Esc·모바일·팝업 차단 복구는 통과했다. 마지막 SDK 실패 사례는 테스트가 `about:blank`의 DOM 준비 전에 접근해 실패했으므로 전체 통과로 계상하지 않았다. 새 공통 아이콘의 주소검색 호환성은 신뢰할 수 있는 가상 opener·SDK로 별도 확인했다.

원래 로고·Pretendard 파일 해시는 동일하다. 업무 계산, 저장 형식, 계정 권한, 상사 로고·도장·서명 및 A4 문서 양식은 변경하지 않았다.

실제 저사양 기기·운영 계정 로그인·실물 프린터 시험은 포함하지 않았다. 운영 사이트 직접 접속은 실행 환경의 프록시 제한으로 미검증이며, 배포 확인은 GitHub 커밋과 S-NOTE Cloudflare Pages의 정확한 운영 빌드 결과를 기준으로 한다.
