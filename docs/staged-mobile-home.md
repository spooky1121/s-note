# 모바일 홈·매입 도구 개선 — 검토용

기준은 1·2단계를 통과한 통합 브랜치 `e809967`이다. 운영 자료·설정은 변경하지 않았으며 main 병합·배포는 하지 않는다.

## 업무를 먼저 보여 주는 홈

모바일에서는 실제 DOM과 화면 모두 ‘오늘 처리할 일 → 업무 바로가기 → KPI’ 순서로 배치했다. 데스크톱의 기존 KPI 우선 순서는 유지한다. 기존 90일 장기재고 판정은 변경하지 않았고, 명시적으로 `계약중`인 본인 차량만 판매 진행 업무로 보여 준다. 소유자·상사·로그인 확인 및 기존 금액 잠금이 먼저 충족되어야 한다.

경리의 시작 화면과 권한은 기존 `contractOffice`를 유지한다. 대시보드 접근을 새로 부여하지 않고 업무 화면 앞에 모바일용 카드만 배치했다. 기존 회사 차량·금융 조회 결과를 읽으며 새 HTTP 요청을 시작하지 않는다. 상사/역할이 바뀌거나 미확인 저장·충돌·대기 중 쓰기가 있으면 업무 건수를 0으로 단정하지 않고 ‘확인 중’으로 표시한다. 동일한 projection은 DOM을 교체하지 않는다.

서류 바로가기는 소유자와 차량 ID를 함께 확인한다. 기존 상세 창이 ID 하나만으로 다른 소유자의 행을 고를 수 있는 모호한 구형 ID라면 상세를 임의로 열지 않고 기존 상사 매입 목록으로 이동한다. 기존 전역 차량 ID나 저장 구조는 이번 변경에서 바꾸지 않는다.

미상환 금융은 기존 회사 집계와 인증된 금융 장부가 준비되고 같은 상사인 경우만 표시한다. 판매 차량의 잔여 원금도 포함하는 1단계 원본을 재사용한다. 현재 재고투자금에 판매 차량을 다시 포함하지 않는다.

## 서류 미등록의 근거

기존 서류 목록은 스냅샷이 없을 때 빈 로컬 배열을 사용할 수 있으므로, 그것만으로 미등록 업무를 계산하지 않는다. 경리의 서류 업무는 현재 회사의 인증된 미디어 스냅샷이 최신이며 전체 행의 수신을 입증한 경우에만 계산한다.

- 기존 회사 미디어 HTTP 요청에 **확인된 경리 역할에서만** `count: 'exact'` 옵션을 붙인다. 딜러·관리자의 백그라운드 요청에는 추가하지 않는다. 기존 SDK의 [공식 select 옵션](https://supabase.com/docs/reference/javascript/select)을 확인했으며 패키지 버전을 변경하지 않는다.
- 서버의 정확한 총수와 받은 행 수가 같고 모든 행이 현재 회사에 속할 때만 완료로 표시한다. 요청 limit보다 적게 왔다는 이유로 완료로 추정하지 않는다. 총수 누락, 서버 cap 1,000/3,000에 의한 부분 응답, 다른 회사 행, 만료되거나 새 조회가 진행 중인 스냅샷은 미확인이다.
- 이 메타데이터는 새 업무 판정에만 사용한다. 기존 목록의 서류 표시 규칙을 바꾸거나 추가 HTTP·운영 `max_rows` 변경을 하지 않는다.
- 저장소의 기존 `zc_media_read`는 `zc_is_member(company_id)`를 사용한다. `20261107041621_vehicle_share_acceptance.sql`의 제한 정책은 확인된 같은 상사 관리자·경리에게 기존 회사 전체 서류 읽기를 유지한다. 실제 정의를 로컬 PostgreSQL에 적용해 활동/퇴사 딜러의 등록증·성능기록부 세 종류를 모두 읽고, 타사·비활성 경리·익명은 차단함을 확인했다. 운영 정책·자료는 조회하거나 변경하지 않았다.

## 매입 도구와 화면 대비

원본 등록 버튼을 모바일에서 ‘+ 차량 등록’으로 표시하고 원래 OCR·보기·열 설정·정렬 노드를 보조 메뉴에 배치한다. 노드와 핸들러·숨김·비활성 권한은 유지하며 데스크톱에서는 기존 위치로 복원한다. 이동한 정렬 노드를 다시 찾도록 탐색을 보완해 중복 생성을 막는다. 초기 인증 또는 준비 전에는 도구 노드를 이동하지 않는다.

기존 공통 기본 버튼은 실제 계산색 `#4455ed`의 흰 글자 대비가 5.573:1로 이미 통과하여 재구현하지 않았다. 새 등록 버튼은 이 색을 재사용한다. 실제 OCR 업로드·다음 버튼에서 확인한 대비 미달만 화면용 CSS로 보완했다. 본문은 최신 main의 회색에서 요청대로 아주 옅은 하늘색 `#f3f8fd`로 조정하며, 기존 흰 카드·데스크톱 구조·A4 인쇄 배경은 유지한다.

모든 시험은 실제 HTML과 가상 Auth/데이터 또는 격리된 로컬 PostgreSQL에서 실행한다.


360/390/430px 및 데스크톱에서 업무 순서·90일 기준·본인 계약중 차량·경리의 서류/미상환·미확인과 실제 0건 구분·계정/상사/잠금·실제 업무 이동·추가 요청/쓰기 없음·가로 넘침을 검증했다. 기존 홈 회귀는 1440/1024/390/320px를 통과했다. 보조 메뉴는 원본 노드·실제 등록/OCR·정렬 재생성 방지·보기 설정·반응형 복원·키보드/바깥 클릭·초기 인증 중 DOM 안정성과 대비를 확인한다.

최종 홈 브라우저 7개 조합은 9개 제품 파일의 SHA256이 시작·종료 때 같음을 확인했다. 같은 상사의 다른 소유자에게 동일한 구형 차량 ID가 있는 실제 가상 RPC 응답도 시험하여, 잘못된 상세 대신 매입 목록으로 이동함을 확인했다. 경리 ‘확인하기’ 버튼의 실제 대비는 정상 6.410:1, 마우스/키보드 상태 6.059:1이었다. 반복한 동일 projection은 기존 카드 DOM을 유지했다.

운영 정책의 현재 설치 상태·실제 계정의 데이터·실제 모바일 기기의 브라우저는 시험하지 않았다. 정확한 미디어 총수나 전송 완료를 확인할 수 없는 경우에는 서류 업무가 ‘확인 중’으로 남는다. 모바일 계약서·인수증 편집과 키보드 검증은 별도 변경에서 수행한다.

툴바 검증 화면의 주황색 ‘목록 저장 상태를 다시 확인’ 안내는 선택적 차량 분류 RPC가 없는 가상 fixture의 기존 안내이다. 금융 저장 실패나 새 모바일 스타일 오류로 판정하지 않았으며, 안내를 숨기는 제품 변경도 하지 않았다.
