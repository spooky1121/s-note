# v2.189 · 상사대표·일반딜러 가입

기준 main은 `8ec56a12ab844c3eb71cd25aed4724bef67db984`이다.

## 가입 동작

로그인 화면의 신규 가입을 상사대표 가입과 일반딜러 가입으로 나눈다. 두 화면은 상사명, 사업자등록번호, 대표자명, 사업장 주소, 가입자 성명·휴대전화, 이메일, 비밀번호·확인을 받는다. 대표는 새 업무공간의 `admin`, 일반딜러는 대표나 초대 없이 새 업무공간의 `dealer`가 된다. 기존 상사에 자동 합류하지 않는다. 기존 직원 초대 경로와 서버의 초대 이메일·권한·만료·일회성 검증은 유지한다.

상사명 옆 확인 버튼은 서버 조회 후 체크 표시를 보여 준다. 값을 바꾸면 확인 상태를 해제한다. 가입 제출 시 서버가 다시 검사하며, 상사명 또는 사업자번호가 겹치면 `등록되어 있는 상사입니다. 채팅으로 문의 부탁드립니다`, 이메일 또는 휴대전화가 겹치면 `가입된 이메일 또는 휴대번 입니다.` 팝업으로 보류한다. 이메일은 실제 Auth 계정, 전화는 Auth·직원·비공개 프로필의 현재 값을 비교한다. 기존 중복 값은 고치지 않고 변경되는 값에만 새 충돌 방지를 적용한다.

사업자등록증과 딜러증(매매사원증) 이미지가 각각 필요하다. JPEG·PNG·WebP, 파일당 5MiB, 총 요청 12MiB를 제한하고 파일 구조·크기·치수를 확인한다. 검증은 전체 픽셀 디코딩을 수행하지 않는다.

## 저장·인증

`/api/registration`은 기존 서버 환경의 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`를 사용한다. 브라우저에는 서버 키가 전달되지 않는다. 회사 조회와 등록은 같은 출처의 요청만 허용한다.

서버는 비공개 신청을 예약하고, 별도 비공개 `snote-registration-documents` 버킷에 두 이미지를 업로드한 뒤 Auth 가입을 요청한다. 비밀번호는 Auth 요청에만 전달한다. 회사·직원 정보, 비밀번호, 파일 URL을 Auth 권한 메타데이터에 넣지 않는다. 파일 참조는 비공개 신청에 저장하며 신청자·상사 직원·관리자의 직접 Storage 접근을 제한한다.

이메일 인증 대기 중에도 서류는 서버에 남는다. 인증 후 로그인하면 검증된 현재 Auth 사용자와 비공개 신청을 대조하고, 회사 정보·정확한 회원 권한·연락처·기존 호환 키를 한 트랜잭션으로 저장한다. 관리자 권한은 수정 가능한 Auth 메타데이터에서 읽지 않는다. 이전 `zc_bootstrap_company`도 같은 검증 경로를 거쳐 직접 호출 우회를 막는다. 운영의 소속 없는 과거 관리자·초대 신청은 식별정보 없는 집계로 확인했다.

확실한 가입 실패는 취소 확인 후 미확정 업로드만 정리한다. Auth 응답 유실은 자동 재시도하지 않고 신청과 파일을 유지한다. 업로드 전 예약은 30분, 인증 대기 선점은 24시간 후 해제하며 파일과 신청은 보존한다. 검증된 이메일 소유자는 이후에도 중복을 다시 확인해 가입을 이어갈 수 있다.

회사·연락처 변경 트리거는 기존 행 잠금 이후 다른 등록 작업을 기다리지 않고 충돌로 반환한다. 일반 로그인이나 변경되지 않은 값은 등록 잠금을 잡지 않는다. 공개 업로드를 보호하는 요청 한도는 원래 IP를 저장하지 않는 서버 HMAC 기준으로 상사 확인 분당 60회, 가입 시간당 20회다.
