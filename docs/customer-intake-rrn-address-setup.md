# 고객 모바일 주민번호·카카오 주소 검색 적용

v2.13에서는 주소 검색을 기존 웹페이지처럼 별도의 HTTPS 새 창으로 엽니다. 검색 결과를 선택하면 원래 고객 화면의 기본주소에 자동 입력되고, 상세주소를 이어서 입력합니다. 등기받을 주소도 별도로 검색하거나 ‘위 주소와 동일’을 사용할 수 있습니다. 카카오 앱 키는 별도로 등록하지 않습니다.

## 현재 테스트 환경 적용

1. 기존 [주민번호 보관 SQL 0003](../supabase/migrations/202611010003_customer_intake_rrn.sql)을 이미 적용했다면 **추가 SQL은 없습니다**. 아직 적용하지 않았다면 기존 0001·0002 이후에 이 파일 전체를 한 번 실행합니다.
2. **새 Cloudflare 암호화 키를 추가할 필요가 없습니다.** 기존 문자 인증 설정의 `CUSTOMER_INTAKE_OTP_SECRET`에서 용도를 구분한 HKDF-SHA256 방식으로 주민번호용 AES 키를 자동 생성합니다. 주민번호는 계속 서버에 암호화해 저장합니다.
3. 이전 버전에서 `CUSTOMER_INTAKE_RRN_KEY`를 등록했다면 그대로 유지합니다. 올바른 전용 키가 있으면 새 저장에는 해당 키를 우선 사용하며, 기존 기본 키 방식으로 저장한 번호도 읽습니다. 형식이 잘못된 선택 전용 키 때문에 새 접수를 막지는 않습니다.
4. v2.13 전체 파일을 다시 배포합니다. `customer.html`, `address-search.html`, `assets/customer-intake.*`, `assets/address-search.*`, `functions/api/customer-intake.js`, `_headers`도 함께 배포합니다.
5. 운영 주소의 `/api/customer-intake`에서 `configured: true`, `rrnConfigured: true`를 확인합니다. `rrnKeyMode`가 `derived`이면 기본 서버 설정을 사용하고, `dedicated`이면 기존 전용 키를 사용합니다. 이 진단은 키 값이나 고객정보를 반환하지 않습니다.

상사별 주민번호 사용 여부는 기존 웹페이지와 동일한 `zc_companies.rrn_enabled` 설정을 사용합니다. 기존 판매 화면에서 주민번호를 저장할 수 있는 상사는 모바일에서도 같은 설정으로 사용합니다. 이 버전은 회사 설정이나 기존 웹페이지의 주민번호 저장 함수를 변경하지 않습니다.

## 입력·보관·불러오기

- 앞 6자리와 뒤 7자리를 나누어 입력하며 뒷자리는 가려서 표시합니다. 별도의 주민번호 안내 확인 체크박스는 없으며, 입력 안내는 기존 개인정보 동의 항목에 함께 표시합니다.
- 번호는 AES-256-GCM으로 암호화해 서버 접수함의 별도 필드에 저장합니다. 일반 고객 JSON, 목록 자동 조회, 브라우저 저장소에는 주민번호 평문을 넣지 않습니다.
- 담당자가 **입력정보 불러오기**를 누르면 판매 입력칸으로 가져옵니다. 기존 번호를 덮어쓰는 경우 확인하고, 계약서 저장은 기존 서버 저장 기능으로 진행합니다.
- 접수 후 30일까지 조회할 수 있으며 기존 0002 SQL의 정리 작업으로 접수 내역과 함께 삭제합니다. 계약서·고객관리로 따로 저장한 기록은 접수함 정리 대상이 아닙니다.
- 주소 검색창은 고객정보나 문자 인증 토큰을 전달받지 않습니다. SDK를 불러오기 전에 검색창의 직접적인 opener 연결을 끊고, 보관한 수신 창 참조를 통해 주소 선택 결과만 돌려줍니다. 원래 화면은 창 출처·origin·회차별 난수를 확인합니다.

기본 키 방식으로 저장한 번호가 남아 있는 동안 `CUSTOMER_INTAKE_OTP_SECRET`을 바꾸면 해당 번호를 읽을 수 없습니다. 전용 키로 저장한 자료도 당시의 `CUSTOMER_INTAKE_RRN_KEY`가 필요합니다. 키를 지우거나 교체하기 전에 기존 접수 자료와 보관기간을 확인합니다. 키 값은 GitHub·HTML·채팅에 올리지 않습니다.

## 운영 확인

테스트 휴대폰에서 문자 인증 → 주소 검색 새 창 → 주소 선택 및 자동 입력 → 상세주소 → 등기주소 검색·동기화 → 주민번호 입력 → 제출 → 담당자 불러오기를 확인합니다. 새 창이 차단되면 팝업 허용 후 다시 검색하거나 직접 입력합니다. 검색창을 닫아도 원래 화면의 다른 입력값은 유지합니다.

카카오의 현재 검색 호스트는 `postcode.map.kakao.com`, SDK 호스트는 `t1.kakaocdn.net`입니다. [공식 도메인 안내](https://github.com/kakao-postcode/kakao-postcode-QnA/issues/1560)와 [CDN 변경 공지](https://github.com/kakao-postcode/kakao-postcode-QnA/issues/1562)를 기준으로 CSP를 구성했습니다. 개발 환경에서는 실제 카카오 접속이 프록시에서 차단되어 모의 SDK와 브라우저의 실제 새 창으로 검증합니다. 실제 검색 결과는 운영 배포 후 휴대폰에서 확인합니다.
