# 대시보드 자동차 칼럼 — v2.241

`GET /api/automotive-columns`는 네이버 뉴스 검색 API의 고정 검색어 두 개(자동차 칼럼, 자동차 기고)를 사용한다. 검색어·대상 URL·새로고침 우회값을 요청자가 지정할 수 없다. 이 경로는 Pages API 보안 허용 목록에 포함되며 같은 출처, GET 방식, 기존 IP·경로 단위 요청 제한과 보안 응답 헤더를 적용한다. 공개 뉴스 조회에는 Supabase HTTP 관측 기록을 새로 만들지 않는다.

## 제공처와 분류

공식 [네이버 뉴스 검색 API 문서](https://developers.naver.com/docs/serviceapi/search/news/news.md)를 기준으로 JSON 엔드포인트, 인증 헤더, 날짜순 정렬과 최대 검색 결과 수를 사용한다. 네이버 API에는 자동차 카테고리나 칼럼 여부를 확정하는 필드가 없다. 따라서 제목에 자동차 관련어와 명시적인 칼럼·기고 등 논평 표기가 함께 있는 항목만 보수적으로 선택한다. 설명에 자동차가 잠깐 언급되거나 일반 기사에 칼럼이라는 말이 들어간 결과는 포함하지 않는다. 이 방식은 일치하는 실제 칼럼을 일부 제외할 수 있으며, 제공처의 분류를 보증하는 방식은 아니다.

최대 다섯 개의 제목·HTTPS 원문 링크(원문이 부적절하면 제공된 안전한 네이버 링크)·제공 날짜·매체 도메인만 반환한다. 본문이나 원문 이미지를 수집하지 않는다. 제목은 HTML과 제어 문자를 제거한 일반 텍스트다. 중복 제목·URL, 부적절한 URL과 날짜, 6개월보다 오래된 항목은 제외한다. 결과가 없으면 실제 빈 목록을 표시하고 일반 뉴스나 가상 기사를 채우지 않는다.

## 서버 설정

Cloudflare Pages의 S-NOTE 프로젝트 환경 변수/비밀에 아래 두 값을 설정하고 새 배포에 반영한다.

- `NAVER_NEWS_CLIENT_ID`
- `NAVER_NEWS_CLIENT_SECRET`

이 값은 네이버 개발자센터 애플리케이션에서 발급받으며 **검색 API** 사용 권한이 필요하다. 비밀 값은 저장소·브라우저·로그·채팅에 넣지 않는다. 설정이 없으면 제공처 요청을 보내지 않고 `NEWS_NOT_CONFIGURED` 503을 반환한다. 설정은 있지만 네이버가 401/403을 반환한 경우는 별도의 `NEWS_AUTH_FAILED` 응답이다.

## 요청과 저장

제공처 호출은 고정 주소 두 건, 검색당 최대 100개, 본문 최대 1MiB이며 전체 제공처 대기 시간을 6초로 제한한다. 같은 요청은 공유하고 검증한 결과는 15분 동안 서버 메모리와 내부 edge cache에 보관한다. 비밀을 노출하지 않는 해시로 캐시를 구분하므로 설정을 바꾸면 이전 인증 캐시를 재사용하지 않는다. 캐시 읽기·쓰기도 짧은 제한을 두며 문제가 생기면 정상 제공처 요청을 막지 않는다. 클라이언트 응답은 기존 API 미들웨어 정책대로 `no-store`다.

성공 목록과 실제 빈 목록은 200, 설정 없음/인증 실패는 503, 제공처 제한은 429, 제공처/응답 오류는 502, 지연은 504로 구분한다. 한 검색만 성공해도 확인한 칼럼이 있으면 `partial: true`로 반환할 수 있다. 실패만 발생한 상황을 빈 목록 성공으로 표시하지 않는다.

## 검증 범위

로컬 단위 테스트는 분류·HTML·URL·날짜·중복·캐시·동시 요청·설정·오류·시간 제한을 검증한다. Wrangler의 실제 Pages 라우터를 빌드하고 설치된 workerd가 지원하는 `2026-10-19` 호환 날짜로 설정 없음(503이며 404가 아님)·성공·빈 목록·장애와 출처/메서드 보안·캐시·Supabase 관측 제외를 시험한다. 네이버와 운영 DB에 실제 요청을 보내지 않으며 실제 키의 뉴스 수신은 별도 운영 확인이 필요하다.
