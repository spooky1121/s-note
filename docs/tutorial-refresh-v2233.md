# 모바일 도움말 제거와 PC 튜토리얼 갱신 (v2.233)

기준 main은 `3bb3cb2f2f19fb5c1db5451d6841c48984e0922b`이다. 깨끗한 작업 트리를 확인한 별도 브랜치에서 진행했다.

모바일 화면(기존 모바일 레이아웃 기준 760px 이하)에서는 챗봇 버튼과 패널을 표시하지 않고 비활성화한다. CSS를 먼저 적용해 초기 표시도 막으며, 챗봇/튜토리얼 API로도 열리지 않는다. PC에서 열어 둔 상담이나 가이드는 모바일로 줄이면 닫히고 숨겨진 창에 포커스가 남지 않는다. 상담 활성 조회·읽음 처리·전송은 모바일에서 실행하지 않는다. 기존 프로필 알림 숫자를 공급하는 별도 미확인 상담 조회는 유지한다. 같은 계정에서 PC로 돌아오면 FAQ/상담과 미전송 초안을 다시 사용할 수 있다.

PC 튜토리얼은 기존의 주제 메뉴·단계별 설명·실제 화면·이전/다음·진행 표시·확대 형식을 유지하고 6주제18단계에서 9주제27단계로 갱신한다.

- 대시보드와 개인 일정
- 실시간 통합검색과 차량 목록/열 설정/카드 보기
- 차량 등록과 차종/금액/재고 설정
- 차량 정보·사진/서류·비용 편집 견적서
- 고객 입력 링크·인증과 계약서/인수증
- 차량 공유·알림과 고객 관리
- 판매 완료 목록·판매등록의 비용/수익·정산
- 수익 그래프·소득정산·재고금융
- 프로필·입금계좌 설정과 휴지통

이미지는 `assets/tutorial/v2233/`의 현재 앱 실제 캡처를 사용한다. 가상 계정·차량·고객·일정을 사용해 모든 요청을 가로채고 UI 자체의 동작/팝업을 촬영했다. 이미지 재생성이나 업무 UI 재제작은 하지 않았다. 운영 고객·계좌·서류·SMS를 사용하지 않았다. 문구는 현재 버튼·입력·권한과 대조하고, 오래된 문자/검색/이자/가입 FAQ 문구도 현재 안내로 맞췄다.

튜토리얼 이미지는 해당 단계에서만 요청하며 모바일에서는 요청하지 않는다. 실패한 이미지는 기존 오류 안내와 다음 단계 이동을 유지한다. 기존 경로 이동 시 권한 재검사, 로그인 전 읽기 전용 안내, 미저장 작업 보호, 계정/역할 변경·페이지 중단 정리를 유지한다. 업무 데이터·문서 규격·상사 로고/도장·DB·운영 설정은 변경하지 않는다.

기존 FAQ/상담 테스트의 모바일 버튼 표시 기대는 새 모바일 숨김 검사로 대체한다. 기존 main에서도 PC 버튼은48px/SVG44px였으나 오래된 검사는68/64px를 기대해 실패했다. 기준 main을 별도로 렌더링해 동일함을 확인한 뒤 검사 기대값만 현재 값으로 고쳤다. 운영자 알림의 기존 테마 색상 기대도 현재 테마 값에 맞췄으며 운영자 제품 파일은 변경하지 않았다.

실제 운영 사이트 직접 열기는 실행환경의 도메인 제한으로 수행하지 않는다. 검증에는 합성 자료만 사용하며 실제 Safari/모바일 기기는 별도 확인 대상이다. 운영 배포는 검증한 소스 트리와 정확한 커밋의 S-NOTE Pages 성공으로 확인한다.

## 추가 요청: 프리텐다드 통일

사용자의 후속 요청에 따라 공통 UI·입력·팝업·월정산/소득정산 iframe·문서 출력의 글꼴을 공식 Pretendard v1.3.9로 통일한다. 원본 WOFF2를 서비스에 직접 포함하고 OFL 라이선스와 출처를 함께 보관한다. 글씨 크기·가중치·line-height 속성은 유지하며, 기존 혼합 글꼴의 폰트 메트릭을 보존해 버튼 등의 줄 상자 높이를 맞춘다. 글꼴 고유의 글자 폭 변화는 컴포넌트 고정 규격과 구분해 기록한다.

7개 HTML에 동일한 로컬 글꼴 CSS를 연결하고, 기존 두 글꼴 preload와 startup의4개강제load를 선택한 Pretendard 요청으로 정리한다. preload와 실제폰트URL은같게맞춘다. 주소검색의 S-NOTE 소유 안내 wrapper와 상사명 줄바꿈 canvas 측정에도 적용한다. 카카오 주소검색 내부 등 외부 제공 화면, 업로드 문서 이미지·로고·도장·서명과 실제 도장 생성용 글씨는 원본 자료로 유지한다.

초기 표시의 1.8초 복구 제한과 글꼴 실패 시 시스템 글꼴 고정은 유지한다. 부하가 높은 병렬 가상 시험에서 해당 fallback이 발생했지만 단독 실행의 실제 Pretendard 로딩과 구분해 확인한다. 새로운 글꼴을 기다리느라 로그인 조작이 막히지 않는 기존7개 회귀도 통과했다.

별도 기존 단위검사 중 tests/sales-popup-return.test.cjs의5개는 격리 VM fixture에 snoteWorkActiveId helper가 없어 실패한다. 해당 제품 함수는 기준 main과 byte/hash 동일하므로 이 요청에서 업무 코드를 바꾸지 않고 기존 문제로 기록했다. 튜토리얼 실제 화면의 권한·판매/문서 초안 보호·이동 검증은 별도로 통과했다.
