# 자체 OCR 테스트 기능 독립 검토

현재 검토 소스에서 남은 차단 사항은 없다. 이 검토는 운영자 테스트 기능에 한정하며 운영 배포·서비스 전환이나 실제 고객 등록증 시험을 수행하지 않았다.

## 발견 후 보완·재검증한 항목

| 초기 발견 | 재현·영향 | 현재 결과 |
|---|---|---|
| 옆 칸 항목명을 못 읽으면 차명 영역이 페이지 끝까지 확장됨 | `차명`, `BMW 530i`, 먼 옆 칸의 `B48B20`만 높은 신뢰도로 인식되면 둘을 합쳐 자동입력했다. | 추출기의 분리된 가로 군집과 거리 검사를 적용했다. 독립 재현에서 옆 칸 값이 제외되고 `layout_uncertain`으로 자동입력되지 않음을 확인했다. |
| 한글 날짜가 모델연도로 선택됨 | 모델연도 값이 없고 옆 칸 제목을 놓친 상태에서 `2025년 3월`이 `2025`로 자동입력됐다. | 한글·숫자 날짜를 모델연도 근거에서 제외하고 먼 영역은 후보에서 배제한다. 독립 재현에서 값은 빈 상태로 확인 대상으로 남았다. |
| 회전 후보끼리 동점인데 첫 방향을 선택함 | 원본 0점, 90도 8점, 180도 8점에서 90도로 회전할 수 있었다. | 검토한 후보의 최고·차점 차이를 확인하며 약하거나 동점이면 원본을 유지한다. 선택하지 않은 PIL 이미지 정리도 검사했다. |
| 다시 분석한 불확실 항목에 이전 자동입력값이 남음 | 새 응답의 값이 없거나 확인 대상이면 이전 자동입력 문자열이 남을 수 있었다. | 직접 수정하지 않은 값만 새 응답에 따라 비우며 사용자 수정값은 보존한다. UI 단위 시험에서 재확인했다. |

레이아웃 확인 사유는 추출기 → FastAPI 허용 목록 → 게이트웨이 → UI의 한국어 안내까지 연결되어 있다. 이 사례 보완으로 실제 등록증 전체 양식의 정확도가 입증된 것은 아니므로 실제 표본 평가가 필요하다.

## 인증·개인정보·입력 수명

- Pages 게이트웨이는 기존 Auth 사용자 및 실제 운영자 세션 허용 목록을 확인한다. 결과 반환 직전에도 같은 actor/session의 권한을 RPC로 다시 확인한다. 일반 딜러·상사 관리자 권한이나 `user_metadata`를 운영자 권한으로 사용하지 않는다.
- Python 서비스의 키는 서버 간 Bearer 전용이며 상수 시간 비교를 사용한다. 이 키를 HTML·브라우저 설정·API 결과에 노출하는 경로는 찾지 못했다. 브라우저와 자체 서버 사이의 임의 URL 전달·Google 자동 폴백도 없다.
- 입력 형식·파일 크기·이미지 크기·다중 파일을 제한한다. 이미지 바이트는 메모리에서 처리하며 업로드 사본·전체 OCR 문자열·주민번호·주소를 DB·Storage 또는 일반 로그에 기록하는 새 경로는 없다. Python 실행 안내는 access 로그를 끄도록 한다.
- UI는 사진 교체·메뉴 이동·로그아웃·인증 세대 변경 후 응답을 버리고 URL·입력값을 정리한다. 사용자의 직접 수정값은 늦은 OCR이나 다시 분석 결과가 덮지 않는다. 원본 바이트를 바꾸는 처리와 차량 저장 호출은 새 테스트 화면에 없다.
- CPU 서비스는 로컬 모델의 크기·SHA256을 확인하고 ONNX CPU 세션을 연다. 추론 코드에 다운로드·HTTP 클라이언트·외부 OCR 폴백은 없다. 필요한 파일이 없으면 준비되지 않은 상태로 실패한다. 네이티브 추론의 응답 시간이 초과돼도 실제 스레드가 끝날 때까지 처리 슬롯을 유지한다.

## 기존 코드와 검증 증거

v2.257의 생산 소스 manifest 297개와 비교해 **293개는 바이트가 동일**하다. 변경된 기존 파일은 운영자 화면 `operator.html`, `assets/operator-console.js`, 운영자 인증 재사용 도우미 `functions/api/operator.js`, 신규 API 정책 `functions/_shared/api-security.js` 네 개뿐이다. 딜러의 `index.html`, Google `functions/api/ocr.js`, 기존 스캐너와 공식 로고·Pretendard 파일은 유지된다.

독립 실행한 시험은 다음과 같다. 모두 가상 계정·생성 입력만 사용했다.

- 로컬 Node 서버 11개: 실제 HTTP 전송, 정적 경로 제한, 가상 Auth·자체 OCR 응답, 권한 거부·일반 업무 API 차단.
- 운영자 OCR UI 단위 10개: 원본 보존·사용자 수정·A/B 교체·다시 분석·확인 영역·인증 변경 정리.
- 추출기·평가·실제 모델을 쓰지 않는 엔진 시험 24개: 두 오입력 재현, 회전 동점, 형식·연도·재판독·좌표·정확한 일치 집계.
- FastAPI 시험 12개: 가상 엔진으로 인증·입력 제한·EXIF·민감 문자열 제외·처리 슬롯과 시간 초과를 확인했다.

독립 검토자는 실제 모델 추론을 중복 실행하지 않았다. 실제 합성 이미지·모델·오프라인 실행 증거는 별도의 모델/API 시험 결과로 구분한다. 기본 명령 샌드박스에서 TestClient 실행이 진행되지 않아 해당 시험만 소켓 사용을 허용한 실행 환경에서 재실행했고 12개가 통과했다.

모델은 공개 재배포 릴리스의 SHA256에 고정되어 있으나 원본 제공자의 독립 체크섬과 일치하는지까지 검증하지 못했다. [모델 출처와 라이선스 기록](../services/registration-ocr/MODEL-NOTICE.md)의 이 한계를 유지하며 실제 운영 전환 시 원본 출처를 재검증해야 한다. 이 검토에서 운영 API·운영 DB·실제 고객 자료는 조회하거나 수정하지 않았다.
