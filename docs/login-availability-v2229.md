# 초기 표시 대기로 막히는 접속·로그인 복구 (v2.229)

기준 main은 `a2b4fb344f438e6562158b153d2002024e684b9a`이다. 스타일 응답을 기다리는 표시 코드가 준비된 로그인 양식까지 숨기는 경로를 수정한다.

## 원인과 수정

실제 HTML과 가상 인증을 사용하는 Chromium에서 `workspace-density.css`만 5~6초 보류하면, 로그인 컨트롤러·활성 버튼이 이미 준비됐는데도 body가 opacity 0 / visibility hidden / pointer-events none으로 유지됐다. 1.8초 watchdog이 `readyState === 'loading'` 또는 미완료 stylesheet 조건에서 반환해 표시 대기를 해제하지 못했다. 기존 검사는 늦은 CSS를 곧 해제한 다음 결과를 확인해 이 상태를 놓쳤다.

동일 조건에서 CSS를 계속 보류하고 표시 가림 속성만 제거하면 기존 인증·상사 권한 확인을 거쳐 정상 로그인됐다. 인증 실패나 실제 운영 서버 장애가 입증된 것은 아니며, 이 표시 차단 경로를 독립적으로 재현한 것이다.

1.8초 후 실제 로그인 gate와 설치된 `zc86Cloud` 컨트롤러가 확인되면, HTML/CSS 로딩이 남아 있어도 표시 가림을 한 번 해제한다. 아직 사용할 문서가 없으면 100ms 후 다시 확인한다. 비활성 탭에서도 표시 애니메이션의 클릭 차단이 남지 않게 정리한다. 정상 로딩의 글꼴·로고·배치 준비와 짧은 fade-in은 유지한다.

`S.ready`, 세션, 권한, 금융 잠금, gate.hidden, 앱 inert와 양식 disabled 값은 수정하지 않는다. 로그인 인증·역할 확인을 우회하지 않으며 v2.228의 검색·카드·문서·업무 기능과 데이터도 유지한다. 관련 6개 UI 문서의 초기 표시 JS 주소를 2.229로 바꾼다.

## 검증

- `tests/login-availability-v2229.browser.cjs`: 가상 실제 앱 1440/390px에서 CSS를 보류한 채 화면 조작과 실제 로그인 완료, 늦은 CSS 뒤 가림 재발 없음, 이후 로그아웃/재로그인, HTML 파싱 지연 복구, 글꼴/이미지 실패, 잘못된 비밀번호와 비활성 회원의 차단을 확인한다.
- `tests/normal-login.browser.cjs`: 로그인·동시 세션·비밀번호 재시도·복원·유휴/명시 로그아웃·배경 자료·회원 검증 전체 통과.
- `tests/startup-stability-v2227.browser.cjs` 중 글꼴/CSS/스크립트/이미지 지연 20개 통과, 관측 CLS 0. 정상 표시 규격을 유지한다.
- JS 문법, `git diff --check`, 서비스 명칭 경계 검사.

집중 검사 7개는 모두 통과했다. 로그아웃 뒤의 기존 성공 알림은 실제 사용자 흐름대로 확인 버튼을 누른 다음 재로그인했다. 테스트가 그 알림을 건너뛰면 배경 입력이 차단되므로 인증 요청 없이 필수 입력 알림이 발생하며, 이 준비 문제는 제품 인증 코드를 바꾸지 않고 fixture에서 바로잡았다.

테스트는 가상 데이터만 사용한다. 공개 인증 SDK URL은 HTTP 200, 키 없는 인증 health 요청은 HTTP 401 응답을 확인했다. 운영 웹 주소 직접 접근은 실행환경의 대상 도메인 제한으로 차단돼 실제 운영 계정의 로그인은 수행하지 않았다. DB·인증·Cloudflare 운영 설정은 변경하지 않는다. 배포는 정확한 커밋의 S-NOTE Pages 성공 및 검증한 소스 트리 일치로 확인한다.
