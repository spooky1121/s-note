# 엔카 HTTP 오류 진단 (클라이언트 2.128)

이번 변경은 503 원인 확인을 돕는 진단 개선이며 장애 해결을 의미하지 않는다. 앱 표시 버전 2.129, 서버 resolverRelease 2.127과 클라이언트 버전은 별개다.

오류의 기존 안전한 diagnostics와 HTTP 상태를 유지하고, 응답이 도착한 경우 다음 정보만 추가한다.

- `responseType`: Content-Type을 json/html/text/other로 분류. 원문이나 매개변수는 복사하지 않는다.
- `observedAt`: 응답 헤더를 받은 클라이언트의 ISO 시각. 서버 문자열을 사용하지 않으며 클라이언트 시계 정확도에 의존한다.
- `rayId`: 정확히 16자리 16진수와 선택적 하이픈/3자리 영문 POP. 소문자로 정규화한다. 유효한 CF-Ray 헤더가 JSON ray_id보다 우선하며 헤더가 없거나 유효하지 않을 때만 JSON 값을 사용한다.
- `cloudflareErrorCode`: 오류 JSON 최상위 error_code의 정수 1000–1999 또는 정확한 4자리 숫자 문자열. 임의 오류 문구는 버린다. 이 필드만으로 응답 발신자나 장애 원인을 확정하지 않는다.

헤더 증거는 HTML 응답과 JSON 파싱 실패에서도 보존한다. 기존 오류 코드/requestId/resolverRelease는 catch에서 덮지 않는다. 증거는 요청별로만 보관하며 새 조회/상세 닫기/컨텍스트 변경 후 이전 응답은 되살릴 수 없다. 토큰, 쿠키, Authorization, URL/쿼리, 차량/고객 정보, 응답 원문은 추가하지 않는다. 요청 수, 자동 재시도, 인증, 보안 설정, 데이터 저장 구조는 변경하지 않았다.

검증: Node 24.22.3에서 `npm test --prefix tests/encar` 1064개 통과, 실패/스킵 0. 정상 광고/기존 서버 오류/타임아웃/취소/수동 재시도 회귀와 잘못된 형식·개행·객체·URL·민감 필드 주입, 헤더 충돌, 이전 ray 초기화를 포함한다. HTTP/DB/인증은 모의이며 운영 고객 데이터로 시험하지 않았다. `git diff --check` 통과.

배포 성공 체크, 운영 JS 바이트 일치, 사용자 판매상세 실제 재현은 각각 별도로 확인해야 한다. 이전 Python 요청의 Cloudflare 403/1010은 사용자 503과 다른 관측이며 동일 원인으로 단정하지 않는다.
