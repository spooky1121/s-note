# v2.205 개인 일정 대시보드

보유 차량·판매완료 차량 목록 카드 두 개를 큰 월간 달력으로 교체했다. 기존 금액 KPI, 실적·수익 차트, 금액 잠금은 유지한다. 모바일에서는 달력을 먼저 보여준다.

## 사용

- 날짜 또는 `일정 추가`를 누르면 제목·날짜와 선택 시간·메모를 입력한다.
- 달력이나 오른쪽 목록의 일정을 누르면 수정·완료·삭제할 수 있다.
- 오른쪽에 오늘 일정, 다가올 미완료 일정, 기한 지난 미완료 일정을 구분한다. 기존 차량의 오늘 처리할 일도 유지한다.
- 한국 시간 기준 날짜를 사용한다. 자정이나 탭 복귀 때 다시 확인하며 작성 중인 초안을 지우지 않는다.
- 달력은 42일, 날짜당 처음 3건과 추가 건수를 표시한다. 추가 건수를 누르면 해당 날짜의 불러온 일정을 볼 수 있다.
- 한번에 달력 500건·각 일정 목록 50건을 받는다. 전체 건수와 생략 여부를 별도로 표시한다. 저장 건수 자체에 이 제한을 적용하지 않는다.

## 저장·권한

`dealer-scheduler-store.js`는 개인 일정을 최대 6개월·30초 동안 메모리에만 캐시한다. 동일 조회를 합치고, 로그아웃·상사/계정/세션 변경·권한 거절 때 데이터와 열린 입력 내용을 지운다. 일정 본문을 브라우저 영구 저장소·URL·로그에 남기지 않는다.

`snote_schedule_list/save/delete`는 확인한 토큰으로 고정된 Supabase RPC에 요청한다. 서버는 실제 세션과 활성 상사 소속을 다시 검증한다. 대표와 딜러가 본인 일정만 이용하며, 같은 상사의 대표에게도 다른 딜러 일정을 공개하지 않는다. 경리·운영자·미인증 사용자는 이 개인 일정 기능 대상이 아니다.

새 `snote_schedule_private.events`는 RLS와 직접 접근 금지를 적용했다. 공개 함수는 INVOKER이며 제한된 private 함수만 호출한다. 기존 Auth·금융 함수와 데이터는 변경하지 않는다. 금융 잠금 중에는 기존 금액 화면을 계속 숨기고 개인 일정만 이용할 수 있다.

저장은 UUID와 revision으로 충돌을 확인한다. 응답이 유실되면 같은 ID·내용·다음 revision을 조회해 성공을 확인하며 무작정 재저장하지 않는다. 삭제는 tombstone으로 재시도와 부활 방지를 처리한다. 충돌·통신 오류 때 입력 내용을 유지하고 성공으로 오인하지 않는다.

## 검증

- `node --test tests/dealer-scheduler-store.test.cjs`: 날짜·한국 시간·단일 조회·캐시·권한 전환·응답 유실·충돌·삭제 재시도 24개.
- `NODE_PATH=/workspace/work/deps/node_modules node tests/dealer-schedule.sql.cjs`: 격리 PostgreSQL에서 권한·세션·상사 이동·CAS·삭제·범위·집계·기존 데이터 보존 16그룹.
- `NODE_PATH=/workspace/work/deps/node_modules node tests/dealer-scheduler.browser.cjs`: 실제 앱·인증 브리지·REST 요청을 가상 계정/서버로 연결한 기능·모바일·금융 잠금·대용량 응답과 격리 SQL 왕복 검증.
- 기존 home-dashboard, dashboard-navigation, normal-login, login-landing, profile-account-bridge, idle-session 회귀와 현재 문서 fixture의 견적서·계약서 인쇄를 확인한다.

브라우저 시험은 모든 외부 요청을 가로채며 실제 고객 데이터·문자·계정 비밀번호를 사용하지 않는다. 운영 검증은 스키마/ACL/기존 함수 해시와 배포된 소스 일치 여부로 수행한다. 실제 딜러 계정으로 운영 일정을 만들지는 않는다.

기존 `document-print-layout.browser.cjs`의 `고객지원센터` 주소 미리보기 기대 실패는 분리한 변경 전 v2.204에서도 동일하게 재현했다. 현재 양식 fixture의 원래 동기 메뉴 이동→미리보기→인쇄 호출은 통과했고, 견적서 A4 1쪽·계약서 2쪽 및 양쪽 고객 서명·도장과 인쇄 스타일을 유지했다. 열린 일정 창이 없으면 이동 guard가 동기 `true`를 반환해 기존 호출 순서를 보존한다. 이번 범위에서 문서 양식은 수정하지 않는다.
