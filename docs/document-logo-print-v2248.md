# 문서 로고와 인쇄 — v2.248

견적서·인수증·계약서 인쇄 버튼은 로고가 없거나 로드되지 않아도 인쇄를 계속한다. 기존에는 모든 문서 하단의 공통 로고 준비 결과를 필수 조건으로 사용해, 닫힌 다른 문서의 로고 실패도 현재 문서의 인쇄를 막았다. 상사 로고 요청이나 디코딩이 끝나지 않으면 대기 또한 계속될 수 있었다.

## 변경

- 인쇄에 필요한 현재 문서의 선택적 로고만 최대 1.2초 기다린다. 준비되지 않은 이미지는 인쇄에만 숨기며 로고 영역 크기는 유지한다. 미리보기 로더와 상사별 자산 범위는 그대로 유지한다.
- 계약서의 실제 인쇄 복제본도 로고는 선택적으로 처리한다. 도장과 고객 서명은 기존대로 정확한 복제 이미지의 디코딩 성공을 확인한다.
- 모바일에서 편집용 A4 원본을 숨긴 상태는 로고 로딩 실패로 판단하지 않는다. 이미지 자체의 로딩 상태를 확인해 정상 로고가 인쇄 복제본에서 유지되도록 한다.
- 준비된 계약서는 브라우저 `beforeprint`에서 다시 만들지 않는다. 이미 검증된 복제본과 로고 실패 표시를 그대로 출력한다.
- 다음 인쇄 준비와 `afterprint`에서 임시 숨김 표시를 초기화해, 로고 복구 후 다시 표시할 수 있다.
- 계좌 조회·버전, 도장 상태·변경, 서명 준비, 계약 필수 항목·금액·초안, 로그인 사용자·상사·차량·미리보기 범위 확인은 유지한다. 금융 계산, 저장 데이터, DB 스키마는 변경하지 않는다.
- 공식 로고 파일·폰트, A4 규격, 페이지 수, 도장·서명 위치, 기존 문서 하단 영역 크기는 변경하지 않는다.

## 검증 방법

`node tests/document-logo-print-v2248.browser.cjs`는 가상 데이터와 차단된 네트워크에서 실제 세 종류의 인쇄 버튼을 사용한다. 정상·로고 미등록·상사 로고 다운로드 실패·공식 로고 HTTP 404·응답 지연·같은 미리보기에서 복구, 계약서 복제본만의 로고 실패를 확인한다. 도장·서명·계좌 실패와 오래된 사용자 범위는 인쇄를 차단해야 한다. PC 1440px·모바일 390px에서 입력값과 저장 차량 불변, 인쇄 미디어에서 깨진 이미지 숨김, A4 크기 및 견적서 1/계약서 2/인수증 1페이지를 비교한다.

관련 회귀는 `document-service-brand-v2231`, `company-document-assets`, `contract-print-recovery-v2165`, `document-footer-office`, `document-print-layout`, `receipt-privacy-layout`, `deleted-customer-document-print`, `document-actions` 브라우저 테스트와 `quote-insurance-adjustments-v2199.test.mjs`를 사용한다. 실제 운영 고객 자료, 실제 프린터 출력과 사용자 컴퓨터의 인쇄 대화상자는 시험하지 않는다.
