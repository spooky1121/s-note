# v2.203 로그인 화면과 계정 복구

로그인 화면을 하늘색 배경과 큰 이미지 카드로 재구성했다. 기존 로그인·가입·초대가입 흐름을 유지하고, 하단의 기능 요약 4개와 상세 소개 4개가 로그인 영역 자체의 스크롤에 맞춰 한 번씩 나타난다. 동작 감소 설정 또는 애니메이션 스크립트 실패 시에도 내용은 읽을 수 있다. 상세 화면 이미지는 실제 S-NOTE 화면에 가상 데이터만 넣어 촬영했다. `tests/login-showcase-capture.cjs`로 재현할 수 있으며 운영 자료는 포함하지 않는다. WebP 이미지 4개는 필요할 때 불러온다.

## 계정 찾기

- 로그인 아래 아이디 찾기·비밀번호 찾기에서 등록된 이름과 휴대전화를 확인한다. 발신번호는 기존 공용 인증 발신번호를 사용한다.
- 기존에 본인인증한 현재 휴대전화만 문자 확인 후 아이디 조회 또는 새 비밀번호 설정을 허용한다. 등록만 하고 인증하지 않은 기존 연락처는 문자 확인 뒤 등록 이메일의 Supabase 복구 링크로 추가 확인한다. 이메일 링크만으로 휴대전화 인증 이력을 생성하지 않는다.
- 등록되지 않은 정보, 중복 연락처, 비활성·보관 계정, 운영자 계정은 공개 응답으로 계정 존재 여부를 구분하지 않는다. 프로필의 현재 연락처가 비어 있으면 오래된 직원 연락처로 대체하지 않는다.
- 인증번호는 5분 동안 유효하고 오입력 5회 후 새 인증이 필요하다. 전화번호·접속정보의 서버 측 제한과 일회용 요청으로 문자 남용을 줄인다. 인증 전에는 아이디를 노출하지 않는다.
- 비밀번호는 조회·표시하지 않고 새로 설정한다. 인증번호·복구 토큰·비밀번호를 브라우저 영구 저장소나 관측 로그에 기록하지 않는다. 새 자격증명 경로는 서비스/HTTP 관측 대상에서도 제외한다.
- 비밀번호 변경 요청은 한 번만 실행한다. 응답 유실로 결과가 불명확하면 자동으로 같은 변경을 재실행하지 않는다. 해당 변경의 최대 60초 실행 구간에만 연락처·대상 계정 변경을 보호한다. 성공 시 해당 사용자의 Auth 세션을 폐기한다. 이미 발급된 JWT의 모든 기존 업무 경로가 즉시 거부된다는 보장은 하지 않는다.

기존 이메일 복구 허용 주소 `https://s-note.kr/`로 도착한 복구 링크는 전용 페이지로 전달한다. 토큰을 주소에서 즉시 지우고, 임시 메모리 Auth 클라이언트의 서버 사용자 확인 후에만 아이디·새 비밀번호 입력을 표시한다. 기존 로그인 저장소를 덮어쓰지 않는다. 가입 확인 링크와 일반 로그인은 이 경로로 보내지 않는다.

## 기타 표시 변경

서버 용량·전송량은 1024 기준 B/KB/MB/GB/TB와 최대 소수 두 자리로 표시한다. 알 수 없는 값은 `—`로 유지하고 원래 바이트 수는 도구 설명에 남긴다. 건수·요금·시간은 변환하지 않는다. 잘못된 로그인 정보 안내는 `계정 ID 또는 비밀번호를 확인해주세요.`로 통일했다. 확인 버튼만 있는 공통 메시지 팝업은 닫기 아이콘을 숨기고, 확인·취소 팝업과 입력창의 닫기는 유지한다.

## 검증 범위

가상 자료로 SQL 권한·인증·동시 요청·실패 후 재시도, 실제 API와 SQL 통합, PC/모바일 로그인·가입·복구·메시지·뒤로가기, 스크롤·동작 감소·스크립트 실패를 검증한다. 실제 문자·이메일 발송, 운영 사용자 비밀번호 변경 및 로그인은 시험하지 않는다. 운영 배포 확인은 동일 소스 트리의 Pages 빌드 결과로 기록한다.

DB 적용 파일: `supabase/migrations/20261123132420_phone_account_recovery.sql`. 기존 Supabase/SOLAPI 인증 환경변수를 사용하며 새 외부 서비스나 주소 설정은 추가하지 않는다. 기존 금융·거래·백업 데이터와 권한은 변경하지 않는다.
