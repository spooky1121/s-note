# 직접 입력 차종을 상사 공용 목록에 저장

v2.20은 차량 등록의 **목록에 없는 차량 직접 입력**으로 입력한 제조사·차명·등급(세부모델)·트림을 상사 공용 DB에 축적합니다. 다음 차량 등록에서 선택할 수 있고, 같은 상사의 다른 직원과 기기에서도 다시 읽습니다. 차량을 삭제해도 독립 차종 목록은 남습니다.

차량의 전체 표시명과 분류를 구분합니다. 예를 들어 `제조사 + 세부모델 + 트림`으로 만든 차량 표시명을 세부모델 칸에 중복 저장하지 않습니다. 같은 분류를 다시 등록하면 중복 행을 만들지 않으며 최초 표시명·연식 정보를 보존합니다. 직접 입력 자료는 사용자 등록 자료로 표시하며 공식 제조사 자료를 덮어쓰지 않습니다.

## 한 번 필요한 DB 적용

이 저장소를 Cloudflare Pages에 배포해도 Supabase의 DB 구조는 자동 변경되지 않습니다. 실행 환경에는 운영 DB의 DDL 관리 권한이 없어 아래 SQL은 프로젝트 관리자가 실행해야 합니다. 새 API 키나 Cloudflare 설정값은 필요하지 않습니다.

1. 연결 프로젝트의 [Supabase SQL Editor](https://supabase.com/dashboard/project/rmlycycleuscfqywbihj/sql/new)를 엽니다.
2. [202611010005_vehicle_taxonomy.sql](../supabase/migrations/202611010005_vehicle_taxonomy.sql)의 **전체 내용**을 새 쿼리에 붙여 넣고 실행합니다. 함수 내부 일부만 선택해서 실행하지 않습니다.
3. `Success` 확인 후 S-NOTE를 새로고침하고 차량 등록을 엽니다. 이미 차량을 등록한 상태라면 화면의 **목록 저장 다시 확인**을 눌러 차종 추가를 재시도합니다. 차량을 새로 중복 등록할 필요가 없습니다.

SQL은 새 차종 테이블과 조회·추가 RPC만 만듭니다. 기존 차량·월정산·고객 자료는 변경하지 않으며 여러 번 실행할 수 있습니다. 활성 소속은 로그인 계정에서 서버가 판별합니다. 제조사·차명·세부모델은 필수이고 트림·하위트림은 선택 사항입니다.

## 저장·복구 방식

- 차량의 실제 서버 저장을 확인한 뒤 차종을 추가합니다. 두 저장은 별도 작업이므로 차량만 저장된 경우 그 사실과 차종 재시도를 안내합니다.
- 회사·계정별 재시도 항목을 이 브라우저에 보관합니다. **목록 저장 다시 확인**은 이미 등록한 차량 ID를 서버에서 대조하며, 차량을 다시 생성하지 않습니다. 연결을 복구한 뒤 재시도합니다.
- DB 적용 전에도 기존 차량 등록은 사용할 수 있습니다. 차종 목록에는 설정 SQL 안내가 표시되며, 서버 저장이 확인되지 않은 분류를 저장 완료라고 알리지 않습니다.
- 다른 회사의 분류나 과거 회사 구분 없는 IndexedDB 항목은 현재 회사에 자동 업로드하지 않습니다. 현재 상사의 구조화된 기존 차량 정보는 선택 목록에 계속 보완됩니다.
- 기존 CSV 가져오기는 현재 회사의 이 브라우저 안에서 참고하는 목록입니다. 직접 등록한 차종을 공유하는 이 기능과 별개이며 공식 자료를 덮어쓰지 않습니다.

동일 회사의 다른 기기에서 추가된 분류는 로그인·서버 새로고침·다음 차량 등록을 열 때 다시 읽습니다. 이미 입력 중인 폼은 배경 조회가 완료돼도 지우지 않습니다.
