# v2.213 페이지 배치 안정 후 fade-in

업무 메뉴를 이동할 때 화면을 먼저 표시하고 뒤이어 카드·아이콘·도구 위치를 보정하던 순서를 조정한다. 기존 권한·금융 잠금·변경 내용 확인을 모두 통과한 실제 페이지 변경 직전에 본문을 투명하게 유지하고, 기존 화면 생성·route 이벤트와 배치 보정은 그대로 실행한다. 사이드바·상단 메뉴·프로필·로그인·문서/차량 팝업은 전환 대상에 포함하지 않는다.

`display:none`이나 축소·이동 효과를 사용하지 않아 카드 폭과 줄바꿈 계산은 정상 크기로 수행된다. 본문과 최대 64개 주요 영역·카드·첫/마지막 행의 위치를 확인한다. DOM·크기·폰트·화면에 보이는 크기 미지정 이미지와 자식 영역의 로딩 상태를 확인하고, 최소 3프레임·90ms 안정 구간 이후 180ms 동안 투명도만 높인다. 재고금융 행의 기존 진입 transform도 위치 측정에 포함한다.

월정산은 기존 최초 사용 지연 로딩·권한 확인·READY/INIT·저장·인쇄 흐름을 유지한다. 늦게 준비된 iframe을 실제 표시할 때도 같은 본문 배치 확인을 한 번 적용해 초기 높이 메시지와 조정을 감춘다. 별도 iframe 선로딩이나 추가 데이터 요청은 없다.

전환 중 본문에 임시 `inert`·`aria-busy`를 적용하고 완료 후 이전 값을 복원한다. 연속 이동은 이전 토큰을 무효화하며 로그아웃의 기존 화면 초기화에서도 전환을 취소한다. 숨은 탭·페이지 종료·인쇄·모션 감소 설정 변경은 즉시 정리한다. 모션 감소 사용자는 배치 확인 후 fade 없이 표시한다. 포커스를 강제로 가져오지 않는다.

통신·폰트·반복 갱신이 끝나지 않아도 본문이 영구히 숨겨지지 않도록 동기 화면 생성 뒤 배치 확인은 최대 1초, 해당 구간의 watchdog은 1.2초로 제한한다. fade는 실제 CSS animationend로 끝내며, 브라우저가 애니메이션 시작을 늦추거나 종료 이벤트를 주지 않는 경우에만 최대 600ms의 별도 종료 타이머를 사용한다. 정상 fade 길이는 180ms다. 화면 생성 중 예외로 settle을 호출하지 못해도 begin 때 등록한 별도 watchdog이 본문을 해제한다. 최대 시간에 도달하면 현재 로딩·오류 화면도 이용할 수 있게 해제한다. 네트워크 전체 종료나 무한 로딩 애니메이션을 기다리지 않는다. 본문을 숨기기 전에 watchdog을 등록하고 예외·애니메이션 종료·종료 타이머에서 원래 표시 상태와 속성을 복원한다. 초기 로딩이 시간 한도를 넘으면 최대 15초 동안 남아 있던 로딩 영역만 확인하고, 준비가 끝날 때 한 번 더 배치를 정리해 표시한다. 이 감시는 새 메뉴 이동·로그아웃·인쇄·숨은 탭·모션 설정 변경 또는 본문에서 사용자가 클릭/키 입력을 시작하면 즉시 끝낸다. 감시 중에는 본문을 이용할 수 있다. 이미 준비된 화면에서의 일반 입력·주기적 데이터 갱신에는 전환을 다시 적용하지 않는다.

가상 인증·차량·일정·장부로 동일 Chromium 환경의 원본 de115b9와 변경본을 비교한다. 원본에서 데스크톱 매입 등록 버튼 16px·대시보드 14.16px, 모바일 설정 2.5px·대시보드 높이 195.22px의 가시중 이동을 재현했다. 측정은 메뉴별 첫 requestAnimationFrame 이후 650ms의 주요 영역 좌표를 비교하며, 통신/CPU 조건에 따라 시간이 달라질 수 있다. 실제 운영 사용자 데이터·DB·서비스 설정은 변경하지 않는다.

검증에는 실제 DOM/스타일/브라우저 프레임을 사용한다. 1440/390px의 매입·판매·설정·대시보드에서 표시 중 주요 요소의 좌표와 중간 투명도 프레임을 확인하며, 450ms 초기 응답·1.6초 늦은 응답·연속 이동·원래 속성 복원·모션 감소·숨은 탭·인쇄·오류·시간 한도 경로도 확인한다. 별도 기존 브라우저 회귀는 1440/390/320px의 내비게이션·앞/뒤 이동·금액 잠금·로그인 이력·경리 진입 5그룹을 통과했다. 월정산은 딜러/경리/관리자 1440/390px의 최초 사용·저장·인쇄·재진입 6개 조합과 지연 iframe 뒤 다른 메뉴로 이동하는 1개 사례를 통과했다. 월정산 6개 조합은 표시 제어의 최종 방어 보완 전 기능 회귀이고, 지연 사례는 준비 상태 보완 후에도 재검증했다.

측정한 화면·요소 범위의 결과이며 전체 브라우저 성능 향상 수치로 해석하지 않는다. 실물 iOS/Android 기기나 운영 계정의 데이터 변경은 수행하지 않았다.

최종 전환 브라우저 6그룹이 통과했다. 정상 전환의 8개 화면·폭 조합 모두 표시 중 주요 영역의 원시 좌표 이동이 0px였고, 원본의 최종 배치와도 같았다. 각 조합에서 0과 1 사이의 실제 투명도 프레임을 6~11개 확인했다. 450ms와 1.6초 지연, 연속 이동, 모션 감소·인쇄·속성 복원·오류/시간 초과 방어와 역할 권한도 통과했다. 이는 운영 서버 응답 시간이나 실물 기기 성능을 측정한 수치가 아니다.
