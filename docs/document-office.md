# 서류 업무 · 매입서류와 매도서류 — v2.133

경리의 메뉴명을 **서류 업무**로 변경하고 매도서류 타일을 연결합니다. 두 서류는 같은 자동차양도증명서 원본과 39개 입력 항목을 사용하며, 기존 매입 양식 기준으로 상사와 상대방의 위치를 반대로 적용합니다.

| 서류 | 상사정보·법인도장 | 상대방 이름도장 |
| --- | --- | --- |
| 매입서류 | 양도인 · 갑 | 양수인 · 을 |
| 매도서류 | 양수인 · 을 | 양도인 · 갑 |

상단 양수인 성명에 입력하면 하단 양수인 성명에도 같은 값이 입력됩니다. 양도인 성명도 같은 방식으로 동기화합니다. 하단을 직접 수정해도 상단 이름을 바꾸지는 않으며, 저장본을 열 때 기존 값을 덮어쓰지 않습니다.

상대방 성명 라벨 오른쪽의 **인감도장** 체크박스를 선택하면 현재 이름으로 만든 빨간 이름도장을 상단·하단 두 서명란에 표시합니다. 체크할 때 하단 이름도 맞춥니다. 매도서류에서는 상대방이 양도인이므로 체크박스와 생성 도장도 양도인 쪽으로 이동합니다. 이 옵션은 기존과 같이 현재 작성·출력 화면에 적용하며 고객 인증이나 제출 서명 상태를 변경하지 않습니다.

법인도장과 생성 이름도장은 이전 19pt 기준에서 **28.5pt로 150% 확대**합니다. 이미지 비율을 유지하고 원본 이름·전화·날짜·하단 용지 문구와 실제 잉크가 겹치지 않도록 배치합니다. 가로·세로 비율이 2를 넘는 회사 도장은 다른 글자를 가릴 수 있어 안내와 함께 출력을 중단합니다. 원본 PDF와 앞뒤 SVG, 양면 A4 2장 구성은 유지합니다.

문서 종류는 39개 입력값 밖의 `document_kind` 메타데이터로 저장합니다. 새 매입·매도 문서는 다른 ID로 만들며 목록·다시 열기·수정 저장은 종류별로 구분합니다. 저장 후 종류를 바꿀 수 없습니다. 이전 문서는 `purchase`로 유지하고, 이전 버전의 계약서 RPC는 매입 문서만 읽고 수정하도록 제한해 매도 문서에 잘못된 위치로 도장을 찍지 않게 합니다.

[문서 종류 SQL](../supabase/migrations/20261118134644_transfer_document_kinds.sql)을 운영 DB에 적용했습니다. 기존 필드·작성자·시간·리비전 보존, RLS·권한과 새 RPC를 확인했고 실제 관리자·경리 역할의 합성 문서 검증은 롤백했습니다. 임시 검증 문서는 남기지 않았습니다. 상세 결과는 [검증 기록](document-office-verification.json)에 있습니다.
