# 단계별 개선 검토 기록

작업 기준은 최신 `main`의 `6a569c5b45f3239ec82898871f66cbd8a2526b08`(v2.183)이다. 요청에 적힌 v2.182는 비교 기준으로만 취급했다. 작업 브랜치는 `codex/staged-audit-v2184`이며 사용자의 승인 전 main 병합·운영 배포를 하지 않는다.

## 보존 범위

- v2.183의 삭제 고객 출력, 계약서·인수증의 문서 오른쪽 위 세로 닫기/인쇄 버튼을 유지한다.
- 기존 `codex/vehicle-business-v2181`과 다른 worktree의 미완료 작업은 유지하고 이번 브랜치에 가져오지 않는다.
- 운영 데이터, Supabase 운영 설정·스키마, Cloudflare 설정, NAS·백업 연결을 변경하지 않는다. 모든 쓰기 시험은 가상 응답 또는 격리된 로컬 PostgreSQL에서만 한다.
- 제거하는 공개 기본값의 원문은 신규 테스트·보고·커밋 설명에 기록하지 않는다. 과거 Git/배포 이력 정리는 별도 검토 대상이다.

## 진행 순서와 통과 조건

1. 공개 선재고 기본값 제거, 회사 범위의 기존 설정 보존, 판매 후 금융 잔액·중복 장부 집계, 판매 확정 검증을 수정하고 데이터/권한 회귀를 통과시킨다.
2. 1단계 통과 후 로그인 초기 로딩과 금융 중복 요청, 엔카 오류 진단·동시 요청을 수정하고 기존 인증/잠금/재시도 회귀를 검사한다.
3. 앞 단계 검증 후 모바일 업무 순서·매입 보조 메뉴·정상 크기 문서 편집을 구현한다. 360/390/430px와 키보드 축소 상태, 데스크톱 및 원본 A4 출력을 검사한다.

## 이미 확인한 기능

- 인증된 active 회원·상사 확인, 금융 잠금/세션 확인 전 업무 화면 감춤이 존재한다.
- 사진·미디어는 로그인 이후 백그라운드로 로딩한다.
- OCR 엔진은 최초 OCR 요청 시 로딩한다.
- 엔카 서버의 확정된 검색 결과 없음은 HTTP 200으로 구분하고, 저장 광고 주소의 직접 열기·재시도·차량/계정 변경 가드가 존재한다.
- 90일 장기재고 판정과 회사/소유자 범위의 대시보드 가드를 유지한다.

## 속도 측정 범위

운영 계정으로 실제 로그인하는 계측은 수행하지 않는다. 실제 앱과 가상 Auth/DB 응답을 연결한 동일 조건 시험에서 클릭 → 인증 응답 → 회원/상사 확인 → 데이터/잠금/세션 확인 → 첫 업무 조작 가능 시점과 요청 수를 비교한다. 이 수치는 운영 로그인 지연의 측정값이나 보장값이 아니다. 운영 수치는 추정하지 않으며 추후 수동 측정 절차를 결과에 남긴다.

## 검증·커밋

단계별 결과와 커밋은 구현과 검증 완료 후 이 문서에 추가한다.

### 1단계의 원본과 보존 규칙

- 선재고 설정의 원본은 회사 공통 `zc_datasets`의 `finance_limits` 내 `_snote203_meta.prestock`이다. 원본 저장 구조를 유지하고, 인증된 읽기 결과를 현재 상사·사용자·클라이언트에 묶어 화면에 사용한다. 미등록은 0원이나 공용 계좌가 아닌 ‘미설정’이다.
- 연결 차량의 `inventoryLoan`은 남은 원금이다. 금융 입력과 차량 상세 저장이 이 값과 별도 `finance` 장부를 함께 갱신하는 구조를 확인했다. 명시적 0원은 완납이며, 오래된 중복 장부가 이를 되살리지 않도록 한다. 필드가 없는 구형 차량만 검증된 장부로 보완한다.
- 같은 상사·담당자의 차량 ID 연결을 우선하고, ID 없는 구형 장부는 같은 담당자 내 번호판이 유일한 경우에만 연결한다. 재매입 등으로 연결이 모호하면 채무를 임의 삭제하거나 과거 장부를 고치지 않고 별도 내역으로 유지한다. 퇴사자에게 연결된 미상환 채무도 확인된 회사 장부 범위 안에서 보존한다.
- 현재 재고투자금은 기존대로 판매 차량을 제외한다. 미상환 금융 목록·한도 사용액은 판매 상태와 별도로 남은 원금만 합산한다.
- 판매 날짜·실판매가 보호는 새 판매 사실 또는 수정한 판매 사실에만 적용한다. 메모/비용 편집 때 과거 오류를 자동 정정하지 않는다. 정상 휴지통 복원과 실패한 저장의 원본 복원을 검증한다.
- 판매 최종 쓰기 경계 SQL은 `20261122052042_sale_completion_validation.sql`이며 운영 미적용이다. 승인 후 별도로 적용해야 서버와 기존 모바일 클라이언트의 쓰기에도 보호가 활성화된다.

### 1단계 통과 기록

통합 코드 `34458b9`에서 금융/설정 두 탭의 조회·CAS·지연 응답(1440/390px) 및 금융 복구 30건·기존 복구 통합 17건을 포함한 관련 단위 시험 7개 파일이 통과했다. 판매 브라우저는 과거 잘못된 날짜/누락 가격의 메모 편집, 실제 판매가 확인, 저장 실패 원본 복원을 PC/모바일에서 통과했다. 로컬 PostgreSQL 판매 27건과 새 trigger를 함께 적용한 휴지통 보호 74건도 통과했다. 기존 핵심 모음 431건과 회사 조회·딜러 이율 12그룹은 통과했다. 운영 데이터 시험은 없다.

데이터/권한 관련 신규 실패를 해결한 뒤에만 2단계 제품 변경을 시작한다. 기존 경리 UI 회귀에는 현재 화면명과 오래된 기대값의 불일치가 있고, 전체 로그인 회귀에는 기존 확인창 fixture 대기가 남아 있다. 전자는 현 화면명을 되돌리지 않으며, 후자는 2단계의 로그인 검증에 포함한다. 자동 로그아웃과 금융 범위의 독립 회귀는 통과했다. 자세한 저장 범위·구형 복구 기록 한계는 `staged-finance-scope-review.md`, 판매 SQL은 `staged-sale-validation.md`에 있다.

추가 등록 회귀에서 신규 차량 저장이 기존 차량 변수에 접근하는 오류를 발견했다. 2단계 통합을 보류하고 신규 등록의 날짜 검사를 독립적으로 수정했다. 기존 등록 시험도 비동기 상세창 닫기와 메뉴 전환을 완료한 뒤 등록을 시작하도록 맞췄다. 수정 후 1440/390/320px의 실제 저장 ACK, 실패·응답 유실 재시도, 계정 전환, 최초 행 표시, OCR 입력 보존과 상세 재편집을 포함한 전체 등록 회귀가 통과했다. 오래된 금융 범위 시험도 실제 인증 스냅샷 fixture에 맞춰 갱신해 9건 통과했다. 제품을 과거 시험의 공용 캐시 가정으로 되돌리지 않았다.

### 2단계 통과 기록

통합 코드 `043310b`에서 기존 핵심 시험 434건 전부, 최초 사용 브라우저 9그룹, 엔카 PC/모바일 전체 18그룹이 통과했다. 로그인 시작 단위 시험은 실제 기본 정보·최초 문서정보 helpers를 함께 실행하는 8건으로 갱신했다. 인증 전에 회사 자료를 읽지 않으며 필수 회사/회원 실패, 선택 정보 fallback, 다른 계정·클라이언트·회사·사용자 객체로 바뀐 지연 응답을 차단한다.

로그인 초기 카탈로그 요청은 7→3, 문서/인쇄 관련 요청은 15→8, 금융 동선의 같은 이율 재조회는 2→1회로 줄었다. OCR 엔진은 원래 최초 사용 로딩이므로 유지했다. 고정 150ms 가상 응답·PC/모바일 각 3회의 비교는 **클릭 이후 시간 개선을 입증하지 못했다**. 운영 수치로 추정하지 않는다. 단계별 수치, 변동 범위, 첫 사용/금융·문서 회귀, 실제 로그인 측정 절차는 `staged-login-review.md`와 `staged-login-measurements.json`에 보관했다.

엔카는 HTTP 200의 검증된 결과 없음만 부재로 취급한다. 503/모순 응답은 오류이며, 서버 오류 로그는 요청 ID·고정 단계·소요 시간만 포함한다. 요청마다 인증/활성 회원을 확인한 뒤 같은 실행 인스턴스 안의 동일 범위 검색만 공유한다. 개별/전체 취소와 재시도·저장 링크 직접 열기는 유지한다. 실제 컴파일된 Workers 검색 21모드·가격 8모드와 단위 173건도 통과했다. 실서비스의 503 원인·차단 여부는 미확인이다(`encar-stage2-audit.md`).

이 통합 검증 통과 후 3단계 모바일 제품 변경을 시작한다. main 병합·운영 배포는 보류 상태다.

### 모바일 통합 전 금융 추가 게이트

모바일 변경은 별도 worktree에서 검증하되 금융의 실패 원복 경로에서 공용 raw 캐시를 백업으로 쓰는 문제를 발견해 루트 통합을 보류했다. 원복 역시 회사별 인증 원본·현재 권한으로만 수행하도록 고쳤다. 선재고 잔액이 다른 탭의 원장과 계산되지 않도록 보호 범위를 `finance`·`finance_limits`·`prestock` 세 본문으로 확대했다. 선재고의 인라인 수정·추가·상환과 보존된 상세 원복·idle 복구도 같은 기준이다.

bulk 응답에서 빠진 금융 행은 기존 행을 중복 읽지 않고 고유한 회사/종류/공통 소유자 조건으로 실존을 확인한다. 확인된 빈 설정은 ‘미설정’, 조회 실패는 ‘미확인’이며 변경을 막는다. 원본이 확인되지 않은 상태에서 미상환·한도 합계를 ready 0으로 반환하지 않는다. 딜러의 공용 선재고 원문 읽기는 기존 RLS가 허용하지 않으므로 차량의 기존 선재고 표시는 보존하되 장부 금액을 추정하지 않는다. 기존 원장·이력·권한 정책을 수정하거나 구형 raw 원장을 자동으로 가져오지 않는다.

최종 금융 통합 `e268aa7`의 파일 트리 `f13200506f5f319b39c30480bdc20464b1344969`는 검증 담당의 동결 트리와 동일하다. 단위 97건, 보존한 실제 권한 정의의 로컬 PostgreSQL 20건, PC/모바일 34그룹(두 탭·실패 원복·CAS·누락 원본 확인·실패/실제 미설정·기존 인라인·시작일·이자·부분/완납) 및 문법/공백 검사를 통과한 뒤 모바일 변경을 통합한다. 운영 자료·설정 변경은 없다. 세부 기록은 `staged-finance-rollback.md`, `staged-financial-source-completeness.md`, `staged-prestock-ledger.md`에 있다.

### 3단계 변경과 검증 범위

모바일 홈에서는 ‘오늘 처리할 일’을 KPI보다 앞에 배치하고 기존 90일 장기재고 판정을 유지했다. 딜러의 판매 진행은 확인된 본인 계약중 차량만, 경리의 서류 미완료·미상환은 회사·역할·저장 상태·금융 원본 및 최신 전체 미디어 수신이 확인된 경우만 표시한다. 모르는 상태는 0건 대신 ‘확인 중’이다. 경리의 시작 화면은 기존 업무 메뉴이며 대시보드 권한을 새로 부여하지 않았다.

모바일 매입 화면은 원래 등록 버튼을 ‘+ 차량 등록’으로 표시하고 OCR·보기·열 설정·정렬의 원본 노드를 보조 메뉴에 모았다. 데스크톱에서는 기존 위치로 복원한다. 권한·이벤트를 복제하지 않고 동일 노드를 사용하며, 메뉴 안에서 자식 팝업을 열고 닫아도 메뉴와 초점을 유지한다. 밝은 하늘색 배경은 화면에만 적용했다. 공통 기본 버튼의 흰 글자 대비 5.573:1은 이미 충족해 유지했고, 미달한 OCR 버튼만 보완했다.

계약서·인수증은 모바일에서 16px 글씨와 44px 이상 입력칸을 사용한다. 키보드의 가시 영역 변화에 맞춰 편집 영역만 스크롤하며, 원본 입력 이벤트·저장·서명 보호를 그대로 사용한다. 지연 로딩·회사/계정/차량/화면 변경과 IME·전화번호/금액 구분자 삭제를 검증했다. 데스크톱 양식과 A4 계약서 2장·인수증 1장, 서명 위치는 유지했다. 새 본체는 문서 첫 사용 때만 내려받는다.

독립 동결 소스에서 문서 8개 suite, 홈 7뷰, 매입 도구 4뷰와 기존 홈 4규격을 검증했다. 최종 통합본의 추가 검증은 아래에 구분한다. 자세한 화면·판정 근거는 `staged-mobile-home.md`, `staged-audit-mobile-documents.md`에 있다. 실제 OS 키보드를 사용한 실기기 시험은 수행하지 않았고 Chromium의 `visualViewport`와 조합 이벤트를 모의한 결과다.
