# 첫 화면·로그인 로딩 검토

기준은 최신 main `8835e793dc666ca6f725048fd8e8ffde6150537d`(v2.184)이다. 시작 시 작업 트리는 clean이었으며 `codex/startup-loading-v2185`를 이 main에서 새로 만들었다. 운영 자료·DB/권한·NAS/백업 설정을 변경하거나 main 병합·배포하지 않는다.

## 변경 전 흐름

- 메인 HTML의 숨은 월정산 iframe에 `monthly.html?v=2.135`가 있어 로그인 전부터 문서와 공통/장부 자산을 받는다. 준비/로그인 후 초기화 hook도 현재 메뉴 조건 없이 실행될 수 있다.
- 차량 분류 script·분류 UI·소득정산 부모 script의 정적 태그는 v2.184에서 이미 제거됐다. 차량 등록/상세의 최초 catalog import 때 JSON을 읽는다. 관련 기능의 화면·원본 차종 보호와 기존 직접 입력을 재구현하지 않는다. JSON 실패 후 같은 rejected ready Promise를 재사용하는 경로와 import 재시도는 별도로 검증한다.
- `readCompany()`는 기본 회사 정보 1회와 소속/역할을 확인한다. 문서용 회사 프로필은 문서 최초 사용 때 별도로 확인하므로 로그인 때의 중복 회사 조회는 이미 제거돼 있다. 필드 호환 fallback과 지연 응답 검사는 유지한다.
- `enterWorkspace()`는 금융 잠금·유휴/세션 정책과 대시보드 수익 표시 설정을 모두 기다린다. 표시 설정만 필수 진입 대기에서 분리할 수 있는지 검증한다. 나머지 인증·역할·잠금 보호를 유지하고, 표시 설정 확인 전에는 기존 숨김 범위의 금액을 숨긴다.
- 금융사 복원은 서버 설정 수신 직후와 최신 딜러 금리 조회가 함께 끝난 뒤 실행된다. 두 번째는 최신 금융사 이름을 반영할 수 있으므로 단순 중복 요청으로 보지 않는다. 계좌·장부의 읽기/저장 구조는 이번 작업에서 바꾸지 않는다.
- OCR은 실제 분석 시, 회사 이미지/문서 도구는 최초 사용 시 불러오도록 이미 분리돼 있다. 계산기·서명·로그인 배경 등 다른 기능의 전면 변경은 하지 않는다.

## 검증 원칙

동일한 가상 Auth/데이터 지연과 실제 로컬 자산 서버에서 변경 전후를 비교한다. cold/warm 캐시, 로그인 표시·인증 응답·업무 준비·차종 선택·월정산 첫 사용을 구분한다. 실제 수신량을 관측할 수 없는 경로를 전송량 추정치로 채우지 않는다. 이 수치는 운영 서버 지연이나 실사용 속도로 간주하지 않는다.

## 표시 설정을 진입 대기에서 분리

대시보드 표시 설정은 우선 네트워크 없이 숨김·로딩 상태로 준비한다. 금융 잠금과 유휴/세션 정책은 기존처럼 기다리고, 첫 업무 화면을 그린 뒤 표시 메타데이터를 읽는다. 빠르게 설정 메뉴를 열어도 기존 설정 항목이 사라지지 않도록 준비 단계의 비활성 markup을 유지한다. 설정 확인 전 수익은 `-`로 표시되며 실패하면 숨김을 유지한다. 다른 계정/상사/클라이언트로 바뀌면 지연 시작·응답을 적용하지 않는다.

추가 브라우저 10개 시나리오(딜러/관리자, 1440/390px)는 선택 설정을 보류·실패시켜도 필수 잠금 완료 후 진입 가능하고, 필수 금융 정책을 보류하면 진입할 수 없음을 확인했다. 준비/지연 로딩·기존 설정과 회사 프로필의 단위 19건도 통과했다. 원본 표시 설정 저장과 금융 접근 권한은 바꾸지 않았다.

## 측정 방법과 범위

동일한 Chromium, localhost gzip HTTP 서버, 1440/390px, 딜러/관리자/경리, cold/warm 각 3회로 변경 전후 각 36회(총72회)를 순차 측정한다. 기준은 `8835e79`, 변경 후 제품은 `39b00ef`이다. Auth/DB는 합성 fixture에 고정 150ms를 적용했고 운영 HTTPS/WSS 요청은 차단한다. 서로 다른 결과·준비 기준을 섞지 않는다.

로그인 표시는 실제 layout/enabled를 확인한 프레임이며 FCP는 별도다. 로그인 클릭→업무 사용 가능은 초기 `networkidle` 후 클릭해 측정한다. 대시보드는 데이터 ready와 실제 업무 버튼 enabled/visible, 경리는 회사 정보 검증과 서류 버튼 enabled/visible, 공통으로 앱이 inert하지 않은 상태까지 확인한다. 인증 ACK, 회사 확인, 필수 자료, 정책 확인도 클릭 기준으로 나눠 기록한다. 첫 기능은 딜러의 차종 선택 가능 시점, 관리자/경리의 편집 가능한 첫 월정산 양식까지다.

cold는 새 browser context로 HTTP cache/IDB가 비어 있는 접속이고 OS file cache 초기화를 뜻하지 않는다. warm은 같은 context의 HTTP cache와 IDB를 유지하되 Auth localStorage를 비우고 다시 명시적으로 로그인한 경우다. 자동 세션 복원 성능은 포함하지 않는다. HTML no-store/정적 자산 max-age=3600은 통제한 로컬 정책이며 운영 CDN 정책을 관측한 것이 아니다.

자산 수신량은 실제 HTTP 응답에 대한 Chromium CDP `encodedDataLength`이며 header를 포함한다. cache hit를 포함한 resource event 수와 실제 wire response 수를 구분한다. 초기 자산은 업무 준비+350ms까지다. Auth/DB의 합성 binding은 논리 호출 횟수만 측정했고 HTTP 전송량이나 실제 SDK 다운로드·파싱 비용은 추정하지 않았다. 운영 속도 개선 보장값이 아니다.
