# 금융 원본 조회의 완료 여부

bulk `zc_datasets` 조회가 서버의 행 제한으로 잘렸을 때, 응답에 없는 공유 원장을 바로 미설정 배열로 간주하지 않는다. 관리자·경리의 `finance`, `finance_limits`, `prestock` 중 bulk 응답에 없던 행만 기존 공유 키(company, dataset, NIL owner)의 `maybeSingle` 조회로 확인한다. 이미 받은 행은 다시 조회하지 않고, 누락 확인은 병렬 실행한다. 공유 원장의 읽기 권한이 없는 역할에는 추가 조회를 하지 않는다.

정확한 조회의 null 응답만 실제 미설정으로 확인한다. 조회 실패·범위 변경·잘못된 회사/owner/버전/payload 또는 중복 응답은 원본 미확인 상태로 남긴다. 비표준 owner의 공유 금융 행을 임의로 현재 공유 키에 매핑하거나 자동 정정하지 않는다. 기존 정상 server 행과 단위는 그대로 보존한다.

차량 원장만 준비된 상태에서 금융 원장이나 금융사 설정 snapshot이 없으면 금융 합계를 ready=true의 0 또는 이전 한도로 반환하지 않는다. 미확인 금융 설정과 원장의 저장도 거부한다. 이는 별도의 설정 안내 흐름이나 DB 정책 변경을 추가하지 않는다.

검증은 가상 원본과 실제 restore/집계/저장 함수를 사용했다. 1440/390px에서 bulk 행 누락을 정확 조회로 복구하고, 정확 조회 실패는 차량 조회 성공과 구분하며, 설정·원장 저장 거부, 재시도와 실제 미설정 확인을 검증했다. 원본 helper 11건, 금융 범위 10건, 기존 금융 복구 30건과 복구 통합 17건도 통과했다. 운영 DB·설정은 조회하거나 변경하지 않았다.
