# v2.255 중복 작업·불필요 코드 정리

기준은 최신 main `aeaf75209c2fa90af8776345499a74587ac94685`이다. 기존 v2.185·v2.253 최적화를 확인하고, 반복이 실제 재현되거나 호출자가 없는 경로만 변경했다. 기능·화면 크기·스타일·권한·저장 형식은 유지한다.

## 적용 내용

| 범위 | 이전 작업 | 변경 |
|---|---|---|
| 계산기·튜토리얼 | 로그인에서도 본체와 계산 모델을 내려받음 | 작은 기존 API 연결부를 두고 최초 사용 때 공용 로더로 내려받음. 동시 클릭은 공유하고 실패 시 재시도하며, 그동안 메뉴·계정·포커스·팝업 상태가 바뀌면 늦게 열지 않음 |
| 관리자 차종 진단 | 모든 접속에서 본체와 200ms 권한 감시 시작 | 확인된 관리자 설정 화면에서 처음 로딩. 로딩 후의 기존 권한 감시는 유지 |
| 메뉴 재정렬 | 무관한 본문 변경에도 메뉴를 다시 검색하고 같은 class·ARIA 기록 | 메뉴 삽입·교체·직접 자식 변경·경리 고정 메뉴·계정 변경은 계속 감시하고, 무관한 변경과 같은 값의 기록만 제외 |
| 매입·판매 현황 | 권한·자료 확인을 반복할 때 같은 안내 DOM 교체 | 확인은 계속 수행하고, 표시가 실제로 달라질 때만 다시 그림 |
| 엔카·차량 상세 탭 | 같은 hidden·disabled·title·tabindex 반복 기록 | 기존 조회·가격·권한·재시도 로직을 유지하고 값이 달라질 때만 기록 |
| 구형 모델 참고사진 | 현재 기본 이미지에 쓰지 않는 사진을 매번 추가 조회·다운로드·Blob URL 생성 | 차량 미디어 갱신의 자동 호출 두 곳 제거. 실제 차량 사진·서류 조회와 기존 모델사진 자료·저장 함수·IDB 이전은 보존 |
| 미사용 함수 | 예전 CSV 가져오기·이미지 생성·OCR 진단 등 호출되지 않는 함수 12개 | 실행 진입점과 다른 자산·테스트의 전역 참조를 확인한 뒤 제거. 현재 카탈로그 내보내기·OCR·차량 기본 이미지·금융 회귀용 함수는 유지 |

다른 문서와 iframe의 공통 코드는 문서마다 필요하므로 제거하지 않았다. 금융사의 두 단계 정규화·최신 금리 반영, 프로필의 본인 확인, 상사·세션·역할 및 금액 잠금 검사를 중복으로 취급하지 않았다. 예전 이미지·폰트 파일과 DB 마이그레이션·백업·연구 자료는 캐시 호환과 자료 보존을 위해 유지했다. 미참조 자산을 지워 현재 전송량이 줄었다고 계상하지 않는다.

## 검증

- 핵심 `tests/encar`의 `npm test`: 438개 통과.
- 새 `optional-tools.test.cjs`: 25개 통과. 첫 사용·공유 로딩·실패 재시도·화면/계정/포커스/팝업 변경 취소를 확인했다. 월정산 iframe 포커스와 import 완료의 경합, 실제 공통 알림의 확인 버튼·수명, 페이지 숨김 때 상담 polling 재시작 방지도 검사했다.
- 새 `render-work-idempotence-v2255.test.cjs`: 10개 통과. 실제 변경·권한 취소·메뉴 교체·역할 변경은 계속 반영한다.
- 새 `unused-model-photo-refresh-v2255.test.cjs`: 6개 통과. 실제 사진·서류, 실패한 미리보기의 서류 집계, 지연 응답 뒤 계정·상사 전환 보호와 기존 자료 호환을 확인했다.
- 기존 매입·판매·계산기 모델 25개와 미디어 완결성 검증 통과. 별도 엔카 deadline·가격 24개도 통과했으며 핵심 모음과 겹치는 항목을 새로운 총계로 더하지 않았다.
- 운영 HTML 7개의 중복 ID·동일 자산 태그와 JS/CSS 242개의 완전히 같은 파일 복제를 검사했으며 발견하지 못했다. JS와 HTML 인라인 스크립트 162개의 구문 검사를 통과했다.
- 독립 리뷰에서 발견한 계산기 로딩 중 외부 포커스·새 팝업의 늦은 열림을 보완한 뒤 재검토를 통과했다.

가상 모델사진 3장과 실제 차량 미디어 2장을 넣은 동일 비교에서 메타 조회 2→1회, 다운로드와 URL 생성 각 5→2회였다. 차량 사진·서류 결과는 같고 기존 모델사진 자료를 지우지 않는다. 초기 본체 소스 60,406B를 5,782B 연결부로 대체했다. 이는 압축 전 파일 크기이며 운영 전송량·로그인 소요 시간의 측정값이 아니다.

## 브라우저 전후 비교

같은 가상 응답·화면 크기로 원본 자산을 제공한 경우와 수정 자산을 제공한 경우를 비교했다. 로그인 후 최초 대시보드까지의 HTTP 응답 수와 가상 응답 본문 길이 합계이며, SDK 내부 호출 계수는 별도로 비교했다.

| 계정·가로 크기 | 요청 수 | 가상 응답 본문 B | 미디어 포함 SDK 읽기 | 1.2초 무조작 DOM 변경 |
|---|---:|---:|---:|---:|
| 딜러 1440px | 210→207 | 7,646,615→7,583,502 | 6→5 | 17→0 |
| 딜러 390px | 209→206 | 7,597,281→7,534,168 | 6→5 | 21→0 |
| 경리 1440px | 208→205 | 7,589,326→7,526,213 | 6→5 | 15→0 |
| 경리 390px | 207→204 | 7,539,992→7,476,879 | 6→5 | 21→0 |

각 조건에서 초기 HTTP 요청은 3개, 가상 응답 본문은 63,113B 감소했다. 필요해진 기능의 첫 사용 시에는 해당 자산을 정상 요청한다. 차량 상세의 분류 데이터는 차종 편집 의존성이 있어 유지하며, 이를 삭제한 것처럼 계상하지 않는다.

실제 Chromium에서 무관한 본문 변경 20회 시 메뉴 속성 기록 130→0회, 메뉴 context 검사 60→0회를 확인했다. 매입·판매의 미확인·로딩 네 상태는 각각 2250ms 동안 childList 기록 4→0회였고 기존 안내 노드를 유지했다. 새 자료·scope 변화, 키보드 재정렬 저장, 새 메뉴 삽입과 경리 고정 메뉴는 정상 반영됐다.

가상 응답 interception은 브라우저 캐시를 비활성화하므로 재접속 결과는 세션 복원 동선으로만 해석한다. 운영의 압축 전송량·warm cache·로그인 소요 시간 개선을 뜻하지 않으며 실제 운영 수치는 추정하지 않았다. fixture 시계 때문에 Performance Resource Timing 목록이 비어 있어 HTTP 계수는 context의 request/response 이벤트를 사용했다. 빈 목록으로 동일 URL의 중복 전송 여부를 판정하지 않는다.

딜러·경리 PC/모바일 4조건의 총 24개 화면 상태와 세션 복원 동선을 확인했다. 화면의 가로 넘침은 없었고 무조작 중 기록되던 15~28개의 반복 속성 변경은 0개가 됐다. 기존 `normal-login.browser.cjs` 전체 10그룹도 통과했다. 인증·활성 소속·금액 잠금 전 업무 진입 차단, 비밀번호 재시도, 명시 로그아웃·유휴 로그아웃, 느리거나 실패한 사진 조회와 로그아웃 뒤 지연 응답을 확인했다.

추가 브라우저 검증:

- `node tests/optional-tools-v2255.browser.cjs`: 실제 온라인 화면의 9개 검증 통과. 첫 사용·연속 클릭·계산과 재열기, 계산기 본체/모델/튜토리얼 실패 후 실제 오류 확인·새 URL 재시도, 메뉴·포커스·Esc·모바일·월정산 iframe 변경 후 취소를 확인했다.
- 기존 튜토리얼은 PC 1440/1024/850px에서 27개 실사진과 검색·이전/다음·확대·권한별 이동, 이미지 실패 복구를 확인하고 모바일 390/320px의 숨김 정책을 통과했다. 최종 수명주기 3규격을 별도로 재실행해 닫기·Esc·계정 변경·pagehide 중 polling 정지·pageshow 재개를 확인했다.
- 모바일 챗봇 기존 6그룹, 관리자 차종 진단 기존 7그룹, 운영자 재정렬 1그룹 통과. 채팅의 같은 문구 선택자는 채팅 패널 안으로 한정했고, 진단의 토큰 기대값은 fixture가 실제 발급한 합성 JWT를 공유하도록 고쳤다. 토큰·권한·지연 응답 검증은 유지했다.
- 서류 목록의 권위 메타데이터·회사 분리·공유 권한 3그룹과 본인 차량 데스크톱 검증 통과. 미리보기 다운로드가 실패해도 서류 집계를 유지하고, 반복 렌더는 추가 조회를 하지 않으며, 공유 회수·계정 변경 후 이전 자료를 표시하지 않는다.

기존 테스트의 한계도 구분한다. `quick-calculator.browser.cjs`는 원본 main에도 없는 `initializeAuth();` 실행 구문을 찾아 시작하지 못하므로 전체 통과로 계상하지 않았다. 현재 온라인 경로의 새 브라우저 9개와 계산 모델 15개로 검증했다. 예전 서류 목록 전체 모음은 데스크톱을 통과한 뒤 모바일의 숨겨진 보기 전환·문서 표시 전제에서 중단되어 전체 통과로 계상하지 않았다. 현재 모바일 보조 메뉴를 통해 보기 전환하도록 helper와 조회 기대값만 보완했고, 관련 메타데이터 3그룹은 별도로 통과했다. 튜토리얼 전체 모음의 최초 실행에서 발견한 pagehide 회귀는 수정 후 수명주기 3규격을 재실행했으며, 내용·이미지와 수명주기를 분리 실행한 결과를 한 번의 전체 실행으로 표기하지 않았다.

실제 고객 자료·운영 DB·Cloudflare 설정·NAS·백업 연결은 변경하지 않는다. 로고와 Pretendard의 원본 SHA256, 상사 로고·도장·서명과 A4 양식은 보존한다.

비공개 파일의 사용자 인증·RLS 경로는 [Supabase Storage 문서](https://supabase.com/docs/guides/storage/buckets/fundamentals#private-buckets)를 대조했고 변경하지 않았다. 브라우저 측 회귀는 가상 Auth/DB·생성 이미지로 수행하며 실제 운영 계정·저사양 PC·실물 프린터/스캐너와 운영망의 전송량·캐시는 미검증이다.
