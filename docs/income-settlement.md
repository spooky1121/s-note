# 차량별 소득정산

판매 완료 목록에서 각 차량의 맨 오른쪽 **소득정산** 버튼을 누릅니다. 딜러는 본인 차량을, 관리자와 경리는 같은 상사의 차량을 정산할 수 있습니다. 휴대폰 목록에도 같은 버튼이 있습니다.

첨부받은 엑셀의 A1:J52 양식, 병합 셀과 51개 수식을 사용합니다. 원본 파일에 있던 실제 이름·차량번호·주민등록번호·정산 금액은 배포 파일에 포함하지 않습니다. 각 차량의 DB와 정산서에서 직접 입력한 값으로 채웁니다.

## 입력과 계산

노란 칸은 직접 수정할 수 있고 계산 결과는 즉시 바뀝니다. `수식 보기`로 계산 칸의 원본 수식을 확인합니다. 금액 단위는 **원**이며 차량 DB의 만원 금액은 원으로 변환합니다.

| 정산서 항목 | 자동 입력 기준 |
| --- | --- |
| 상사, 딜러 | 현재 상사명, 차량 소유 직원의 이름 |
| 차명, 차량번호, 연식 | 해당 차량 정보 |
| 매입일, 매출일 | 매입일, 실제 판매 완료일 |
| 매출액 D8 | 실제 판매가. 판매 예정가는 대신 사용하지 않음 |
| 재활용 매입액 D11 | 매입가. 요청한 기본 구분이며 변경 가능 |
| 취득세 D31 | 차량에 기록된 취득세 |

매입금액 구분에서 재활용매입(D11), 세금계산서 매입(D10), 직접 입력을 선택합니다. 판금·광택·광고·수리 등의 차량 비용은 옆에 참고로 표시합니다. 증빙을 확인하고 **세금계산서 수취분으로 넣기**를 눌러 반영합니다. 차량 DB에는 세금계산서 수취 여부가 없으므로 비용을 자동으로 이 항목에 넣지 않습니다. 수리 내역과 합계의 중복을 피하고 기존 소득세·대출 원금도 다시 비용에 넣지 않습니다.

## 원본 수식에서 확인할 부분

다음은 첨부 엑셀의 실제 수식을 그대로 유지한 부분입니다.

- 재활용매입 항목은 `10/110`이라고 적혀 있지만 F11의 실제 수식은 `=ROUND(D11/1.09,0)`입니다. 화면에 이 차이를 안내합니다.
- 타차량 적자분 D40은 D41에서 **더합니다**. 차감할 금액은 음수로 입력합니다.
- H35는 병합된 빈 셀 I30:I32를 합하는 원본 참조를 유지하며 I36의 합계에도 별도로 추가하지 않습니다.
- 매입비 차액 I39와 딜러소득세 H51은 별도 입력 칸입니다. 다른 금액과 임의로 연결하지 않습니다.
- 매입 소득세는 D41의 3%를 10원 미만 버림하고, 지방소득세는 그 소득세의 10%를 다시 10원 미만 버림합니다. 중개수수료 정산도 원본 수식대로 계산합니다.

## 저장과 다시 불러오기

**서버 저장**을 누르면 실제 저장 응답을 확인한 뒤 저장 완료로 표시합니다. 정산서를 닫았다가 같은 차량에서 다시 열면 저장한 내용을 불러옵니다. 입력 중인 내용을 브라우저에 임시 보관하되 주민등록번호는 임시 보관하지 않습니다. 임시본 복구 시에는 서버에서 읽은 주민등록번호를 유지합니다.

차량 원본 정보나 다른 화면의 정산서가 바뀌면 작성본을 유지하며 확인 화면을 띄웁니다. 변경된 차량 정보를 반영할 때 직접 수정했던 칸은 유지합니다. 저장 결과를 받지 못하면 같은 요청으로 재확인하여 중복 저장과 잘못된 완료 표시를 피합니다.

기존 `cars` 데이터의 해당 차량 `incomeSettlement` 항목만 서버에서 갱신합니다. 서버가 최신 차량 목록을 읽어 기존 `zc_write_dataset`의 리비전 확인을 거쳐 저장하므로 같은 목록에 있는 다른 차량과 관련 없는 항목은 보존합니다. 저장 응답 중 로컬 차량 목록에 다른 변경이 생겼다면 리비전을 임의로 올리지 않고 목록 새로 불러오기를 안내합니다.

중개인 주민등록번호 H50은 기존 `CUSTOMER_INTAKE_OTP_SECRET`의 키 구성을 사용하되, 고객정보와 별도의 HKDF/AES-GCM 범위로 암호화합니다. 상사·소유 직원·차량을 암호화 범위에 묶습니다. 일반 차량 캐시에는 평문 번호를 넣지 않고 권한을 확인한 정산서 응답에서만 복호화합니다. 암호화 키를 읽지 못하면 기존 번호를 지우거나 저장 완료로 처리하지 않습니다.

## 인쇄와 배포

**인쇄 / PDF**를 누르면 판매 상태와 서버 변경 여부를 확인한 뒤 현재 정산서를 A4 세로 한 장으로 출력합니다. 미저장 작성본을 출력할 때는 출력물에 그 상태를 표시합니다. 화면의 버튼과 참고 비용 패널은 출력하지 않습니다.

이번 기능을 위한 별도 SQL이나 새 환경변수는 없습니다. 기존 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`와 주민등록번호 저장에 사용하는 기존 암호화 키 구성이 필요합니다. 로컬 예시 자료에서는 계산·인쇄를 사용할 수 있고 서버 저장은 온라인 로그인 후 가능합니다.

배포에는 `index.html`뿐 아니라 `income-settlement.html`, `assets/income-settlement*`, `functions/api/income-settlement.js`, `_headers`를 함께 포함합니다.
