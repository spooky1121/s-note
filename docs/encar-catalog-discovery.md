# 엔카 차량번호 우선 탐색 — v2.127

검색이 실행되어도 무관한 광고만 나오는 경우를 보완한다. 실제 실패 진단은 검색 2회, 결과 7개, 후보 6개 모두 다른 차량번호였으며, 직접 차량번호 검색 폼은 지원되지 않았다. 이 경우를 검색 키 누락이나 해당 차량의 광고 부재로 해석하지 않는다.

## 자동 조회

1. 기존 저장 후보와 공식 엔카 상세를 먼저 확인한다. 미해결이고 검색 키와 유효한 제조사가 있으면 전체 차량번호의 정확 검색 1회를 카탈로그보다 먼저 실행한다. 명시적인 공식 부정 결과는 계속 우선한다.
2. 제조사(`make`)만으로 조회할 수 있다. 모델 그룹(`group`)·등급(`grade`)은 각각 유효할 때만 탐색 순서에 활용한다. 값이 없거나 잘못되어도 유효한 제조사 조회를 막지 않는다. 자유 입력 차명 전체나 고객 정보는 보내지 않는다. 힌트는 NFKC·공백 정규화와 길이·제어문자 검사를 거친다.
3. 공개 `https://encar.spb.ru/catalog/`에서 실제 제조사 링크, 다음 화면의 실제 모델 링크를 찾는다. 제조사·모델 값으로 주소를 생성하지 않는다. 정적 링크는 필터 폼 안에 있어도 읽을 수 있으나 폼 제출이나 스크립트 실행은 하지 않는다.
4. 같은 매물 카드 안에서 전체 차량번호와 광고 ID를 대조한다. 힌트·연식·VIN 일치는 최종 조건이 아니다. 모호한 카드나 추천 차량의 정보는 제외한다. 모델 아래의 관측된 세대·등급 링크도 탐색하며, 모델/등급 표기는 탐색 순위에만 사용한다. 경로당 실제 다음 링크는 최대 3페이지, 모델/세대/등급 합계는 8페이지, 이 단계 전체 8초 안에서 읽는다. 읽은 디렉터리는 한 요청 안에서 재사용한다.
5. 미해결이면 카탈로그 탐색과 남은 검색으로 이어간다. 두 번째 검색도 전체 번호를 따옴표로 묶고 지원 출처의 도메인 필터를 사용한다. 원문 모델 문구나 site 문법을 추가 조건으로 요구하지 않으며 기존 최대 2회 basic 검색을 유지한다. 검색 원문 중 정확한 번호 가까이 있는 광고 ID를 먼저 선택한다.

탐색은 검색 키가 없어도 동작한다. 실제 페이지의 정적 링크·카드가 없거나 원문을 읽을 수 없으면 성공으로 처리하지 않는다. 전체 35초, 기존 외부 원문 최대 6개·누적 8초와 기존 후보 한도를 유지한다. 다음 페이지를 추측하거나 전체 사이트를 무제한 순회하지 않는다.

공식 상세에서 이미 다른 번호 등으로 판정해 건너뛴 외부 주소는 실제 원문 6회 한도를 소비하지 않는다. 번호 가까이에서 얻은 새 광고 ID도 기존 최대 3개의 알려진 개별 광고 주소 대조 대상에 포함한다. 검색 추출문을 직접 읽은 원문으로 표시하지 않으며, 아래 조건을 충족한 경우 검색 출처 링크로 별도 제공한다. Tavily의 `raw_content`는 원본 HTML이 아닌 정제 Markdown이다.

## 번호를 포함한 검색 결과의 링크

`resultPlateMatchCount: 1`은 검색 결과 문서 하나에 번호가 있다는 뜻이다. 그 문서의 다른 차량 광고 ID를 가져오거나 원문 확인 완료로 표시하지 않는다. v2.127부터는 같은 매물 구간의 정확한 전체 번호·제조사·광고 ID 하나를 함께 확인하면 검색 출처 링크도 제공한다. 모델·등급·연식·VIN 일치를 요구하지 않는다. URL 속 번호만 있는 경우, 다른 번호/ID가 섞인 구간, 제조사가 맞지 않는 자료는 사용하지 않는다.

검색 근거는 `externalVerification.method: search-index`와 날짜 null로 저장하고 **검색 결과 확인**을 표시한다. 말풍선은 검색 확인 시각과 출처, 원문 HTML 및 한국 엔카의 현재 광고 상태 미확인을 알린다. 기존 원문 확인 기록에는 이 선택 필드가 없다. 공식 확인 또는 직접 읽은 원문 증거가 있으면 그 자료를 우선한다. 공식 번호 불일치·종료·삭제·불명확 상태나 읽힌 원문의 명백한 충돌은 검색 자료로 덮어쓰지 않는다.

검색 근거는 엔카의 현재 가격 확인을 대신하지 않는다. 화면·저장 브리지·자동 가격 API의 외부 근거 차단을 그대로 적용해 자동 촬영·OCR·판매가 변경을 실행하지 않는다. 검색 근거와 원문 근거는 같은 저장 ACK 후 목록 아이콘 갱신·복원 경로를 사용한다.

HTML 읽기는 SVG/MathML 등 제외할 namespace를 먼저 제거하고 합법적인 `li`·`option` 등의 종료태그 생략을 처리한다. 정상 제목·본문이 있는 페이지의 푸터 안내를 전체 차단 화면으로 단정하지 않는다. 인식할 수 없는 구조가 실제 차단인지 파서 호환성 문제인지 안전한 진단 개수와 사유로 구분하며 원문이나 예외 메시지는 복사하지 않는다.

## 이미 아는 외부 주소

`광고 주소로 확인`은 기존 공식 엔카 주소 외에 허용된 Trust Encar 계열의 HTTPS `/auto/{광고ID}/` 주소를 받는다. 서버에서 호스트·경로·개수 한도를 다시 검사하고 주차량 번호를 대조한 뒤 한국 엔카 주소를 제공한다. 위장 도메인, 사용자 정보, 포트, 리디렉션, 쿼리·fragment·인코딩 우회는 허용하지 않는다. 외부 사이트로 인증 정보를 보내지 않는다.

기존 `encarLinks`의 출처 메타데이터와 소유자·revision CAS 저장을 사용한다. 공식 페이지가 명시하는 다른 번호·광고 종료·삭제·불명확 상태는 외부 확인으로 덮어쓰지 않는다. 외부 확인만 있으면 자동 촬영·가격 안내·판매예정가 변경을 실행하지 않으며 서버 가격 API를 직접 호출해도 같은 제한을 적용한다.

v2.125부터 광고 링크의 서버 저장 성공 직후 현재 매입 목록을 갱신한다. 상세창을 닫거나 새로고침하지 않아도 목록형·카드형에 Encar 아이콘이 나타난다. 검색·페이지·보기 방식과 상세의 작성 중 입력은 유지한다. 저장 대기·실패 또는 계정/차량 전환 뒤 늦게 도착한 응답으로는 목록을 갱신하지 않는다. [실시간 목록 검증 기록](encar-live-list-verification.json)에 범위를 남긴다.

## 검증과 운영 범위

```sh
npm test --prefix tests/encar
node tests/encar/model-catalog-discovery.browser.cjs
node tests/encar/trim-discovery.browser.cjs
node tests/encar/plate-first.browser.cjs
node tests/encar/external-confirmation.browser.cjs
node tests/encar/detail-action.browser.cjs
node tests/encar/direct-price-change.browser.cjs
```

새 브라우저 검증은 실제 앱·`onRequest`·HTMLRewriter 파서를 합성 원문과 인증/DB에 연결한다. 기존 실패와 동일한 검색 결과 수·다른 번호 후보 수를 재현한 뒤, 제조사→모델 탐색·서버 확인·저장·복원·목록 재열기를 PC와 두 모바일 폭에서 확인한다. 실제 외부 원문 HTML을 fixture로 수집한 시험은 아니다.

연구용 웹 도구로 실제 공개 카탈로그의 제조사→모델→세대→등급 링크와 같은 카드의 번호·광고 ID를 확인했다. v2.124에서 사용자 요청 차량 1건의 확인된 링크 메타데이터를 별도로 연결했으며, v2.126에서는 지정 차량의 차종 선택값만 읽고 운영 자료를 변경하지 않았다. 실제 Cloudflare 원문 수신·운영 자동 탐색 종단 검증은 실행환경의 도메인 제한 때문에 별도 확인 대상이다. 운영 링크 연결과 자동 탐색 시험을 같은 증거로 취급하지 않는다.

진단에는 화면/서버 버전·안전한 단계명·힌트/설정 여부·요청/페이지/일치/건너뜀/검색 근거 개수와 고정 사유만 추가하며 원문·차량번호·고객 정보·자격증명을 넣지 않는다. 새 항목이 없는 과거 진단만으로 화면과 서버 중 어느 버전이 오래되었는지는 단정하지 않는다. 최신 자동 시험 수와 소스 해시는 [v2.127 검증 기록](encar-plate-first-verification.json), 이전 범위는 [v2.126 기록](encar-trim-discovery-verification.json)과 [v2.124 기록](encar-catalog-discovery-verification.json)에 남긴다.
