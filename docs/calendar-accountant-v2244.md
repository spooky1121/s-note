# 달력과 경리 업무 화면 — v2.244

일정은 시작일 `eventDate`와 포함되는 종료일 `endDate`, 반복 `none/daily/weekly/monthly/yearly`를 원본 한 건에 저장한다. 반복을 별도 일정 행으로 무한 생성하지 않고 요청 범위의 발생 구간으로 투영한다. 월말·윤년 반복은 해당 월의 마지막 날로 보정하고 원래 기간 일수를 유지한다. 편집과 삭제는 반복 전체에 적용한다.

기본 달력은 5주이며 해당 월의 모든 날짜를 표시하기 위해 필요한 경우만 6주로 늘린다. 기간 막대는 주 경계를 넘어 연결해 표시한다. 중앙 월 제목, 작은 이동 화살표, 옅은 다른 달 날짜와 방향별 월 전환을 제공한다. 빠른 재클릭과 모션 감소 설정을 처리한다.

새 조회는 `snote_schedule_list_v2`와 `schemaVersion: 2`를 사용한다. 기존 42칸 단일 일정 조회 RPC는 보존한다. 기존 단일 일정은 별도 데이터 재작성 없이 하루·반복 없음으로 해석한다. 구 클라이언트가 새 기간·반복 일정을 단일 일정으로 덮어쓰려 하면 서버가 거부한다. 세션·상사·본인·수정 버전과 재전송 보호는 유지한다.

경리 대시보드의 현재 총매입은 현재 보유 차량의 매입금액과 대수다. 이번 달 매입·판매는 각 날짜 기준 대수이며 최근 3개월 그래프에도 같은 기준을 쓴다. 총 재고사용·금융 한도는 기존 재고금융 합계를 재사용하므로 판매 후 미상환과 중복 장부 처리도 그대로다. 미확인 금액을 0원으로 추정하지 않는다. 경리 화면의 뉴스와 서류 준비 카드는 제거한다.

매입·매도의 고객 탭은 판매완료 차량에 연결된 고객만 읽는다. 새 `snote_accountant_sold_customers` RPC는 검증된 경리 세션과 상사 권한을 확인하고 담당자·차량을 결합한다. 이름·전화번호·연결 키만 반환하고 주민번호·주소·서명은 반환하지 않는다. 중복 차량, 삭제·휴지통, 다른 상사 자료는 제외한다. 기존 본인 고객 API의 권한을 넓히지 않는다.

딜러소득에는 판매완료 차량과 검증된 저장 정산표의 사업소득을 표시한다. 저장 정산은 실제 세무 신고를 뜻하지 않으므로 별도의 신고 자료가 없으면 신고정보 없음을 표시한다. 운영서류함은 요청한 다섯 종류의 아이콘과 등록 상태를 제공한다. 일반 회사 서류의 신규 업로드·보관 서버는 이번 아이콘 추가 범위에 포함하지 않는다.

차량서류 목록은 차량번호·차명·매입일·담당딜러·서류로 구성한다. 서류 세 슬롯은 메타데이터 요청 하나를 공유하고 등록 수와 이름을 표시한다. 서류함의 새 미리보기 경로는 명시적으로 열 때 이미지 바이트를 검증·다운로드한다. 미디어 `owner_id`는 업로더일 수 있어 차량 담당자 UUID와 같다고 가정하지 않는다. 모호한 차량 ID, 불완전한 조회와 늦은 다른 계정 응답은 표시하지 않는다.

전화번호에는 확인된 직원 연락처를 읽기 전용으로 기본 표시하고, 수동 연락처의 그룹·메모·편집을 유지한다. 같은 번호라는 이유로 별도 수동 메모를 삭제하지 않는다. 운영정산은 화면용 CSS만 정리하며 계산·저장·인쇄 양식을 유지한다.

검증은 가상 계정·회사·일정과 합성 파일로 수행하고 실제 운영 고객을 시험 자료로 사용하지 않는다. SQL·단위·브라우저 결과와 실제 마이그레이션·배포 여부는 별도 릴리스 기록에 보관한다.
